### 0-2. 정상으로 확인된 것

- 코드 품질 게이트: lint 오류 0, 테스트 208 통과·2 건너뜀·0 실패, prettier 통과, 스키마와 커밋된 마이그레이션 `0000_smooth_cerebro.sql` 이 바이트 단위로 동일(`drizzle-kit generate` 결과와 diff 없음).
- 운영 사이트는 `icn1` 리전에서 응답하며 모든 공개 페이지가 200 이다. 정적·캐시 페이지 40~180 ms, 동적 구멍이 있는 상세 페이지 0.4~1.4 s. 네이티브 클라이언트가 쓰는 경로(health, version, ranking, best, players, rivals)는 모두 계약 형태로 응답한다.
- 인증 필요한 API 는 무자격 요청에 401 을 준다(`/api/auth/me`, `/api/fe/tokens`, `/api/fe/me/settings`). 입력 검증 실패는 400 + `VALIDATION_ERROR`.
- 다크·라이트 토큰, State Triad(스켈레톤·빈 상태·오류), 폼 검증, 토큰 평문 1회 표시는 코드에 구현돼 있다.

### 3-4. 배포된 빌드가 지금 저장소와 같은 판인가

같다고 볼 근거: ① `web/` 마지막 변경 커밋이 2026-09-09(`7fa8106`)이고 이후 변경이 없다. ② `/guide` 의 `h1`·절 제목(1~9절, "8. 다른 도구용 API 토큰 (Advanced)")이 `guide-sections.ts` 와 일치한다. ③ `/api/health` 본문이 `capabilities.ts` 의 상수와 일치한다. ④ `/favicon.ico` md5 가 저장소 파일과 같다. ⑤ 페이지 구성(14개 라우트)이 같다.
Git 연결이 아닌 배포로 보이는 근거: `/api/version` 의 `commit` 이 `null` 이다. `getVersionInfo()`(`capabilities.ts:31-37`)는 `SERVER_COMMIT` 또는 `VERCEL_GIT_COMMIT_SHA` 를 쓰는데 둘 다 비어 있다. HTML 에 `data-dpl-id` 가 있어 시스템 환경변수 노출은 켜져 있는 것으로 보이므로, `VERCEL_GIT_COMMIT_SHA` 가 없다는 것은 Git 연동 배포가 아니라 CLI 업로드 배포일 가능성이 높다(추정). 운영 홈 셸의 `age: 188675` 초는 마지막 셸 갱신이 약 2026-10-11 22:17 GMT 임을 뜻하므로 코드 변경 없이 최근에 재배포됐다(추정).
확인하지 못함: Vercel 대시보드의 프로젝트 이름·소속·Git 연결 여부·환경변수 값(계정 접근 없음), 운영 `ALLOW_GUEST`·`REQUIRE_BUILD_HASH` 값(쓰기 요청 없이는 알 수 없음).

### 3-5. 모바일 폭(HTML·CSS 로 판단)

- `md` 미만: NavRail 숨김, `MobileNav` 헤더(메뉴 시트 · 로고 · 테마) 표시. `h-dvh` + `main` 내부 스크롤.
- 표는 `overflow-x-auto` 래퍼라 가로 스크롤로 보인다. 열 너비가 px 고정(`width: 160px` 등).
- FilterPanel 은 `hidden … lg:flex` 라 1024px 미만 `/search` 에는 검색어·모드·레벨 필터가 없다.
- 터치 대상 `h-7`(28px)인 토글·페이저 버튼이 많다(권장 44px 미만).
- 화면 렌더(스크린샷)는 확인하지 못함(브라우저 자동화는 요청 수 제한 때문에 쓰지 않았다).

현재는 **하나뿐**이다: admin 세션(쿠키)을 가진 사람이 `POST /api/tables` 에 위 DTO 전체를 JSON 으로 보낸다. 관리자 UI 없음, 클라이언트 업로드 없음, 원격 가져오기(URL → 표 헤더 → 데이터) 없음, 시드 스크립트 없음. 운영은 `[]`. admin 은 `user.role='admin'` 을 DB 에서 직접 바꿔야 만들어진다(가입 경로는 항상 `user`).

### 5-3. 차트 페이지와의 연결

`table_chart.chart_sha256` 이 `chart.sha256` 과 같을 때만 상세 표의 행이 `/charts/${sha256}` 로 링크된다. 표에 있는 곡이 아직 한 번도 제출되지 않았다면 `chart` 행이 없어 md5 가 `''` 로 나오고(`table.service.ts:58`), 차트 페이지는 "등록되지 않은 차트입니다" 가 된다. 표에서 내 램프·EX 를 보여주는 조인(`chart_best`)은 없다.

### 5-4. 발광 난이도 페이지에 재사용할 것

- 라우트 구조 `/tables`·`/tables/[tableId]`(발광 = `tableId` 한 개 또는 `/insane` 같은 전용 경로), `QUERY_KEY.TABLE`, `tableListQueryOptions`/`tableDetailQueryOptions`, 캐시 태그와 `revalidateOnTableUpsert`.
- 화면 부품: `PanelCard`, `DataTable`, `Pager`, `ColumnToggle`, `SortSelect`, `LampBadge`, State Triad, `PageHeading`.
- `POST /api/tables` 의 admin 가드 + 트랜잭션 교체 방식은 스냅샷 시딩 때 그대로 쓸 수 있다(단 항목 모델 확장 후).
- 클라이언트 쪽: `crates/rbms-table`(dto/fetch/html/saved)과 `apps/rbms-player/src/tablesrc.rs` 는 표준 BMS 표 형식을 읽는다. 웹이 `/…/header.json`·`data.json`·bmstable 메타가 있는 HTML 을 내면 기본 등록 URL 로 그대로 쓸 수 있다.

### 5-5. 새로 필요한 것

1. **항목 모델**: 표준 표 항목은 md5(+ 보통 title·artist·level·url·url_diff·comment)다. 현재 모델은 sha256 필수·메타 없음이라 그대로는 저장되지 않는다. 신규 테이블(예: `table_entry(table_id, folder_id, md5, sha256 NULL, title, artist, url, url_diff, comment, position)`)과 마이그레이션이 필요하다.
2. **폴더 순서·표시 이름**: 표준 `level_order`, `symbol`(발광은 별 기호 + 숫자 형태의 폴더 이름) 반영. 실제 값은 표 스냅샷 작업자의 문서를 따른다.
3. **목록 요약 API / 상세 지연 로딩**: 수천 곡을 한 응답으로 내리지 않기(§4-5).
4. **내 기록 오버레이**: 로그인 사용자의 `chart_best` 를 md5 → `chart.md5` → `chart_best.chart_sha256` 로 이어 램프를 붙이는 쿼리(제출 안 된 곡은 `chart` 행이 없음).
5. **차트 메타 시딩**: 표 항목의 title/artist 를 `chart` 행(md5 기준)에 채우는 경로(§0 #3 해결과 연결).
6. **표준 형식 제공 라우트**: HTML(`<meta name="bmstable" content="header.json">`) · `header.json` · `data.json`, 출처 표기, CORS 헤더.
7. **관리 경로**: 스냅샷 JSON → DB 임포트(스크립트 또는 admin UI), 재실행 안전(멱등).
8. **사용자 폴더(요청 2번)**: 사용자별 폴더 + 항목, 웹 편집 API(세션·본인 가드), 클라이언트용 읽기 API(Bearer) — 기존 `table_*` 모델을 재사용할지(`owner_user_id` 열 추가) 별 테이블로 갈지 결정 필요.

Ignored Build Step 의 정확한 동작(문서 인용 요지): 명령은 Root Directory 에서 실행되고, 종료 코드 `0` 이면 빌드를 즉시 중단(deployment 상태 `CANCELED`), `1` 이면 정상 빌드. `vercel.json` 의 `ignoreCommand` 가 프로젝트 설정을 덮어쓴다(문서 예: `"ignoreCommand": "git diff --quiet HEAD^ HEAD ./"`). 취소된 빌드도 배포 한도와 동시 빌드 슬롯에 계산된다. Vercel 은 `git clone --depth=10` 으로 받는다. `VERCEL_GIT_PREVIOUS_SHA` 는 "해당 브랜치의 마지막 성공 배포 SHA, 브랜치 첫 배포에서는 빈 값", **Ignored Build Step 이 지정된 경우에만 노출**된다.

권장 값(`web/vercel.json`에 추가):

```json
{
    "$schema": "https://openapi.vercel.sh/vercel.json",
    "framework": "nextjs",
    "regions": ["icn1"],
    "ignoreCommand": "git diff --quiet \"$VERCEL_GIT_PREVIOUS_SHA\" HEAD -- . || exit 1"
}
```

`git diff --quiet A B -- .` 는 변경 없음 0, 있음 1, 알 수 없는 SHA 128 을 낸다. 로컬에서 확인했다: `web/` 이 바뀌지 않은 구간 0, `7fa8106~1..7fa8106` 1, 빈 SHA 와 없는 SHA 128. `|| exit 1` 로 0 이외(변경 있음·SHA 없음·얕은 클론에서 SHA 가 범위 밖)는 모두 빌드로 정규화한다. 푸시에 커밋이 여러 개여도 마지막 성공 배포와 비교하므로 `HEAD^ HEAD` 단순 비교보다 안전하다. 이 명령의 Vercel 위에서의 동작(환경변수 노출 시점 포함)은 실제 푸시로만 확인할 수 있어 **확인하지 못함**.
`web/` 이 바뀌지 않은 커밋(Rust·docs 변경)은 `CANCELED` 배포로 기록된다(내장 스킵과 달리 슬롯을 쓴다).

Preview: 기본값은 모든 브랜치 푸시가 Preview 배포가 된다. `feat/skin-followups` 처럼 `web/` 을 건드리는 다른 브랜치가 Preview 로 빌드돼 운영 DB 를 읽지 않게 하려면 Preview 환경에 별도 DB 를 주거나 `ignoreCommand` 에서 `[ "$VERCEL_ENV" != "production" ] && exit 0` 로 Preview 를 막는다(결정 필요).

### 6-4. 마이그레이션 절차와 `drizzle/meta` 문제

현재 `web/drizzle/` 에는 `0000_smooth_cerebro.sql`(21 테이블) 하나뿐이다. 점검 결과:

- 스키마와의 차이 없음: 임시 폴더(작업용 폴더 `…/scratchpad/wave17a/drizzle-check/out2`)에 `drizzle-kit generate` 한 결과(`0000_audit.sql`)가 커밋된 `0000_smooth_cerebro.sql` 과 diff 0. 저장소 `drizzle/` 에는 아무것도 만들지 않았다. 21 테이블: `api_token chart chart_best client_build course course_best course_chart course_score difficulty_table replay rival score setting_blob submission_audit table_chart table_course table_folder account session user verification`.
- drizzle-kit 은 `schema.ts` 안의 `@server/db/auth-schema` alias 를 현재 작업 폴더의 `tsconfig.json` `paths` 로 해석한다. `web/` 에서 실행해야 하고, 다른 폴더에서 실행하려면 같은 `paths` 를 가진 tsconfig 가 필요하다(이번에 임시 폴더에 두었다).
- **문제**: `.gitignore:49` 가 `/drizzle/meta` 를 제외하고, 로컬 `web/drizzle/` 에도 `meta/` 가 없다. drizzle 의 마이그레이터는 `meta/_journal.json` 을 읽어 적용할 파일 목록을 정하므로 이 상태로는 `bun run db:migrate` 가 동작하지 않고, `bun run db:generate` 는 스냅샷이 없어 21 테이블 전체를 새 마이그레이션으로 만든다. 2026-09-09 에 사용자 DB 에 `migrate` 가 적용됐다는 기록(`docs/history/2026-09-09-web-nextjs-ir-server.md`)이 있으나 그 meta 는 남아 있지 않다.

복구 절차(17B 첫 작업, 순서대로):

1. `web/.gitignore` 의 `/drizzle/meta` 줄 삭제.
2. 임시 폴더에서 `drizzle-kit generate --name smooth_cerebro` 로 현재 스키마의 스냅샷을 만들어(SQL 은 이미 동일함이 확인됨) `meta/_journal.json`·`meta/0000_snapshot.json` 을 `web/drizzle/meta/` 로 복사.
3. 저널의 `0000_smooth_cerebro` 항목 `when` 값을 **운영 DB 에 기록된 값보다 작게** 맞춘다. 마이그레이터는 `__drizzle_migrations` 의 가장 큰 `created_at` 보다 `when` 이 큰 항목만 실행하므로, 새로 만든 `when`(오늘)이면 운영에서 0000 이 다시 실행돼 "테이블이 이미 있음" 으로 실패한다. 운영 `select max(created_at) from __drizzle_migrations` 는 사용자 DB 접근이 필요하다(확인하지 못함).
4. `bun run db:generate` 로 새 테이블 마이그레이션 생성 → 커밋.
5. 사용자 PC 에서 `DATABASE_URL` 을 환경에 주고 `bun run db:migrate`(빌드에 포함하지 않음 — architecture §6-2 의 원칙). `drizzle-kit push` 는 쓰지 않는다.
6. 배포.
