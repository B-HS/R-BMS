## 0. 먼저 읽을 결론

1. 지금 앱에는 "언어"라는 개념이 어디에도 없다. 내장 화면, 설정, 알림, 기본 스킨 Lua 의 고정 문자열은 전부 영어(대문자 위주)이고, 한국어는 서버가 주는 오류 문구로만 화면에 섞여 들어온다(5.4절).
2. 글꼴이 먼저 풀려야 한다. 번들 Inter 에는 한글, 가나, 한자 글리프가 하나도 없다(2.5절 실측). 한국어·일본어 글자는 지금도 OS 의 시스템 글꼴로 대신 그려지고, 이 경로의 실제 화면 모양은 문서에도 "캡처로 확인하지 못했다"고 적혀 있다(`docs/skin.md:716`). 이 조사도 실행하지 못해 확인 못 했다.
3. 추천 구조: `Language` 열거형은 `rbms-model`, 설정은 `display.language`(AUTO 기본, 새 의존성 없이 OS 언어 감지), 문자열은 크레이트별 정적 카탈로그(전 언어 필수 항목이라 누락이 컴파일 오류), 번역은 "표시 가장자리"에서만(설정 표가 표시 문자열을 상태 비교에 쓰고 있어 제자리 치환이 위험하다, 2.2절), 스킨에는 확장 불린 id 로 현재 언어를 알려 준다.
4. 가장 큰 불확실성은 범위다. 웹은 한국어 전용이고 약 1,300줄·168 파일이라(5.3절), 클라이언트만인지 웹까지인지 사용자가 정해야 한다.
5. 같은 날 요구 4~7(선곡 UI, 랭킹 모드, 리플레이 배치)이 새 문자열을 많이 더한다. 기반(구현 단위 I0)을 먼저 넣고 그 기능들이 처음부터 카탈로그를 쓰게 해야 나중에 한 번 더 훑는 일이 없다(7절).

### 2.2 설정 화면은 표시 문자열을 상태 비교에도 쓴다 (번역의 가장 큰 함정)

설정 표의 값은 `display_value()` 가 돌려주는 영어 `String` 이고, 화면은 그 문자열이 무엇인지 문자열 비교로 되짚는다.

| 위치 | 비교 |
| --- | --- |
| `apps/rbms-player/src/settings_ui.rs:197` | `SettingKind::Toggle => RowControl::Switch { on: value == ON_VALUE }` |
| `apps/rbms-player/src/settings_ui.rs:199` | 선택지의 선택된 칸을 `values.iter().position(\|entry\| *entry == value)` 로 찾음 |
| `apps/rbms-player/src/settings_ui.rs:202` | `filled: value != NONE_VALUE && value != UNSET_VALUE` |
| `apps/rbms-player/src/stage/settings/info.rs:139`, `:156` | 선택지 설명을 `position(\|value\| *value == line.value)` 로, 액션 행을 `line.value != ACTION_VALUE` 로 가른다 |
| `crates/rbms-config/src/settings.rs:1058-1060`, `:998-1001` | 선택지 인덱스를 `cycle_values` 와 값 비교로 얻음 |

`ON_VALUE`, `ACTION_VALUE`, `NONE_VALUE` 같은 상수는 `rbms-config` 가 공개하고(`crates/rbms-config/src/settings.rs:47-68`), `rbms-cli config` 도 같은 영어 라벨을 찍는다. 그래서 `rbms-config` 의 영어를 한국어로 바꾸면 스위치 모양, 선택된 칸, 액션 행이 한꺼번에 어긋난다. 번역은 `rbms-config` 가 아니라 플레이어가 줄(line)을 화면용으로 만드는 자리에서, `SettingId` 와 선택지 인덱스를 키로 해야 한다(4.1절 3번).

### 2.3 문장을 조각으로 이어 붙이는 곳

한국어·일본어에는 영어의 단수/복수나 어순이 없어서 조각 번역이 안 된다. 문장 하나를 템플릿으로 다시 써야 하는 곳의 예:

- `apps/rbms-player/src/stage/settings.rs:896`, `:899`: `"ROW GOES"`/`"ROWS GO"` 를 골라 `"{changed} CHANGED {go} BACK TO DEFAULT.{kept}"` 에 끼움.
- `apps/rbms-player/src/stage/settings/info.rs:112` `hint()`: `format!("{key} {action}")` 를 3칸 공백으로 이은 힌트 줄. 키 이름(`ESC`, `F2`)은 번역 대상이 아니고 동작 단어만 번역 대상이다.
- `apps/rbms-player/src/stage/skin_menu.rs:802-803`: `"ALSO ON 1 OTHER SCREEN ..."` 와 `"ALSO ON {peers} OTHER SCREENS ..."` 처럼 단수/복수를 문장 둘로 나눠 둠. 한국어·일본어는 한 문장으로 합쳐야 한다.
- `apps/rbms-player/src/stage/select/scene.rs:259`: `"{}   {}   GAUGE {}{}"`.

`const X: &str` 이 player, render, config 에 489개(공백이 든 문장형 212개), `format!(` 가 player+render 에 653곳 있다(테스트 제외, 단순 `grep` 계수).

### 2.6 언어 감지에 이미 있는 재료

- cosmic-text 의 `FontSystem::new()` 가 OS 언어를 `sys_locale::get_locale()` 로 읽는다(`cosmic-text-0.19.0/src/font/system.rs:422`). `sys-locale 0.3.2` 는 이미 `Cargo.lock:3961` 에 있다(직접 의존성이 아니라 전이 의존성).
- `TextContext::new()` 가 그 로캘 문자열을 받고(`font.rs:333`) 곧 `han_locale()` 로 바꿔 엔진에 넘긴다(`:335`). 원래 값은 어디에도 남지 않는다.
- sys-locale 의 공급자: macOS 는 선호 언어 목록(`src/apple.rs`, CoreFoundation), Windows 는 `GetUserPreferredUILanguages`(`src/windows.rs`, UI 언어), Unix 는 `LANGUAGE`, `LC_ALL`, `LC_MESSAGES`, `LANG`(`src/unix.rs`). `get_locale()` 은 그 목록의 첫 항목만 돌려준다(`src/lib.rs`).
- 이 Mac 의 선호 언어는 `defaults read -g AppleLanguages` 로 `en-KR, ko-KR, ja-KR` 순이다. 첫 항목이 영어라서 AUTO 는 이 Mac 에서 영어가 된다(Q2 의 이유).

## 4. 설계안

### 4.1 추천안 A: 열거형 + 정적 카탈로그 + 표시 가장자리 번역

1. **언어 타입.** `rbms-model` 에 `Language { English, Korean, Japanese }`, `ALL`, `id()`(0,1,2), `Default = English`, `from_locale(&str)`(`ko*` 한국어, `ja*` 일본어, 그 밖 영어). `rbms-render`, `rbms-config`, 플레이어가 모두 `rbms-model` 에 의존하므로 새 크레이트가 필요 없다(`docs/architecture.md` 의 의존 표).
2. **설정.** `display.language`: `Auto | English | Korean | Japanese`. 직렬화는 `window_mode_token` 선례를 따른 문자열 토큰(`"AUTO"`, `"ENGLISH"`, `"KOREAN"`, `"JAPANESE"`), `#[serde(default)]`(기본 `AUTO`), 스키마 버전은 그대로 6. 설정 행 `SettingId::Language`(DISPLAY 탭 맨 위 새 구역 LANGUAGE, 선택지 AUTO/ENGLISH/한국어/日本語, `SETTING_COUNT` 97 -> 98). 자기 언어로 쓴 선택지 이름은 번역하지 않는다. 바꾸면 같은 프레임에 적용한다(재시작 없음).
3. **설정 표는 영어 정본으로 두고 번역은 플레이어의 줄 만들기에서.** `SettingId` 에 대한 exhaustive `match` 로 라벨, 도움말, 설명문, 구역 제목을 돌려주고(행을 더하고 번역을 빠뜨리면 컴파일 오류), 선택지 값은 `cycle_values(id)` 의 인덱스로 번역한다. 줄 구조체에 화면용 문자열 `shown` 을 따로 두고 로직 비교(`value == ON_VALUE`, `position(...)`, `value != NONE_VALUE`)는 영어 정본 `value` 로 유지한다(2.2절). `rbms-config` 와 `rbms-cli config` 출력은 바뀌지 않는다.
4. **카탈로그 형식.** `rbms-model` 에 `macro_rules!` 하나(`translations!`)를 두고 크레이트마다 자기 모듈에 목록을 쓴다.

   ```rust
   translations! {
       pub(crate) enum SelectText {
           MusicSelect => ("MUSIC SELECT", "선곡", "選曲"),
           ChartCount => ("{0} CHARTS", "차트 {0}개", "{0}譜面"),
       }
   }
   ```

   항목마다 세 문자열이 모두 있어야 매크로가 맞아서 하나라도 빠지면 컴파일 오류다. 4번째 언어를 더하면 모든 항목이 오류가 나서 빠짐없이 채우게 된다. `{0}`, `{1}` 자리 채움은 `Text::fill(lang, &[...])` 로 하고, 자리표 집합이 세 언어에서 같은지는 단위 테스트로 검사한다(컴파일 검사는 아니다). 매크로가 `ALL` 상수도 만든다. 새 의존성이 없고 `#[allow]`, `unsafe` 도 필요 없다. 쓰이지 않는 항목은 `dead_code` 경고가 되므로(`clippy -D warnings`) 죽은 문자열이 남지 않는 이점이 있다.
5. **렌더 크레이트.** `RenderCtx` 에 `language` 를 더하고(`ctx.rs:13-21`), 옛 진입점은 `set_theme` 처럼 스레드 로컬을 쓴다(`theme.rs:363-369`). 전역 `AtomicU8` 은 병렬 테스트가 서로 간섭할 수 있어 쓰지 않는다. 테스트의 기본 언어는 영어여야 기존 골든 서명 10개가 그대로다.
6. **문장 조립을 문장 단위로.** 2.3절의 조각 조립은 문장 전체를 템플릿으로 다시 쓴다. 영어의 단수/복수는 영어 쪽 항목 둘로 나눈다.
7. **알림.** `notify(Level, String)` 은 진단성 알림용으로 그대로 두고, 행동하는 알림 약 60개를 위해 `notify_text(Level, Text, args)` 를 더한다. 큐에는 `Text` 와 인자를 넣고 프레임 스레드에서 현재 언어로 만든다(작업자 스레드에서 만든 알림도 같은 규칙). stderr 에는 영어를 즉시 찍는다. 서버가 주는 한국어 오류 문구는 그대로 보이게 두거나, 오류 코드 25종(`web/src/server/lib/error-message.ts:3-25`)을 클라이언트가 번역하는 방법이 있다(Q8).
8. **언어 감지(AUTO).** `TextContext::new()` 가 받는 원래 로캘 문자열을 필드에 남기고(`font.rs:333`) 접근자 `system_locale()` 을 더한다. 새 의존성이 없다(`sys-locale` 은 이미 전이 의존성이다). 시작할 때 `Language::from_locale` 로 해석한다. 첫 선호 언어만 읽으므로 2.6절의 Mac 은 영어가 된다. `RBMS_LANGUAGE`(`ko`/`ja`/`en`) 환경 변수로 설정을 건드리지 않고 덮어쓰게 하면 캡처 하니스와 점검에 쓸 수 있다(선택).
9. **스킨.** 확장 불린 21150~21152(`21150 + Language::id()`, 해석된 언어가 k 이면 `21150 + k` 가 켜짐)와 21153~21159 예약을 `Cluster::System` 으로 라우팅한다(`skin_host/mod.rs:449-456`, 시계·플레이어 합계·기계 값을 답하는 클러스터 `skin_host/system.rs`. 선곡·플레이·결과 모든 화면에서 답하는지는 구현 때 확인한다). 기본 스킨은 `lua/i18n.lua` 에 `t(key)` 를 두고 `main_state.option(21150..)` 로 현재 언어를 읽는 함수 필드로 글자를 만든다. 언어가 바뀌면 함수 필드라 문서를 다시 읽지 않고도 다음 프레임에 바뀐다. 정적 `constantText` 로 남는 글자는 문서를 다시 읽을 때 반영된다. 로더는 `op = {id}` 에서 확장 id 를 버리므로 `op` 에는 못 쓰고 함수 필드로만 읽는다(`docs/skin.md` 1.4절, ADR 4절).
10. **스킨 메뉴 옵션 이름(헤더 데이터 약 160개).** 헤더 읽기 단계에서는 `main_state` 가 비어 있어(`docs/skin.md:574`) 이번 단계에서는 영어로 둔다. 번역하려면 로더가 언어를 Lua 에 주는 변경이 따로 필요하다(후속 S1).
11. **글꼴.** 1단계는 시스템 글꼴 폴백 그대로(번들 없음). 실창 점검에서 빠지는 글리프나 줄 높이 문제가 나오면 카탈로그 글자만 담은 OFL 서브셋 글꼴을 번들하는 것이 대안이다(Q7). 한글·일본어 소형 글자 가독성을 위해 `px_for` 에 CJK 하한을 둘지는 실측 뒤에 정한다(6절).
12. **유지하는 영어 용어(번역하지 않음).** PGREAT, GREAT, GOOD, BAD, POOR, MISS, FAST, SLOW, EX SCORE, BP, BPM, HI-SPEED, SUDDEN+, LIFT, HIDDEN+, RANDOM, MIRROR, R-RANDOM, S-RANDOM, 게이지 이름(ASSIST EASY, EASY, NORMAL, HARD, EX-HARD, HAZARD), 클리어 램프 이름(`format.rs:122-132`), DJ 등급(AAA, MAX), 판정 알고리즘 이름, LN/CN/HCN, 모드 이름(5KEYS 등), SCRATCH AUTO, KEEP GREEN NUMBER 와 키 이름. 근거: IIDX 공식 도움말이 옵션 이름을 영어로 유지하고(3.2절), 램프 와이어 이름·id 는 바꾸면 안 되는 제약이 있으며, R-BMS 웹도 램프를 영어로 쓴다. 표시용 라벨(`format.rs`)과 와이어(`rbms-ir`)는 이미 분리돼 있다.

### 4.5 테스트 방법

1. 컴파일 시점: 항목마다 세 문자열 필수(매크로), `SettingId` exhaustive `match`. 4번째 언어 추가 시 전부 오류.
2. 단위(결정적, I/O 없음): 자리표 `{n}` 집합이 세 언어에서 같은지, 빈 문자열 없음, 한국어·일본어에 영어 문장이 그대로 복사되지 않았는지(비ASCII 포함 또는 허용 목록), 앞뒤 공백 같음, 용어집의 금지어, `Language::from_locale` 표(`ko-KR`, `ko`, `ja-JP`, `ja`, `en-US`, `en-KR`, `zh-TW`, `fr`, 빈 문자열).
3. 설정: 옛 `settings.ron`(필드 없음)이 AUTO 로 읽히고 라운드트립 되는지, 계약 골든 재생성 후 웹 `client-requests` 테스트 통과.
4. 렌더: 기본 언어 영어에서 기존 골든 서명이 그대로여야 한다. 한국어·일본어 픽셀 골든은 만들 수 없다. 테스트 하니스는 글꼴 DB 에 Inter 하나뿐이어서 CJK 가 빈 네모로 나오고 호스트마다 다르기 때문이다(`font.rs:858-870`). 대신 실제 창에서 `RBMS_SKIN_CAPTURE_DIR` 하니스(`docs/HANDOFF.md` 7절)로 화면 x 언어를 찍어 사람이 보는 점검표를 `docs/quality-assurance` 에 둔다.
5. 스킨: `skin-dump --strict --frames 120` 을 언어별 시나리오로 돌린다(`apps/rbms-cli/src/skin_dump/scenario.rs` 의 `booleans` 표에 21150~21152 지정). 기본 팩 게이트 테스트(`crates/rbms-skin/tests/default_pack.rs`)는 영어 기준 유지.
6. 알림: 큐에 담긴 `Text` 가 프레임 스레드에서 현재 언어로 풀리는지, stderr 는 영어인지.
7. 실기: macOS 와 Windows 에서 세 언어로 설정, 선곡, 플레이 메뉴, 결과, 기본 스킨 선곡·결과를 보고 잘림, 줄 높이, 읽힘을 확인한다(Windows 폰트는 이 조사에서 확인 못 함).

## 5. 사용자 결정이 필요한 질문

### 5.1 질문 목록

1. **Q1. 범위** - **클라이언트 먼저, 웹은 별도 작업(추천)** / 둘 다 한 번에 / 웹만. 추천 이유: 웹은 한국어 전용 약 1,300줄·168 파일에 AI 프롬프트와 서버 오류 문구까지 얽혀 독립된 큰 작업이다(5.3절).
2. **Q2. 기본 언어** - **AUTO(OS 언어 감지, 지원하지 않는 언어는 영어)(추천)** / 영어 고정 / 한국어 고정. 추천 이유: 새 사용자가 처음부터 자기 언어를 본다. 다만 이 Mac 은 첫 선호 언어가 영어(`en-KR`)라 AUTO 가 영어가 되니, 소유자는 설정에서 직접 고른다.
3. **Q3. 알림 번역 범위** - **행동하는 알림 약 60개만 번역하고 OS 오류 원문이 든 진단성 약 90개는 영어 유지(추천)** / 전부 번역 / 전부 영어. 추천 이유: 진단 문구는 오류 원문과 섞여 번역해도 반쪽이고, 로그(stderr)와 문구가 갈리지 않는다.
4. **Q4. 게임 용어** - **원어 유지(PGREAT, 게이지·램프 이름, 옵션 이름, EX SCORE 등) + 설명문만 번역(추천)** / 램프·게이지 이름까지 번역(`iidx-rank` 방식). 추천 이유: IIDX 공식 일본어 도움말이 옵션 이름을 영어로 둔다(3.2절). R-BMS 웹도 램프를 영어로 쓴다.
5. **Q5. 한국어 chart 용어** - **차트(R-BMS 웹과 일치)(추천)** / 채보 / 보면(`iidx-rank`). 추천 이유: 같은 서비스 안에서 용어를 통일한다. 일본어 プレー/プレイ 는 IIDX 식 プレー 로 초안을 쓴다(4.6절).
6. **Q6. 일본어 감수** - **모델 초안 + 용어집 + 되번역으로 내고, 원어민 감수는 릴리스 노트로 요청(초안 승인 뒤에만 게시)(추천)** / 감수 없이 출시 / 감수 뒤에 출시. 추천 이유: 일본어 원어민 검증 수단이 이 저장소에 없다.
7. **Q7. 글꼴** - **시스템 글꼴 폴백 유지, 실창 점검 뒤 필요하면 서브셋 번들(추천)** / 처음부터 CJK 서브셋(OFL) 번들. 추천 이유: macOS·Windows 는 기본으로 CJK 글꼴이 있고(Windows 는 확인 못 함) 번들은 파일과 갱신 도구가 늘어난다. 번들하면 테스트 골든을 결정적으로 만들 수 있다는 이점이 있다.
8. **Q8. 서버 오류 문구** - **지금처럼 서버 한국어를 그대로 보임(1단계)(추천)** / 클라이언트가 오류 코드 25종을 번역. 추천 이유: 1단계 범위를 줄이고 웹 단계에서 서버가 `Accept-Language` 를 받게 하는 편이 맞다.
9. **Q9. Discord 문구** - **영어 유지(추천)** / UI 언어를 따름. 추천 이유: 타인에게 보이는 문구라 상대 언어를 알 수 없다.
10. **Q10. 크레이트와 구조** - **새 크레이트 없이 `Language` 와 매크로는 `rbms-model`, 카탈로그는 각 크레이트(추천)** / 새 워크스페이스 크레이트 `rbms-i18n`. 추천 이유: 한 타입을 위해 크레이트를 늘리지 않는다. 외부 의존성은 어느 쪽도 없다.
11. **Q11. 스킨 메뉴 옵션 이름(헤더 약 160개)과 스킨 노출** - **이번엔 영어 유지하고 확장 불린 21150~21152 로 스킨 본문 글자만 번역(추천)** / 로더가 언어를 전달해 헤더도 번역 / 스킨에 언어를 알리지 않음. 추천 이유: 헤더 읽기 단계는 `main_state` 가 비어 있어 로더 변경이 따로 필요하다.
12. **Q12. 진행 순서** - **기반(I0)과 스킨 헬퍼를 먼저 넣고, 요구 4~7 이 새 문자열을 카탈로그로 쓴다(추천)** / 요구 4~7 을 먼저 끝내고 마지막에 한꺼번에 훑음. 추천 이유: 같은 날의 선곡 UI·랭킹 작업이 `stage/select/**`, `ir_ranking_view.rs`, `lua/select/**` 를 대폭 고쳐서, 나중에 훑으면 충돌과 재작업이 크다.

## 부록. 이 조사에서 직접 확인한 방법

- 문자열 계수: 테스트 외 `.rs` 의 큰따옴표 리터럴 정규식(2.4절 머리말의 방법), Lua 는 `lua/**/*.lua` 와 `*.luaskin` 의 `--` 주석, `require` 줄, 식별자형 문자열을 뺀 리터럴.
- 글리프: 두 Inter 파일의 `cmap` 표(형식 4, 12)를 직접 읽어 유니코드 범위별 개수를 셌다.
- OS 정보: `defaults read -g AppleLanguages`, `ls /System/Library/Fonts`.
- 외부 사실의 출처: IIDX 공식 도움말 2건, RemyWiki 용어집, 나무위키 IIDX 문서, next-intl 문서(모두 요약 도구로 읽음). 확인 못 한 것은 6절 14번.
