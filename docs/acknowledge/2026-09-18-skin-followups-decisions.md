# 스킨 후속 기능 결정 (2026-09-18)

사양: `docs/plan/2026-09-18-skin-followups.md`. 조사 근거: 세션 스크래치의 R-A(이벤트·화면·캐릭터 의미), R-B(CSV 로더 명령 표), R-C(비디오 디코더 선택지), R-D(코드 사실) 보고서(저장소 밖, 핵심 사실은 사양에 옮김). 사용자 지시는 "요약한 남은 기능들을 다 구현해서 커밋·푸시·머지"이며 아래는 그 범위 안의 메인 오케스트레이터 판단이다. 항목은 배경 / 결정 / 이유 / 기각 순서.

## E1. 새 의존성은 순수 Rust 만, 시스템 라이브러리 경로는 구현하지 않는다

- 배경: 레퍼런스 구현은 번들된 ffmpeg 로 비디오 BGA 를 재생한다. 이 저장소의 CI 는 3-OS 이며 시스템 패키지를 설치하지 않는다.
- 결정: `.mpg`(MPEG-1 PS)는 `mpeg-ps` + `mpeg-pes` + `oxideav-mpeg12video` + 자체 YUV→RGB, `.mp4`(H.264)는 `re_mp4` + `rusty_h264-decoder` 조합을 각각 cargo feature 로 두고, stable 툴체인 컴파일과 로컬 ffmpeg 로 만든 픽스처 대조를 통과한 백엔드만 기본 활성으로 남긴다. `.wmv`(VC-1) 는 순수 Rust 디코더가 없어 미지원(경고 후 정지 이미지 폴백).
- 이유: CI 를 시스템 의존성 없이 유지한다. 컴파일·대조 검증 없이 0.0.x 크레이트를 신뢰하지 않는다.
- 기각: `ffmpeg-next` — 시스템 ffmpeg 필요. `openh264` — C++ 빌드 단계가 CI 에 들어온다(대안으로 기록). 자체 MPEG-1 디코더 작성 — VLC 표 전사 오류 위험이 크고 시간이 길다.

## E2. CSV 스킨은 별도 로더가 `SkinDef` 로 변환한다

- 배경: 레퍼런스 CSV 로더는 JSON 을 거치지 않고 런타임 객체를 직접 만든다. 이 빌드의 렌더러는 `SkinDef`→`LoadedSkin` 한 경로만 있다.
- 결정: `crates/rbms-skin/src/csv/` 가 `.lr2skin` 헤더와 CSV 본문을 MS932 로 읽어 `SkinDef`(객체·목적지·헤더 옵션/파일/오프셋) 로 변환하고, 그 뒤는 기존 로더·렌더러가 처리한다. 좌표는 헤더 `#RESOLUTION`(기본 640×480) → 1280×720 y-up 변환.
- 이유: 렌더러 분기가 없고 JSON 문서와 같은 검증·커스터마이즈 경로를 탄다.
- 기각: CSV 전용 렌더 경로 — 객체 21종을 두 번 구현.

## E3. 문서 이벤트는 `SkinScreen` 이 소유하고 레퍼런스 의미를 따른다

- 배경: 모델은 `customEvents`·`customTimers`·`act`·`click` 을 이미 파싱하지만 평가·디스패치가 없다. 레퍼런스는 클릭 사각형 = 현재 프레임의 애니메이션 목적지, 위에서부터 첫 히트, `click` 0~3 은 증분 방향, 숫자 `act` 는 내장 이벤트 id(없으면 커스텀 id), 문자열 `act` 는 Lua, `minInterval` 은 ms 스로틀이다.
- 결정: 위 의미를 그대로 구현하고 내장 이벤트 중 이 빌드에 동작이 있는 것만 `Hot`/설정 조정으로 연결한다. 없는 id 는 경고 1회.
- 이유: 레퍼런스 문서 호환. 기존 `hotspot` 확장은 단순 경로로 유지.
- 기각: `act` 문자열을 내장 이벤트 이름으로 해석 — 레퍼런스 JSON 경로는 문자열을 Lua 로만 읽는다.

## E4. BGM 루프는 오디오 엔진의 루프 보이스

- 배경: 믹서 보이스에 루프 플래그가 없고 `sample_duration_us` 는 호출처가 없는 잔재다. 앱 프레임에서 재스케줄하면 프레임 지연이 이음새 끊김이 된다.
- 결정: `Command::Play{ looping }` 로 보이스가 샘플 끝에서 커서를 되감아 이음새 없이 반복하고 `release()`(stop/clear_namespace) 가 끝낸다. 곡 선택 진입 시 `select` 스템 루프, 이탈 시 정지. 결정 스템은 1회.
- 이유: 샘플 정확 이음새, 기존 정지 경로 재사용.
- 기각: 앱 재스케줄 — 끊김. 별도 BGM 스트리머 — 22 스템 중 2개를 위해 과함.

## E5. 24키 문서 타입은 16(레퍼런스 PLAY_24KEYS), 활성화는 `Mode::ALL` 편입

- 배경: 이 빌드의 표는 이미 16 을 `KEYBOARD_24K` 에 매핑하지만 `Mode::ALL` 에 없어 `is_supported_skin_type` 이 거부하고, 기본 키 바인딩이 8레인, 문서가 자리표시자였다.
- 결정: `Mode::ALL` 에 편입, 26레인 기본 키·건반형 레인 폭·실제 `play-24k.json5`·헤드리스 캡처. 17(24KEYS DOUBLE) 은 이 빌드에 모드가 없어 제외.
- 이유: 판정·게이지 표는 이미 24K 를 알고 있어 편입만으로 나머지 경로가 열린다.
- 기각: 별도 24K 전용 화면 코드 — 레인 수는 데이터다.

## E6. `practice` 객체는 연습 화면이 플레이 문서를 그리는 방식으로

- 배경: 레퍼런스는 PRACTICE 스킨 타입이 없고 플레이 스킨 안에서 `practice` 객체(`visibleItems`)가 행 수만 정하며 행은 일반 객체가 그린다(0 이면 레거시 목록을 객체 사각형 안에 직접). 이 빌드는 연습 설정이 별도 Stage 다.
- 결정: 연습 Stage 가 차트 모드의 플레이 문서를 그리고, 행은 사설 id(라벨 20401~, 값 20421~, 포커스 20441~, 연습 화면 열림 20451) 로 답한다. 문서에 `practice` 가 없으면 네이티브 유지.
- 이유: 레퍼런스 의미를 유지하면서 기존 Stage 구조를 바꾸지 않는다.
- 기각: 연습 전용 문서 타입 신설 — 레퍼런스 타입 표에 없다.

## E7. `skinpreview` 는 선택 문서의 오프스크린 렌더, SKIN 탭에도 축소판

- 배경: 레퍼런스는 SKIN SELECT 화면에서 강조된 스킨을 FBO 에 라이브 렌더한다. 이 빌드는 SKIN 탭이 네이티브이고 헤더 `preview` 필드는 레퍼런스에도 없다.
- 결정: `SkinScreens::render_preview` 가 선택 문서를 유휴 상태로 CPU 캔버스에 그려 RGBA 를 만들고, SKIN 탭 우측과 `skinpreview` 객체(모든 화면 문서 허용, 같은 화면 재귀는 생략)가 그것을 그린다. CPU 경로가 텍스처를 못 싣는 경우 첫 `source` 이미지 축소로 폴백하되 보고한다.
- 이유: 새 화면 타입 없이 미리보기를 제공한다.
- 기각: SKIN SELECT(9) 문서 화면 신설 — 설정 화면 전체를 문서화해야 한다.

## E8. 옵션 패널 마우스는 행 사각형을 `Hot::OptionRow` 로 공개

- 배경: 옵션 오버레이는 키 전용이고 스테이지 위에 있어 클릭이 오버레이에 먼저 가야 한다.
- 결정: 네이티브·문서 옵션 행 사각형을 `Hot::OptionRow(i)` 로 공개하고, 클릭은 행 포커스 + 좌/우 반쪽에 따라 -1/+1 조정.
- 이유: 키 조작과 같은 결과를 내는 최소 경로.
- 기각: 드래그·휠 — 후속.

## E9. pmchara 는 `.chp` 캐릭터 정의를 읽고 기본 번들은 생성 캐릭터를 동봉

- 배경: 레퍼런스 `pmchara` 는 스킨 소스가 아니라 MS932 `.chp` 파일이 가리키는 이미지와 모션 표(타입 0~15, 모션별 타이머 900~908)를 쓴다. 외부 캐릭터 자산은 복사할 수 없다.
- 결정: `.chp` 로더와 `pmchara` 객체를 구현하고, 생성 스크립트가 단순 절차 캐릭터(`images/chara/`)를 만들어 `play-9k.json5` 에 붙인다.
- 이유: 레퍼런스 캐릭터 파일 호환 + 저작권 없는 기본 자산.
- 기각: 스킨 시트 기반 자체 캐릭터 형식 — 레퍼런스 캐릭터 호환이 깨진다.

## E10. 비디오 BGA 동기화는 레퍼런스 방식(전진 디코드 + 오프셋 + 프레임 드롭, EOF 시 공백)

- 배경: 레퍼런스는 시크 없이 BGA 타임라인 시점에 0프레임부터 재생하고 늦으면 프레임을 버리며, 플레이 BGA 는 루프하지 않고 EOF 후 공백이다.
- 결정: 같은 모델. 디코드는 별도 스레드, 프레임마다 새 `generation` 으로 업로드.
- 이유: 동기 규칙이 단순하고 레퍼런스와 같다.
- 기각: 시크 기반 동기 — 컨테이너별 인덱스가 필요하다.
