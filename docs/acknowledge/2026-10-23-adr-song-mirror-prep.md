## 배경

- 사용자 요구 7(2026-10-23): 가진 발광 전곡을 내 서버에 올려 Stella 식 다운로드를 갖추면 좋겠고, Cloudflare 에 올리면 되니 검토해 달라.
- 결정 17: 전곡을 업로드할 수 있을 것이라 보지만 업로드는 준비만 하고, 조사한 기록을 마지막에 알려 달라.
- 이 작업 전에는 곡 폴더를 압축·업로드하는 도구가 없었다. 웹은 Vercel Node 런타임이라 서버 코드에서 `Bun.S3Client` 를 쓸 수 없고, 저장 추상화는 리플레이 하나뿐이다.

## 결정

### 1) 지금 만든 것은 로컬 묶음 도구 하나

`rbms-cli mirror-pack <라이브러리 폴더> --out <폴더> (--table <data.json>)... [--all] [--dry-run]`

- 네트워크를 쓰지 않는다. 계정·토큰·업로드·서버·DB 변경이 없다.
- 고르는 범위: 표(`--table`, 여러 번)에 md5 가 있는 차트를 직접 가진 곡 폴더, 또는 `--all`. 둘 다 없으면 사용법 오류다(11,336 차트 전부를 실수로 묶지 않게).
- 곡 폴더 = 차트를 직접 가진 폴더. 폴더 전체(다른 차트, 소리, 그림, 아래 폴더 중 곡 폴더가 아닌 것)를 zip 으로 묶는다. `.DS_Store` 등 파일 시스템 파일과 링크는 뺀다.
- 결정적 zip: 항목은 이름의 바이트 순서, 고정 시각·권한, 주석·추가 필드 없음. 이미 압축된 형식(ogg, mp3, png, jpg, zip 등)은 저장, 나머지는 deflate 6. 같은 폴더면 같은 바이트다. 이름은 zip 바이트의 SHA-256 이고 객체 키는 `packs/<sha256>.zip` 하나뿐이다(내용 주소. 곡 이름·폴더 이름은 키에 넣지 않는다).
- `manifest.json`(형식 `rbms-song-mirror-manifest`, 세대 1, 경로·시각 없음): 표별 적중 현황, 묶음별 `key`·`sha256`·`bytes`·`uncompressed_bytes`·`entries`·`folder`·`top`·`fingerprint`·`charts`(md5·sha256·묶음 안 이름)·`notices`, 거절 목록, 겹친 md5. 폴더의 파일 이름·크기·수정 시각 지문이 같으면 다시 읽지 않고, 같은 이름의 묶음이 이미 있으면 다시 쓰지 않는다.
- 클라이언트 해제기와 같은 한도로 거절한다: 항목 10,000개, 항목 하나 1 GiB, 합계 2 GiB(`rbms_download::ExtractLimits`). 클라이언트가 풀 수 없는 묶음을 만들지 않으려는 것이다. 거절·읽기 실패는 매니페스트에 적고 나머지를 계속한다.
- `--out` 이 라이브러리 폴더 안이면 거절한다(다음 실행이 자기 결과를 묶지 않게). 결과 폴더는 저장소 밖에 둔다(곡 파일은 커밋하지 않는다. 도구가 강제하지는 않는다). 추천 위치는 `/Users/hyunseokbyun/rbms-song-mirror`.
- 매니페스트가 묶음마다 알려 주는 업로드 전 점검 정보(`notices`): 재배포를 말하는 텍스트 파일(낱말 `再配布`·`二次配布`·`転載`·`redistribut`), 모든 텍스트 파일 목록, 다른 플랫폼에서 이름이 달라질 수 있는 결합 문자 이름 수(`nfd_names`), 차트가 폴더 밖 파일을 가리키는 수(`escapes_root`). 업로드를 막지는 않고 표시만 한다.
- `zip` 크레이트는 결정 15 가 승인한 같은 워크스페이스 줄(9.0.0, `default-features = false`, `deflate-flate2-zlib-rs`)을 쓴다. 승인 문구가 "해제용" 이었는데 묶음 쓰기에도 쓴 것은 메인 판단이며 사용자에게 알린다(설계서 D-1). `Cargo.lock` 은 9.0.0 이다(설계서는 9.0.5 로 적었다).

### 2) 하지 않은 것 (사용자 답과 승인을 기다린다)

| 단계 | 내용 | 상태 |
| --- | --- | --- |
| M1 | `web/scripts/upload-song-mirror.ts`: Bun 내장 `S3Client` 로 R2 에 올림, 기본 dry-run, 자격 증명은 macOS 키체인에서 실행 중에만 | 설계만 |
| M2 | 서버: `song_mirror_pack`·`song_mirror_chart` 표, 관리 등록 라우트, 로그인 사용자에게 10분짜리 서명 URL, `node:crypto` SigV4, 환경 변수 `R2_*`, 에러 `MIRROR_NOT_FOUND` | 설계만 |
| M3 | 클라이언트 모달의 "R-BMS 미러에서 받기" | 설계만 |
| M4 | 웹 표 상세의 같은 버튼 | 설계만 |

- 모달 자리: 지금 모달은 `ModalButton`(GetChart·OpenSongUrl·OpenChartUrl·Close·Cancel)과 `buttons()` 가 만드는 순서 있는 목록이다. 미러 버튼은 이 목록의 맨 앞에 변종 하나를 더하면 된다. 구현과 다름: 설계서 U2 의 `DownloadChoice` 목록·`MAX_DOWNLOAD_CHOICES` 상수와, 내려받기 작업이 기대 바이트·SHA-256 을 입력으로 받는 계약(C3)은 만들지 않았다. 다운로드 작업은 URL 만 받는다. M3 에서 더한다.
- 버킷 만들기, 토큰 발급, 키체인·Vercel 환경 변수 등록은 사용자가 한다(12절 순서: 설계서). 에이전트는 `.env` 를 읽지 않고 시크릿 값을 대화에 남기지 않는다.

### 3) 조사 기록의 위치

- 권리 조사 기록(원문 인용, 읽은 것의 요약, 사용자 확인 질문): [`docs/plan/2026-10-23-song-mirror-prep.md`](../plan/2026-10-23-song-mirror-prep.md) 3절.
- R2 가격·한도·서명 URL·토큰과 Bun S3 의 공식 문서 사실: 같은 문서 4절(2026-10-23 확인). 비용 추정: 7절. 사용자가 할 일: 12절. 마지막 보고 초안: 13절.
- 원자료(Stella 의 규칙·소개·링크 페이지, 표 운영처의 안내, 패키지 페이지, 서비스 약관): [`docs/reference/2026-10-23-stella-course-dan-survey.md`](../reference/2026-10-23-stella-course-dan-survey.md) 의 7절, A-3, B-3.
- 요약(법적 판단이 아니다): 어느 출처도 제3자가 곡·차분 파일을 다시 배포해도 된다고 말하지 않고, 이를 직접 금지하는 문구도 R-BMS 에 직접 적용되는 것은 찾지 못했다. 표 운영처는 입수 불가 곡의 보관·공유를 각자 하는 것은 자유라 하면서 작자에게 연락할 수 있으면 먼저 하라고 한다. 차분 업로더 규칙은 대리 업로드를 제작자 허가가 있을 때만 허용한다. 곡별 readme 의 재배포 조건은 곡 폴더를 열지 않아 확인하지 못했고, 도구가 `notices` 로 표시한다.
- 비용 추정(공개 값 기준, 실측 아님): 발광 1,035곡 상한 약 40 GB → R2 Standard 월 약 $0.45(무료 10 GB 제외), 이그레스 무료. 실측은 사용자가 SSD 를 꽂고 `--dry-run` 으로 한다.

## 이유

- 결정 17 이 준비까지만 허락했다. 외부 상태(버킷, 토큰, 공개 파일)를 바꾸는 단계는 권리 근거와 접근 범위의 답이 먼저다.
- 묶음을 내용 주소의 결정적 zip 으로 만들면 중복 제거와 재업로드 판단이 해시 비교 하나이고 이름 문제가 없다. 클라이언트 해제기의 한도를 그대로 쓰면 미러에서 받은 묶음이 반드시 풀린다.
- 로컬 도구는 네트워크가 없어 에이전트가 실행해도 외부 영향이 없지만, 실제 곡 폴더 전체 실행은 시간·용량이 크고 사용자 환경이라 사용자에게 맡긴다.

## 기각된 대안

| 대안 | 기각 이유 |
| --- | --- |
| 지금 업로드까지 실행 | 결정 17 은 준비만 허락했고 권리 근거(Q-R1)가 확인되지 않았다 |
| 묶음 도구를 `web/scripts` 의 Bun 스크립트로 | Bun 에는 zip 쓰기가 없어 손수 구현하거나 의존성이 필요하다. 해제기와의 왕복 시험도 어렵다 |
| 객체 키에 곡 이름·`<md5>.zip` | 이름 문제(일본어·특수 문자·사생활)와, 한 폴더에 차트가 여럿일 때의 중복 |
| macOS NFD 이름을 묶을 때 NFC 로 바꿈 | 정규화 크레이트(새 의존성) 승인이 필요하다. 세기만 한다(설계서 D-7) |
| 서버 서명을 Bun 런타임으로 전환해 `S3Client.presign` | 운영 런타임 전환 위험. Node 유지 + `node:crypto` SigV4 (M2 설계) |

## 영향과 관련 파일

- 사용자에게 마지막 보고로 묻는 것: Q-R1 업로드 가능하다고 본 근거(작자 허락 / 표 운영처 안내 / 무료 공개 배포 / 기타), Q-R2 범위(발광 표 1,035 md5 / GENOSIDE 159곡 / `notices` 가 있는 묶음 제외 / Stella·Satellite 포함), Q-R3 받을 수 있는 사람(로그인 사용자 / 누구나), Q-R4 삭제 요청 창구, Q-R5 작자에게 미리 알릴지, Q-C1~C3 Cloudflare 계정·버킷 이름·결과 폴더.
- 남은 위험: 허락 없는 재배포가 될 수 있다. 폴더 밖 파일을 가리키는 차트(`escapes_root` > 0)는 미러로 받아도 소리·그림이 빠진다. 2 GiB 를 넘는 곡 폴더는 거절된다. 서명 URL 의 하루 상한은 메모리 레이트리밋이 인스턴스마다 따로 세어 DB 집계가 필요하다(M2). R2 가 `response-content-disposition` 질의를 지원하는지는 확인하지 못했다.
- 확인하지 못한 사실: 실제 `/Volumes/SSD/bms` 전체 실행의 시간·용량·거절 수. 곡별 readme 의 재배포 조건.
- 코드: `apps/rbms-cli/src/mirror_pack.rs`, `apps/rbms-cli/src/mirror_pack/{args,folders,manifest,notice,pack,render,select}.rs`, `apps/rbms-cli/src/main.rs`, `crates/rbms-download/src/extract.rs`(`ExtractLimits`), `Cargo.toml`(`zip`).
- 시험: `apps/rbms-cli/src/mirror_pack/tests.rs`.
