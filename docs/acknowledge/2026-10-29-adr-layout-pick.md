# ADR: 선곡에서 배치를 직접 써서 미리 보고 치는 LAYOUT PICK 은 RANDOM 판 + 역탐색 시드로 기록

> 최종 갱신 2026-10-29 · 대응 커밋 `c38a7ea`
> 상태: 유효(D1·D4·D6 은 사용자 확인 2026-10-29. M1~M4 와 "세부" 절은 메인 추천 또는 구현 단위의 결정, 사용자 미확인) · 결정일 2026-10-29 · 결정자 사용자(요청과 D1·D4·D6)와 메인(M1~M4), 구현 단위 U1(세부) · 커밋 `c38a7ea`
> 관계: 판이 도는 동안 배치를 빌리는 길은 [배치 플레이 ADR](2026-10-24-adr-layout-play.md)을 그대로 쓴다. 시드 범위는 [배치 시드 ADR](2026-10-14-adr-layout-seed-range.md), 같은 배치 재시도는 [같은 배치 재시도 ADR](2026-10-14-adr-same-layout-retry.md). 설계 [plan/2026-10-29-feature-upgrade.md](../plan/2026-10-29-feature-upgrade.md), 조사 [reference/2026-10-29-feature-upgrade/layout-pick.md](../reference/2026-10-29-feature-upgrade/layout-pick.md).

## 배경

- 사용자 요청(2026-10-29): "시작 전에 배치를 내가 정하고 미리보기를 하고 그 배치대로 플레이 가능한 기능을 넣어줘 (기록저장도 되어야해 어차피 계속뽑다보면 나올 배치라 그걸 편하게하려고 하는기능)".
- RANDOM 은 차트 내용과 무관한 레인 순열이다. `lane_permutation(Random, mode, seed)` 는 모드와 시드만 읽는다. 그래서 원하는 순열을 내는 시드는 차트 없이 찾을 수 있고, 그 시드로 판을 시작하면 지금의 로드 경로가 같은 배치를 만든다.
- 판이 도는 동안 옵션과 시드를 빌려 기록·리플레이·제출이 RANDOM + 시드로 남는 길(`AppShared::borrow_layout`)이 이미 있다.

## 결정

### 1) 사용자가 정한 것

| 번호 | 결정 |
| --- | --- |
| D1 | 직접 정한 배치의 판은 RANDOM 판으로 저장한다. 그 배치를 내는 RANDOM 시드를 역탐색해 옵션 RANDOM + 시드로 기록한다. 서버·웹·리플레이 형식은 바꾸지 않는다 |
| D4 | 배치 미리보기는 그 배치를 적용한 실제 노트를 레인에 그려 스크롤하고 레인 번호 순서를 보인다 |
| D6 | 지정한 배치 문자열은 앱이 켜져 있는 동안 모드별로 기억한다. 설정 파일에는 저장하지 않는다(사용자 답 "2번으로"를 NPS·배치 기억 두 질문 모두 2번 선택지로 읽었다) |

### 2) 메인 추천(사용자 미확인)

| 번호 | 결정 |
| --- | --- |
| M1 | 배치 지정은 선곡 위에 여는 새 내장 화면(`Stage::LayoutPick`, 연습 패널과 같은 층)이다. 새 단축키 `Y`(설정 이름 `layout_pick`, 키 설정 Browser 그룹, 패드 지정 가능)로 연다. 커서가 차트 막대일 때만 열린다. 폴더·코스·라이브러리에 없는 차트에서는 알림만 낸다. 검색어를 치는 중에 누르면 검색을 끝내고 연다 |
| M2 | 배치 문자열은 "왼쪽 i 번째 레인에 오는 원래 레인 번호"이고 쪽마다 1부터 센다(beatoraja 의 lane order 표시와 같다). 스크래치는 문자열에 넣지 않는다. OFF 와 같은 `1234567`, MIRROR 와 같은 `7654321` 도 D1 대로 RANDOM + 시드로 기록한다 |
| M3 | DP 는 1P·2P 두 줄을 모두 지정한다(Tab 으로 쪽 전환, 기본은 둘 다 순서대로). 10키에서 RANDOM 으로 만들 수 없는 쌍과 24키는 시작을 거절하고 이유를 화면에 보인다 |
| M4 | AUTOPLAY 가 켜져 있으면 미리보기는 되고 시작은 막고 안내한다. 코스·연습에서는 시작하지 않는다(`borrow_layout` 의 `NotFreePlay` 거절) |

### 3) 시드 역탐색(구현 단위가 정함, 사용자 미확인)

| 항목 | 내용 |
| --- | --- |
| 함수 | `rbms_chart::shuffle::random_seed_for(mode, wanted, limit, cancel)` 와 `random_seed_limit(mode)`. 기존 함수의 동작과 골든은 바꾸지 않았다 |
| 탐색 순서 | 시드 1 부터 오름차순의 첫 시드. 같은 배치는 늘 같은 시드다(결정적). 시드 시작점을 `fresh_layout_seed` 로 두는 안은 탐색 시간과 상한 보장이 비결정적이라 쓰지 않았다 |
| 방식 | 쪽마다 스택 배열로 Fisher-Yates 를 끝 자리부터 그리고 처음 틀린 자리에서 그 시드를 버린다. 2P 쪽은 1P 쪽이 맞을 때만 그린다(시드 s 의 2P 쪽이 시드 s+1 의 1P 쪽과 같다). 찾은 시드는 `lane_permutation(Random, mode, seed) == wanted` 로 한 번 더 확인한 뒤에만 돌려준다 |
| 상한 | 5키·7키·9키 2^23, 10키 2^21, 14키 2^29. 측정한 최댓값(각각 4,775,533 / 1,250,411 / 468,482,176)을 넘는다. 결과는 늘 1 이상 2^53 미만이다 |
| 취소 | 65,536 시드마다(첫 시드 포함) 취소 플래그를 본다. 배치가 바뀌면 진행 중인 탐색을 취소하고 다시 찾는다 |
| 불가능 | 24키는 `UnsupportedMode`(24! 이 2^53 보다 커 대부분 만들 수 없다). 10키는 14,400쌍 중 12,600쌍만 RANDOM 이 만든다. 1,800쌍(예: `12345` / `51234`)은 상한을 다 돈 뒤 `Unreachable` 이다. 원인은 구조적이라는 것만 확인했고 증명하지 않았다 |
| 비용 | 릴리스 14키 시드당 약 4.6 ns. 시드 83,818,986 의 쌍은 0.38 초, 10,933,418 의 쌍은 0.05 초. 최악 4.7억이면 약 2.2 초로 추정한다. 디버그 빌드는 수십 초일 수 있다 |

### 4) 화면과 시작(구현 단위가 정함, 사용자 미확인)

- 입력: 숫자 1~9(넘패드 포함)는 현재 쪽에 들어간다. 그 차트 모드의 레인 키는 그 레인이 속한 쪽에 그 쪽 번호로 들어가고 현재 쪽도 그쪽으로 바뀐다. 남은 칸은 쓰지 않은 번호를 오름차순으로 채우므로 키 하나를 칠 때마다 배치 전체가 완성된 상태가 된다. 다 채운 줄에 다시 치면 새로 시작한다. 이미 넣은 번호나 범위 밖 번호는 거절하고 2초 알린다.
- 미리보기: 내장 플레이필드(`render_playfield_view`)를 화면의 첫 그리기로 부른다. 한 화면에 네 마디(하이스피드 0.25). 각 레인 아래에 원래 레인 번호를 쓰고 입력한 칸은 밝게, 자동으로 채운 칸은 흐리게 보인다.
- 시작: Enter, 키보드 START, 패드 START. `borrow_layout(LayoutRequest { md5: 라이브러리 md5, random_label: "RANDOM", seed, source: "지정한 배치 3517246" })` 을 부르고 돌아온 `Transition::Open` 을 `Transition::To` 로 바꿔 이 화면 자리에 판이 선다. 거절 순서: AUTOPLAY, 차트 읽는 중·실패, 라이브러리 md5·모드가 실제 파일과 다름, 24키, 10키 불가능 쌍, 시드를 아직 못 찾음, `borrow_layout` 의 거절.
- 기억: 화면을 나갈 때(시작 포함) `AppShared.picked_layouts` 에 모드 이름별로 두고 다음에 열 때 그 배치로 연다. 설정 파일에는 쓰지 않는다.
- 차트 읽기(`decode_chart` + 플레이어 LN MODE 해석)와 시드 탐색은 각자 이름 있는 스레드에서 돌고 프레임 스레드는 결과만 받는다.

## 이유

- RANDOM + 시드로 기록하면 서버·웹·리플레이 형식과 마이그레이션이 없고, 기존의 같은 배치 재시도·버림 규칙·고스트 규칙이 그대로 맞는다. 사용자는 "계속 뽑다 보면 나올 배치"를 편하게 얻으려는 것이므로 RANDOM 판이라는 기록의 의미도 그대로다.
- 독립 화면이어야 레인 키를 입력으로 읽을 수 있고, 내장 플레이필드가 프레임을 지우는 것(`clear`)도 문제가 되지 않는다. 연습 패널이 같은 이유로 독립 화면이다.
- 결정적 탐색이면 같은 배치의 판들이 같은 시드를 쓰지만 시드는 배치 재현용 값이라 기록·리플레이에 문제가 없다.

## 기각된 대안

| 대안 | 기각 이유 |
| --- | --- |
| 선곡 오버레이 모달 | 내장 플레이필드가 화면을 지워 `PlayfieldView` 를 고치거나 함수를 쪼개야 하고 골든 PNG 에 영향이 간다. 스킨 선곡의 건반 읽기와 키 경로가 얽힌다 |
| 연습처럼 로드 후 화면으로 | 미리보기 전에 LOADING(키음·BGA 디코드)을 치른다. 연습은 기록하지 않는 규칙과 섞인다 |
| OFF·MIRROR 모양의 문자열은 OFF·MIRROR 로 기록 | 일관성(D1)이 깨진다. 모양이 같아도 RANDOM + 시드로 남긴다 |
| 시드 시작점을 판마다 바꿈 | 탐색 시간이 결정적이지 않고 상한 보장이 약해진다 |
| `Borrowing` 과 별도의 `picked_layout` 필드 | 수명·복원 규칙(재시도 유지, 버림, 내 옵션 복원)을 다시 구현해야 한다 |
| 한쪽만 지정, 불가능 쌍은 가장 가까운 가능 쌍을 제안 | 양쪽 지정(M3)이 단순하다. 불가능 쌍은 거절하고 이유를 보인다 |
| 문자열을 설정 파일에 저장 | D6 이 세션 기억으로 정했다 |
