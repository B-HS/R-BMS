## 배경

- 사용자 요청 요지(2026-11-19): 12 곡 선택 화면 UI/UX 개선(머리·바닥·제목 크기, 자체 심사).
- 메인이 캡처(`docs/assets/screenshot-select.jpg`)를 보고 적은 문제(조사 12절):
  1. 머리: 한 줄에 모양이 다른 7개 블록(`MUSIC SELECT` 맨글자, `SP`·`FREE PLAY` 채운 칩, 밑줄 검색칸, 시계 칩, 두 줄짜리 MODE·SORT·LN MODE 카드)이 섞여 있고 아래 선이 오른쪽 절반에만 있다. 경로(`ALL SONGS`)는 머리와 목록 사이에 떠 있다.
  2. 제목: 제목 글자가 화면에서 가장 크고(디스플레이 크기), LEVEL·BPM 은 오른쪽 끝에 떨어져 있어 사이가 빈다. 블록 높이 200.
  3. 바닥: 두 줄. 둘째 줄은 대문자 문장("SEARCH, FILTER, ... SEE H FOR THE KEY OF EACH")이다. 왼쪽 키 표지와 오른쪽 버튼 높이가 다르다.
  4. 정보창: 구획 머리의 선 길이와 값 정렬이 구획마다 다르다. MY SCORE 의 등급 상자와 `MAX -27` 이 붙어 있다.

#### 머리

모든 글자가 기준선 y 77(`head.baseline`) 하나를 공유한다. 규칙은 "정보는 맨글자, 조작할 수 있는 것은 칩과 칸"이다.

| 자리 | 내용 |
| --- | --- |
| 왼쪽(x 64, 폭 552) | 맨 위 작은 줄 "MUSIC SELECT · SP · FREE PLAY"(caption, muted). 그 아래에 목록 위에 떠 있던 경로를 label 24 로 올렸다. SP/DP/9KEYS 와 FREE PLAY/COURSE 칩은 없애고 첫 줄 문장(화면 이름 · 스타일 · 모드)으로 합쳤다. 새 문구는 없고 기존 i18n 을 쓴다 |
| 가운데(검색, x 736, 폭 360, 정보창 오른쪽 끝에 맞춤) | 검색칸. 비었을 때는 선 하나와 muted 라벨만 보인다. 검색 중이거나 검색 결과를 보는 중이면 panel 채움과 accent 밑줄, sub 라벨로 바뀐다 |
| 오른쪽(x 1128 부터, 목록 열에 맞춤) | MODE·SORT·LN MODE 를 같은 모양의 한 줄 칩(높이 40, 이름은 caption, 값은 오른쪽 정렬 label)으로 바꿨다. 끝(x 1752, 폭 104)에 시계를 칩 없이 sub 글자로 둔다 |
| 아래 선 | 머리 아래 선은 원래부터 64~1856(여백에서 여백)에 있었고 그대로 둔다(0~1920 으로 넓히면 바닥 선·결과·결정 화면과 어긋난다). 문제의 원인은 오른쪽 필터 카드의 아랫변(96)이 선(104) 바로 위에 붙어 오른쪽 절반에만 이중선처럼 보인 것이었다. 칩이 88 에서 끝나도록 해서 선이 하나만 보인다. 계획 지침 1 의 "띠 아래 선은 화면 전체 너비"는 그 때문에 다르게 처리했다 |

#### 제목 블록

| 항목 | 내용 |
| --- | --- |
| 크기 | 블록 높이 200 → 136(y 136~272). 제목을 `title` 64 에서 `heading` 44 로 줄였다(`SHRINK_CUT` 유지). 장르는 label 24(sub), 부제는 24(sub), 아티스트는 body 32(text). 줄 기준선은 153(장르)·199(제목)·228(부제)·263(아티스트) |
| LEVEL·BPM | 오른쪽 끝에서 색 막대 바로 옆 폭 104(`meta_width`) 칸으로 옮겼다. LEVEL 은 장르 줄의 라벨과 제목 기준선의 `num44`, BPM 은 부제 줄의 라벨과 아티스트 기준선의 값이다. 제목 길이와 상관없이 빈 띠가 생기지 않는다 |
| 폴더·코스 | 제목 줄이 색 막대 바로 옆(x 96)에서 시작한다 |

#### 바닥

| 항목 | 내용 |
| --- | --- |
| 구성 | 한 줄, 중심선 y 1040(`foot.center`). 왼쪽: ENTER PLAY · ESC BACK · ↑↓ MOVE · H KEY GUIDE. 문장형 둘째 줄과 i18n 키 `bar_hint_line`·`bar_hint_all_keys` 를 지우고 `bar_hint_key_guide`(KEY GUIDE / 키 안내 / キーガイド)를 더했다. Inter 에 ↑↓ 글리프가 있는 것을 확인했다 |
| 높이 | 키 표지(`key_height` 28)와 버튼(`button_height` 40)이 같은 중심선과 같은 글자 기준선을 쓴다. 키 표지를 버튼보다 작게 두어 누를 수 없는 표지임을 구별한다. 키 라벨·버튼 글자는 모두 sub 로 통일했다 |
| 오른쪽 | REPLAY 묶음은 목록 열(x 1128)에서 시작하고 버튼은 1856 에서 끝난다. 누르는 영역도 `kit.button` 의 같은 상자로 함께 옮겼다. 버튼 글자(FAVORITE·AUTOPLAY 등)에 `SHRINK_CUT` 을 걸어 한국어·일본어(お気に入り, ランキング)에서도 칸을 넘지 않게 했다 |
| LN MODE 칩 값 | LN·CN·HCN 약어. 한 줄 칩에서 HELL CHARGE NOTE(24 크기에서 238 px)나 ヘルチャージノート 는 하한 0.75 를 넘어 잘린다. 목록 막대 라벨·코스 제약과 같은 표기이고 빠른 설정 패널은 전체 이름을 그대로 보인다 |

#### 정보창

| 항목 | 내용 |
| --- | --- |
| 구획 머리 | `kit.section`(구획 폭의 선 + 12 아래 caption + 머리 높이 40, `section = { title_drop = 12, header = 40, label_drop = 48, value_gap = 10 }`) 한 부품으로 통일했다. CHART DATA·MY SCORE·NOTES RADAR·MY RECORDS/IR RANKING·SCORE TARGETS·CLEAR RATE·폴더(CHARTS, CLEAR LAMPS)·코스(STAGES, CONSTRAINTS)가 모두 쓴다. SCORE TARGETS 만 따로 쓰던 머리 간격이 없어졌다 |
| 라벨·값 | 라벨은 구획 위에서 48 아래, 값은 `kit.value_baseline`(라벨 아래 10 + 값 높이) 한 식으로 맞췄다 |
| MY SCORE | 등급 상자가 라벨 위에서 큰 숫자 기준선까지 차지하고, 램프 이름과 `MAX -27` 은 그 아래 16 을 띄운 줄(기준선 +136, `lamp_baseline_drop`)로 옮겨 겹침이 없어졌다. 등급 상자 128 → 112, MISS 칸 96 → 112(MISS COUNT 라벨이 96 폭에서 눌려 보이고 5자리 12345 가 상자에 닿던 것을 고침) |
| 세로 배치 | 제목 136~272 → 24 → 1행 296~552 → 24 → 2행 576~872(높이 256 → 296, 줄어든 머리 높이를 여기에 줌) → 24 → 목표 줄 896~968(높이 64 → 72). 위아래 끝(136·968)은 스크롤 막대 트랙과 같고 머리 선 아래 32·바닥 선 위 32 로 대칭이다. 구획 사이 간격 24 는 세로에 일률 적용하고 가로 간격은 격자 gutter 32 를 그대로 둔다(열 경계 352·784·1128) |
| 그 밖 | MY RECORDS 줄 높이 36 → 42. 레이더 영역 `RADAR_AREA` y 640 → 576·높이 296, 레이더 중심 영역 위에서 144 → 168 아래(`RADAR_CENTER_DROP`). 쓰지 않게 된 토큰(`facts.label_drop`·`value_drop`, `score_rows.label_drop`·`baseline_drop`·`badge_height`·`lamp_drop`, `records.header_height`, `head.chip`·`style_chip`·`mode_chip`)은 지웠다 |
| 등급 램프 | 웨이브 1 의 `lamp_graded`(목록 막대)와 MY RECORDS·랭킹 줄 덮개는 `cell()`·`row_box()` 를 따라 새 자리에서도 램프 칸에 겹친다(U8 이 `recorded-scratch-auto` 캡처로 확인했다고 보고) |

#### 검색 강조의 근거

검색어가 있는지·입력 중인지는 스킨이 직접 읽을 수 없다(`SEARCHWORD` 는 원본처럼 항상 빈 문자열이고 입력 중 플래그도 없다). 그래서 `DIRECTORY` 가 원본 `SearchWordBar` 제목 형식 `Search : '` 로 시작하는지로 판단한다. 앱 쪽 값은 추가하지 않았다(M18). 이 때문에 계획 지침 1 의 "입력 중이면 도드라지게"는 첫 글자를 친 뒤부터 적용된다. 검색 키만 누르고 아직 글자가 없는 순간에는 조용한 모양에 캐럿만 보인다. 이 구간까지 하려면 스킨이 읽을 입력 중 값이 앱에 있어야 한다.

## 이유

- 머리의 모양이 7가지이던 것을 "정보는 맨글자, 조작은 칩과 칸" 두 규칙으로 줄이면 한 띠에서 기준선을 공유할 수 있다.
- 제목을 heading 크기로 줄이고 LEVEL·BPM 을 붙이면 줄어든 높이를 아래 정보창이 쓴다(2행 256 → 296).
- 한 줄 바닥은 문장형 안내(H 키 안내와 중복)를 없애고 버튼과 같은 높이로 맞춘다.
- 구획 머리를 한 부품으로 하면 구획마다 선 길이와 값 정렬이 다르던 문제가 구조적으로 사라진다.
- 스킨만 바꾸면 외부 스킨·앱 코드·시험 기대값에 영향이 없다(선곡을 고정한 시험은 기본 스킨 좌표를 고정하지 않는다).

## 기각된 대안

| 대안 | 기각 이유 |
| --- | --- |
| 앱 쪽 값 추가(입력 중 플래그 등) | 범위가 커진다. 검색 강조는 `DIRECTORY` 형식으로 대신했다 |
| 머리 아래 선을 0~1920 로 넓히기 | 바닥 선·결과·결정 화면의 64~1856 과 어긋난다. 이중선의 원인은 칩 아랫변이었다 |
| LN MODE 칩에 전체 이름 | 한 줄 칩 폭에서 잘린다. 약어(LN·CN·HCN)를 쓴다 |
| 새 색 | 모노톤과 강조색 규칙. accent 는 기존처럼 켜짐 상태(검색 중 밑줄, 랭킹 켜짐, 리플레이 선택)에만 쓴다 |

## 영향과 관련 파일

- 코드(스킨): `assets/skins/rbms-default/lua/{theme.lua, select/{controls,info,kit,list,main,radar,records}.lua, i18n/select_bar.lua}`. Rust 변경 없음.
- 검증: 선곡 단위 시험 598개, 기본 팩 시험 71개, `rbms-skin` `default_pack` 12개, `rbms-cli` strict 게이트 시험, `skin-dump --strict --frames 120`(팩 전체 문서 9개 ok, select.luaskin 을 en/ko/ja 시나리오로 돌려 dest 2166·fns 465·pcall·fn fail·warn·over 모두 0, 팩 88 files unchanged), 시트 검사 exit 0. 개편 전·후 캡처를 반복해 떠서 보고 고쳤고 메인이 캡처로 판정했다.
- 알려진 위험(테스트 부채 3.180·3.181, 실기 QA 3.29 G12):
  - 캡처 하니스는 CJK 를 그리지 못해 한국어·일본어의 실제 모습은 보지 못했다. 폭은 계산으로만 따졌다. 칩 이름 칸(MODE 60, SORT 56, LN MODE 92), 바닥 라벨 64, REPLAY 76, ランキング 90/96, お気に入り 약 90/88 은 `SHRINK_CUT` 하한 0.75 안에 든다고 계산했다.

  - LN MODE 칩이 약어로 바뀌어 머리에서 전체 이름이 사라졌다(빠른 설정 패널에는 남아 있음).
  - SORT 값 `RIVALCOMPARE_SCORE`·`RIVALCOMPARE_CLEAR` 는 칩 폭 136 에서 말줄임이 된다(드문 정렬).
