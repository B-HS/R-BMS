# 스킨 시스템 완성 결정 (2026-09-17, 최종 갱신 2026-09-18)

사양: `docs/plan/2026-09-17-skin-system-completion.md`. 이력: `docs/history/2026-09-17-skin-system-completion.md`. 조사 근거는 세션 스크래치의 R1(엔진 격차)·R2(앱 배선)·R3(외부 묶음 레이아웃) 보고서이며 핵심 수치는 사양 §9와 이력 K1에 옮겼다(보고서 자체는 저장소 밖). 사용자 지시는 "제공한 외부 스킨 묶음과 화면을 참고해 기본 스킨·스킨 구조·커스터마이징을 완벽히 구현하고 필요한 기능은 docs/에 두고 구현"이다. 아래는 그 범위 안에서 메인 오케스트레이터가 내린 판단이며, 사용자가 다른 선호를 알리면 그때 갱신한다. 각 항목은 배경 / 결정 / 이유 / 기각한 대안 순서다. 결정 여러 건을 한 파일에 두는 것은 이 저장소의 관례(`2026-09-09-enhancement-decisions.md`)를 따른 것이다.

## D1. 기본 번들은 3세대 `steel-neon-v3`, 프리셋 라벨 `STEEL NEON` 유지

- 배경: v1·v2 번들이 이미 설치돼 있고 설정 파일은 프리셋 라벨로 번들을 가리킨다.
- 결정: 디렉터리만 `steel-neon-v3`로 올리고 라벨은 유지한다. `BUNDLE_GENERATIONS`(v1·v2·v3)에서 이전 세대의 `custom`·`shared`를 새 세대 키로 옮긴다.
- 이유: 기존 설정이 그대로 새 번들을 가리키고 사용자가 고른 값이 유실되지 않는다.
- 기각: 새 프리셋 이름 — 설정 마이그레이션과 라벨 변경을 요구하고 얻는 것이 없다.

## D2. 중첩 destination 은 로더가 조립(`LoadedSkin.nested`)

- 배경: R1 — 로더가 최상위 `destination`만 트랙으로 조립해 `note`·`judge`·`songlist`의 내부 배열은 그릴 수 없었다.
- 결정: 로더가 `NestedTracks`(note group/bpm/stop/time, `JudgeTracks` images/numbers, `SongListTracks` 9배열+graph)를 만들어 렌더러에 넘긴다.
- 이유: Lua 컴파일과 dst 보간이 로더 한 곳에만 있고 렌더러는 트랙만 읽는다.
- 기각: 렌더 측 재조립 — `build_track`을 공개해야 하고 Lua 컴파일이 두 곳으로 갈린다.

## D3. 행·시계열 상태는 `SkinFrame.extra`(`FrameExtra`)

- 배경: R1 — 상태 소스가 스칼라(숫자·문자열·불리언)만 답해 노트 배열·곡 목록 행·게이지 추이를 줄 수 없었다.
- 결정: 프레임마다 화면 모양의 `FrameExtra`(Play/Select/Result)를 별도로 붙인다.
- 이유: 기존 스칼라 계약과 문서·테스트를 그대로 둔다.
- 기각: 스칼라 트레이트 확장 — 기존 문서·테스트 전수 수정.

## D4. 타이머는 `TimerState` 드라이버(`PlayTimers`·`ResultTimers`·PANEL1)

- 배경: R1 — 타이머가 상태 소스로 흐르지 않고 결과·결정 화면에 드라이버가 없어 KEYON/KEYOFF/BOMB·결과 애니메이션이 동작하지 않았다.
- 결정: 화면별 드라이버가 레인·사이드·결과 타이머(150/151/152)와 옵션 패널 타이머를 채운다.
- 이유: 레퍼런스의 타이머 의미를 한 곳에서 유지한다.
- 기각: 상태 소스의 `timer()` 구현 — 레퍼런스 의미와 이중화.

## D5. `note` 객체가 있으면 레인 기하는 문서가 단일 원천

- 배경: 실화면 캡처 2장에서 RON 좌표와 문서 좌표가 어긋나 노트·BGA·그래프가 겹쳤다.
- 결정: 플레이 문서의 `note.dst`로 `Skin::with_document_lanes`가 레인을 재구성하고 HUD·커버·키봄도 그 좌표를 쓴다. RON은 `note`가 없는 문서의 폴백.
- 이유: 좌표 이중 원천이 결함의 근원이었다.
- 기각: RON과 문서 병행 — 같은 결함 재발.

## D6. 대체 선언은 최상위 `replace` 표

- 배경: R1·R2 — 네이티브 대체가 결과 화면 전용(`result.replace` 4단위)이었다.
- 결정: 모든 화면이 최상위 `replace: [...]`로 단위를 선언하고 `SkinScreen::replacement(screen, name)` 한 곳이 필요한 객체 id 를 판정한다. 하나라도 없으면 경고 1회 + 네이티브 유지.
- 이유: 화면마다 코드 중복 없이 같은 계약.
- 기각: 결과 전용 하드코딩 확장 — 화면마다 코드 중복.

## D7. 히트 사각형은 `songlist` 슬롯 + `hotspot` 선언

- 배경: 문서 객체에 `click` 이벤트가 없어 곡 목록 클릭과 상단 버튼을 문서가 제공할 수 없었다.
- 결정: `songlist.clickable` 슬롯 사각형과 `hotspot: [{ id, action }]`(8 action)을 `SkinScreen`이 화면 좌표로 변환해 `Hot`으로 넘긴다.
- 이유: 입력 계층을 새로 만들지 않고 기존 `Hot` 경로를 재사용.
- 기각: 문서 객체 `click` 이벤트 디스패치 — 입력 계층 신설 필요, 후속.

## D8. 커스터마이즈는 번들 스코프 저장(R2 안 A)

- 배경: R2 — 커스터마이즈가 문서 절대경로 키라 5개 플레이 문서가 값을 공유하지 못하고 세대 이동 시 `custom`이 유실됐다.
- 결정: 헤더의 `scope: 'bundle'` 행은 `SkinOptions.shared[bundle_key]`에 저장하고 `user_config`가 문서 값 아래에 병합한다. SKIN 탭은 `BUNDLE` 그룹으로 보인다.
- 이유: 값이 한 번 정해지면 번들의 모든 화면이 따른다.
- 기각: include 헤더(안 B) — 선언만 공유하고 값은 공유하지 못함.

## D9. 사운드 22 스템은 절차 생성, 번들 `sound/`에서 해석

- 배경: 시스템 사운드가 `audio.sound_folder` 단일 폴더였고 번들에 사운드가 없었다. 외부 음원 복사는 금지.
- 결정: `tools/generate-sounds.py`로 합성하고, `sound_folder` 미지정 + 프리셋 `STEEL NEON`이면 번들 `sound/`를 읽는다.
- 이유: 저작권 없는 자산으로 전 스템을 채운다.
- 기각: 외부 음원 복사 — 금지. BGM 루프 — 재생 경로가 없어 후속.

## D10. 옵션 패널은 select 문서의 `options` 대체 단위 + 사설 id 20101~

- 배경: 옵션 오버레이가 네이티브 고정이었고 참고 화면 3장이 옵션 패널이었다.
- 결정: `options-panel` + `option-row-{0..10}-{label,value}` 객체와 사설 id(라벨 20101~, 값 20121~, 포커스 20141~)로 대체한다.
- 이유: 레퍼런스 화면 타입 표를 바꾸지 않는다.
- 기각: 별도 화면 타입 신설 — 레퍼런스 타입 표와 어긋남.

## D11. 판정 문구·라벨은 `text` 객체, 숫자는 7세그먼트 비트맵

- 배경: 생성 스크립트는 순수 파이썬(PIL 없음)이라 글꼴을 래스터화할 수 없다.
- 결정: 글자는 `text`(엔진 글꼴), 숫자는 7세그먼트 시트. rbms 확장으로 `judge.images[k]`가 `text` id 를 가리킬 수 있다.
- 이유: 도구 의존 없이 재생성 가능.
- 기각: 글꼴 래스터 비트맵 — 래스터라이저 부재.

## D12. 노트 밀도는 rbms 확장 `densitygraph` 객체

- 배경: 선택 상세의 밀도 그래프가 네이티브 전용이었고 레퍼런스에 대응 객체가 없다.
- 결정: `densitygraph`(`barColor`, `peakColor`, `lineWidth`) 객체를 추가한다.
- 이유: 상세 패널을 문서가 통째로 가질 수 있다.
- 기각: 네이티브 유지 — `detail` 대체 단위가 성립하지 않는다.

## D13. 숫자 시트는 렌더러 11셀 규약(12셀 시트 폐기)

- 배경: 처음 만든 12셀 시트는 렌더러의 "11번째 셀 = 대체 0" 규칙과 어긋나 선행 빈자리가 `-`로 그려졌고 7세그먼트 `1`이 콜론처럼 보였다.
- 결정: `digits-s/m/l`은 0~9 + 공백 11셀(`divx: 11`), `digits-f`는 11×2(소수점·음수 행). 글리프 기하도 다시 그렸다.
- 이유: 레퍼런스 `value` 의미와 같은 규약을 쓰면 문서가 그대로 호환된다.
- 기각: 렌더러 규칙 변경 — 레퍼런스 문서 호환이 깨진다.

## D14. SUDDEN+ 커버는 `offset: 4` 이미지, HIDDEN+/리프트만 전용 객체

- 배경: 레퍼런스 어휘에 `hiddenCover`(HIDDEN+)·`liftCover`(리프트)는 있으나 SUDDEN+ 전용 객체는 없다.
- 결정: 문서의 `cover-sheet` 이미지에 `offset: 4`(레인커버 오프셋)를 걸어 SUDDEN+ 를 표현한다.
- 이유: 새 객체 없이 레퍼런스 방식 그대로.
- 기각: SUDDEN+ 객체 신설 — 레퍼런스 어휘 밖.

## D15. 결과 `hint`·`ir` 대체 단위와 사설 id 20203~20205

- 배경: 중간 캡처에서 앱이 그리던 IR 상태 줄과 하단 조작 힌트가 문서 표 위에 겹쳤다.
- 결정: `result-hint`(20204)·`result-ir`(20205), 선택 힌트 20203 을 추가하고 `draw_result_skin*`는 `ResultExtras`(목표·다시 하기 힌트)를 받는다. `ResultExtras` 구조체는 clippy `too_many_arguments` 를 피하기 위한 것이기도 하다(레포에 `#[allow]` 전례 0건).
- 이유: 문서가 겹치지 않게 그 줄을 소유할 수 있다.
- 기각: 네이티브 줄 무조건 제거 — 그 줄을 안 그리는 문서에서 정보가 사라진다. `#[allow(clippy::too_many_arguments)]` — 레포 관례 위반.

## D16. 키 봄은 항상 네이티브

- 배경: 리뷰 지적 — 봄을 문서 객체로 두면 판정과 레인 좌표 이중 관리.
- 결정: `render_key_bomb`는 대체 단위 없이 항상 그린다(레인 좌표가 D5로 문서와 같으므로 위치가 맞는다).
- 이유: 레퍼런스도 봄을 판정 객체와 분리한 독립 객체로 두지 않는다.
- 기각: `bomb` 대체 단위 — 이중 관리.

## D17. `screen_content`는 컴파일 시 1회 계산해 캐시

- 배경: 리뷰 지적 — 대체 게이트를 프레임마다 재계산하고 있었다.
- 결정: `SkinScreen` 컴파일 시 `screen_content_of`로 계산해 `screen_content(screen)`이 읽는다.
- 이유: 문서가 바뀔 때만 게이트가 바뀐다.
- 기각: 프레임마다 재계산 — 불필요한 비용.

## D18. BGA SIZE OFF 는 투명 목적지로 `bga` 소유를 유지

- 배경: 엔진은 "문서가 `bga`를 그린다"로 네이티브 BGA 사각형을 생략한다. OFF 에서 목적지를 없애면 네이티브 사각형이 다시 나타난다.
- 결정: `op: [912]` 목적지를 `a: 0`으로 둔다.
- 이유: 엔진 변경 없이 OFF 를 표현.
- 기각: `bga` 선언 자체로 게이트하도록 엔진 변경 — 가능하나 이번 범위 밖(이력 "남은 범위").

## D19. PLAY SIDE 2P·GRAPH POSITION 은 문서 분기(4조합 펼침) + 프레임 4장

- 배경: 렌더러에 좌우 미러 변환이 없다.
- 결정: 로더의 조건부 원소·include 로 `shared/objects-play.json5`가 PLAY SIDE × GRAPH POSITION 4조합을 `op`로 분기하고 `shared/judge-sp.json5`가 1P/2P 판정 위치를 나눈다. 프레임은 `frame-sp{,-2p,-near,-2p-near}.png` 4장.
- 이유: 엔진 기능 추가 없이 문서만으로 동작하고 프레임 그림과 어긋나지 않는다.
- 기각: 렌더러 미러 변환 — 새 엔진 기능이며 프레임 그림과 어긋난다.

## D20. 실제 GPU 창 확인은 사용자 절차로 이관

- 배경: 이 터미널에 macOS 화면 녹화 권한이 없어 `screencapture`가 실패했다.
- 결정: 헤드리스 캡처 12장을 근거로 남기고 실제 창 확인 절차를 QA 체크리스트 §3에 두어 완료로 표시하지 않는다.
- 이유: 사용자 규칙 — 실제 렌더 확인 없이 "완료"를 단언하지 않는다.
- 기각: 헤드리스만으로 완료 선언 — 규칙 위반.

## D21. 커밋은 5단위, 한국어 Conventional Commits, 사용자 지시 후

- 배경: 사용자 규칙 — 커밋은 명시 지시 때만, author 단독, 트레일러 금지. 최근 커밋이 한국어 설명(`2026-09-17-commit-language.md`).
- 결정: `feat(skin)` 로더·모델 / `feat(render)` 객체·상태 / `feat(config)` 공유 스코프 / `feat(player)` 배선·설치·사운드 + v3 자산 / `docs(skin)` 문서. 단위별 파일 목록은 `docs/HANDOFF.md` §8.
- 이유: 크레이트 단위로 되돌릴 수 있고 `assets.rs`의 `include_bytes`가 자산에 의존하므로 player 와 자산은 같은 커밋.
- 기각: 단일 커밋 — 되돌리기 단위가 너무 큼. 지시 전 자동 커밋 — 사용자 규칙 위반.

## D22. 결정 기록은 세션 단위 파일에 ADR 항목 구조

- 배경: 핸드오프 스킬은 "결정 1건 = 파일 1개"를 권하지만 이 저장소는 세션 단위 결정 파일 관례를 쓴다.
- 결정: 기존 파일에 배경/결정/이유/기각 항목 구조를 넣고 파일을 쪼개지 않는다.
- 이유: 프로젝트 관례가 컨벤션 묶음보다 우선한다(`~/.claude/convention/index.md` 우선순위 사다리).
- 기각: 결정 1건 = 파일 1개 — 기존 결정 파일과 병렬 체계.

## D23. 이전 HANDOFF 본문은 history 로 이동, HANDOFF 는 최신 스냅샷 전용

- 배경: `docs/HANDOFF.md`가 2026-09-10 보존 본문을 담고 있었고 새 스냅샷은 덮어써야 한다.
- 결정: 본문을 `docs/history/2026-09-10-handoff-snapshot.md`로 옮기고 `docs/HANDOFF.md`는 2026-09-18 스냅샷만 담는다.
- 이유: 새 세션의 진입점이 하나여야 하고 과거 기록은 history 가 맡는다.
- 기각: 덮어쓰기만 — git 에는 남지만 문서 지도에서 사라진다.
