# ADR: 감사 에이전트의 실수로 운영 서버에 간 판 49개는 지우지 않고 둔다

> 최종 갱신 2026-10-15 · 대응 커밋 ea698a9
> 상태: 유효 · 결정일 2026-10-15 · 결정자 사용자(A) · 재발 방지 커밋 `1676c57`(`--help`·`--version` 처리)

## 배경

2026-10-15 12:15~12:17, S19 3차 감사 에이전트가 개발 빌드(`afa1e2f` 작업 트리)를 사용자의 실제 HOME 으로 `rbms-player --help` 실행했다. 그때 앱은 이 인자를 처리하지 않아 정상으로 시작했고, 시작할 때의 기록 동기화([기록 동기화 ADR](2026-10-14-adr-record-sync.md))가 사용자 계정으로 운영 서버에 판 49개를 보냈다. 모두 수락됐고, 리플레이는 6개를 올리고 43개는 대기로 남았다. 옛 세대 2 SCRATCH AUTO 37판은 설계대로 보내지 않았다. 같은 실행이 `settings.ron` 을 다시 쓰고, 곡 DB 를 전체 재스캔하고(당시 `PARSER_VERSION` 4), 기록 DB 에 `ir_sync` 행을 적고, 사용자 폴더 사본을 갱신했다(`docs/history/2026-10-15-process-archive.md` 의 S19 사고 기록).

## 결정

1. 운영 서버의 49개 기록은 그대로 둔다. 지우지 않는다.
2. 기록 DB 의 `ir_sync` 행과 대기 중인 리플레이 43개도 그대로 둔다. 리플레이는 다음 실행의 기록 동기화가 올린다.

## 이유

- 사용자 판단: 나중에 테스트할 때 참조할 수 있다.
- 49개는 사용자가 실제로 친 판이고, 언젠가 기록 동기화가 보낼 판이었다. 서버는 같은 판을 멱등으로 받으므로 다음 정상 실행이 중복을 만들지 않는다.

## 기각된 대안

| 대안 | 기각 이유 |
| --- | --- |
| 운영 DB 에서 49개를 지운다(B) | 사용자가 A 를 택함. 지우는 일은 파괴적 운영 작업이다([운영 DB 작업 ADR](2026-10-14-adr-production-db-operations.md)) |

## 영향과 관련 파일

- 재발 방지 1: 모든 에이전트 지시에 "rbms-player 는 scratch HOME 과 닿지 않는 서버(`--server http://127.0.0.1:9`)로만 실행"을 넣는다(세션 작업 규칙. 저장소 문서에는 `docs/reference/frame-cost.md` 의 측정 조건으로만 남아 있다).
- 재발 방지 2: 앱이 명령줄을 디스크·네트워크보다 먼저 읽고, `--help`·`-h`·`--version` 과 받아들이지 않는 명령줄은 앱을 시작하지 않고 끝난다. 설정·DB·스킨·서버를 건드리지 않는다(`apps/rbms-player/src/command_line.rs` 모듈 문서, 테스트 `command_line/tests.rs`, `main_tests.rs`).
- 사용자 확인 남음: 개발 빌드가 다시 쓴 설정이 의도대로인지 v0.1.4 를 실행할 때 확인한다(결정이 아니라 사용자 실기 확인 항목).
