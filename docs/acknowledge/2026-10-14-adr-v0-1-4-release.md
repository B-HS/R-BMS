# ADR: v0.1.3 draft 는 두고 다음 릴리스는 S19 고도화까지 넣은 v0.1.4 로 낸다

> 최종 갱신 2026-10-15 · 대응 커밋 ea698a9
> 상태: 유효(게시 2026-10-15T07:27:28Z) · 결정일 2026-10-14 · 결정자 사용자(S18 결정 3·4, S19 결정 5 의 B) · 커밋 `87eacd0 release: v0.1.4`(릴리스 run 38696475211)

## 배경

`v0.1.3` draft(버전 커밋 `fb29d24`, run 38563811699)는 사용자가 한 판 쳐서 `IR: RANK` 를 확인한 뒤 게시할 예정이었다(`docs/history/2026-10-15-process-archive.md` 의 S16). 그 사이에 점수 제출 400(空POOR, [판정 수 ADR](2026-10-14-adr-judge-count-consumed-notes.md))이 드러났고, S18 에서 클라이언트 기능(기록 동기화, Esc 포기 판 저장, IR 오류 필드 표시)이 더해졌다. 첫 릴리스의 `v0.1.0` draft 도 게시되지 않은 채 남아 있었다. 그때까지는 잘못 만든 draft 를 지우고 다음 patch 로 갔다([릴리스 정책 ADR](2026-10-14-adr-release-policy.md) 결정 6). 이어 S19 고도화를 이번 릴리스에 넣을지도 물었다.

## 결정

1. `v0.1.3` draft 는 지우지 않고 둔다. 다음 릴리스는 `v0.1.4` 다(S18 결정 3).
2. `v0.1.0` draft 도 둔다(S18 결정 4).
3. `v0.1.4` 는 S18(기록 동기화, Esc 포기 판, 판정 수 검사) 뒤에 바로 내지 않고 S19 고도화(감사·수리, 판정 의미 9건, 키 입력 시각, 디바운스)까지 넣어 한 번에 낸다(S19 결정 5 의 B).
4. 게시는 사용자가 한다(릴리스 정책 그대로). 메인은 draft 를 만들고 산출물과 본문을 확인한다.

## 이유

- 사용자 판단. 지울 필요 없이 다음 번호로 내면 된다.
- 고칠 것이 쌓인 상태에서 두 번 내지 않고, 실기 확인을 한 번에 하게 한다.
