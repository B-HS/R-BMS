## 동영상 디코더 (D5 의 후속, 2026-10-11 메인 선정)

- 선택: `openh264`(Cisco OpenH264 소스 동봉 정적 빌드, BSD-2-Clause) + `re_mp4`(mp4 디먹서, MIT). 새 크레이트 `crates/rbms-video` 에 디코더 트레이트 뒤로 격리하고 cargo 피처로 켜고 끈다.
- 근거: `docs/reference/skin-compat/v2-video-decoder.md`. 런타임 의존 없음(README 의 단일 바이너리 원칙 유지), CI 필수 설치 단계 없음, safe API, GPL-3.0-or-later 호환, 대상 mp4 8개(H.264 High·CABAC·B 프레임)가 지원 범위.
- 기각: FFmpeg 정적 링크(3개 OS 정적 빌드 절차·libclang·CI 시간, BGA 형식 전반이 필요해지면 재검토), FFmpeg 시스템 링크·사이드카·GStreamer(최종 사용자 설치 필요), OS 기본 디코더(FFI 에 `unsafe` 필요, OS 별 3벌), 순수 Rust H.264(공개 6개월 이내, High 프로파일 일부 미지원), symphonia isomp4(영상 샘플을 주지 않음).
- 한계: H.264 전용(mpg·wmv·avi·webm BGA 는 덮지 못함), 인터레이스 미지원, 단일 스레드 디코드.
- 사용자에게 고지한 사실: Cisco FAQ 상 소스에서 빌드한 OpenH264 는 Cisco 의 MPEG LA 특허 비용 부담 대상이 아니다. 사용자는 릴리스 바이너리에 동영상 기능이 필요하다고 답했다(D10). 배포물에는 OpenH264 의 BSD-2 고지를 동봉한다.
