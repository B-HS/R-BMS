## 운영 전제

- KEK(`AI_CREDENTIAL_KEKS`, `AI_CREDENTIAL_KEK_CURRENT`)는 사용자가 Vercel 환경변수(Sensitive)로 넣는다. 에이전트는 값을 만들거나 보지 않는다. 없으면 AI 경로만 503.
- 관리자 지정(`hs@gumyo.net`)은 운영 DB 쓰기다. 사용자 지시(2026-10-19)를 승인으로 보고, 대상 행 수(1이어야 함)를 먼저 확인해 보고한 뒤 한 행만 바꾼다.
- 곡별 패턴 업로드: 사용자가 `bhs`(hs@gumyo.net) 계정의 API 토큰을 macOS 키체인(계정 `rbms-admin`, 서비스 `rbms-pattern-upload`, 2026-10-19 13:17:32 UTC 저장)에 넣었다. 업로드 스크립트가 실행 중에 `security find-generic-password -w` 로 직접 읽어 Authorization 헤더에만 쓰고, 값을 출력·로그·파일·대화에 남기지 않는다. 사용자가 에이전트의 직접 업로드를 요청했다(2026-10-19 "너가 직접 업로드하는건 ?"). 토큰은 관리자 지정 뒤부터 관리자 경로에 유효하다.

## 구현 중 메인 결정(2026-10-20, W2·W4 작업자 질문)

사용자가 외출 중 "쭉 진행"을 지시해 메인이 정했다. 판정·점수 의미와 저장 규칙은 바꾸지 않는 선택만 했다. 사용자가 돌아오면 함께 보고한다.

| 질문 | 결정 | 이유 |
| --- | --- | --- |
| 경계 레벨 정의(W2) | 클리어 비율 0.5 이상인 가장 높은 레벨의 다음 | 안 친 낮은 레벨이 경계를 끌어내리지 않는다 |
| 판정 습관 AI 오프셋 방향(W2) | 서버 결정론 결론으로 덮어쓰고 AI 는 설명만 | 숫자는 결정론에서만(기획 7.6) |
| 같은 미리보기로 폴더 다시 만들기(W2) | 같은 폴더의 곡만 바꾸고 사용자가 고친 이름·설명은 유지 | 사용자 편집 보존 |
| 주간 요약의 램프 갱신(W2) | 그 주 전 최고보다 오른 클리어 램프만, FAILED 첫 판은 "처음 친 곡" | 갱신의 뜻이 분명하다 |
| trace 계약 파일 커밋 순서(W4) | 웹 trace 경로와 같은 커밋 | web CI 계약 테스트가 깨지지 않게 |
| 9키 trace 일관성 검사(W4) | 9키는 BAD·POOR 를 검사에서 뺀다 | 서버 `judgedNoteCount` 의 9키 BAD 예외와 같은 방향, 엔진 판정 로직 불변 |
| 로컬 trace 보관 상한(W4) | 지금대로(지우지 않음), 크기는 테스트 부채로 관찰 | 판 데이터를 버리지 않는다는 사용자 원칙 |
| NETWORK 설정 화면 묶음(W4) | SETTINGS SYNC 세 줄을 SERVER AND ACCOUNT 끝으로 옮긴 배치 유지 | 행 수 한도 안에서 가장 작은 변경 |
| trace 보관 상한을 세는 바이트(W4 웹) | 압축 전 JSON 바이트 합(byte_size), 관리자 화면에 저장 바이트(stored_size)를 함께 | 기획의 크기 계산·리플레이 한도와 같은 방식 |
| "다가가면 알림" 기준(W4 웹) | 판 수·바이트 중 하나라도 90% 이상이면 near | 추천안 |
| play_analysis 일괄 재계산 관리자 경로(W4 웹) | ANALYSIS_VERSION 을 처음 올리는 작업과 함께 만든다. 지금은 읽을 때 다시 계산 | 쓰이지 않는 경로를 미리 만들지 않는다 |
| 패턴 읽기 허용 목록에 compose/trace.ts(W4 웹) | 받아들인다. 라우트·화면에서 배치를 읽지 않는다는 검사는 그대로 | 서버 내부 분석만 읽는다 |
| speed.changes·tempo 상한 4,096 과 앞·뒤 절반 보존(W4 클라이언트) | 그대로, 서버는 변경을 다시 재생해 end 를 검사하지 않는다 | trace 를 skipped 로 만들지 않는다 |
| 점수를 trace 저장 전에 받은 판(테스트 부채 3.81) | 부채로 두고 보고가 있을 때 처리 | 다음 동기화가 다시 보낸다 |
| 9키 BAD 를 trace 에 따로 담기(W4 클라이언트) | 하지 않음(형식 v1 유지, 서버가 9키 BAD·POOR 를 검사에서 뺀다) | 형식 세대를 올리지 않는다 |
| 라이벌 구간 공유 범위(W5) | 공유를 켠 사용자와 **서로 라이벌**(양쪽 목록에 서로 있음)인 요청자에게만 구간 집계 차이를 준다. 설정 기본 끔 | 라이벌 등록은 상대 동의 없이 되므로, 한쪽 등록만으로 구간 데이터를 받게 하면 모르는 사람에게 열린다. ADR Q4 "라이벌이 허용했을 때만"을 가장 좁게 해석 |
| trace-normal 의 짝 점수(W5) | 실제 판 경로로 score-trace-normal.json 을 캡처해 테스트의 random 덮어쓰기를 없앤다 | 계약이 편집본이 아니라 캡처본으로 검증되게 |
| 분석 버전 분리(W5) | 판 분석 요약에 곡별 분류 버전(ANALYSIS_VERSION)도 함께 저장하고, 둘 중 하나라도 낮으면 다시 계산 | 사람이 둘을 함께 올리는 것을 기억하지 않아도 되게 |
| 비교 방식(W5) | 32구간 집계 비교 | 라이벌 허용 범위와 같은 단위 |
| 소급 trace 의 속도 옵션(W6) | 라이브와 같은 유효 커버·리프트(ENABLE COVER/LIFT 반영)로 시작값=끝값, 변경 이력은 비움 | 리플레이에 속도 이력이 없다. 라이브 trace 와 같은 뜻의 값만 싣는다 |
| 차트 없음·리플레이 못 읽음(W6) | 끝난 것으로 표시하지 않고 라이브러리가 바뀌거나 다음 실행에서 다시 본다 | SSD 가 자주 빠진다(HANDOFF 7절). 일시 실패로 판 데이터를 영구히 놓치지 않게 |
| 코스 스테이지 판의 소급(W6) | 하지 않는다 | 리플레이에 코스 게이지·이월 값이 없어 같은 판을 재현할 수 없다 |
