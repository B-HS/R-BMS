## 요약

U4를 끝냈습니다. 선곡 목록 막대, MY RECORDS 줄, 랭킹 줄의 램프가 이제 어시스트 등급 색(theme.assist_grade = theme.grade_lamp, 새 색 없음)으로 그려집니다.

(1) 렌더
- `SongBar` 에 `assist_grade: u8`(0~4)를 더했습니다.
- songlist 에 R-BMS 확장 키 `lamp_graded`(등급 1~4 그림 4개)를 더했습니다. 기존 확장 키 `rank`·`thumb` 와 같은 경로입니다(model `SongList`, loader `SongListTracks`·build_slots, `branch.rs` 의 NESTED_ARRAY_FIELDS, from_lua·script 두 walk, render build).
- 램프 id 가 3 이고 등급이 1 이상이며 그 등급의 그림이 있으면, 기존 lamp 패스 안에서 `lamp` 항목 대신 그 그림을 그립니다. 새 패스는 없고 prepare 는 rank 다음 맨 끝입니다. 라이벌 모드(playerlamp)는 바꾸지 않았습니다.

(2) 플레이어
- `wheel_bar`(scene.rs)가 `SelectBar.assist_grade` 를 넘깁니다.

(3) MY RECORDS·랭킹 줄
- 스킨이 받는 값에 등급이 없어서 확장 숫자 id 를 더했습니다. 21087~21092 는 `MY_RECORD_ASSIST_GRADE_FIRST`(기록 6줄, Select 클러스터, BrowseFacts·RecordRow)이고, 21093~21102 는 `RANKING_ASSIST_GRADE_FIRST`(랭킹 10칸, Ir 클러스터, IrScore.assist_grade 를 RankingRow.record_lamp 에서 채움)입니다.
- 결과 화면 링크에서는 랭킹 칸처럼 INTEGER_ABSENT 를 돌려줍니다.
- 기본 스킨 `records.lua` 는 lamp_strip 셀 위에 등급 색 블록을 덮습니다. 기록 줄은 lamp==3 이고 grade==g 일 때 그리고, 랭킹 줄은 image index 390+row==3 이고 grade==g 일 때 그립니다.
- `list.lua` 는 `lamp_graded = graded_lamps(s)`(theme.assist_grade[1..4].color 의 block)를 냅니다. `props.lua` 에 두 이름을 더했습니다.

폴더 분포 그래프, 스크롤 분포, 내장 선곡 LED 는 건드리지 않았습니다. 외부 스킨(키 없음)이 화소 하나까지 같다는 회귀 시험이 있습니다.

## 결정한 것

- 등급 그림은 lamp 패스 안에서 lamp 항목을 대신합니다(새 패스 없음). 그래서 키가 없는 문서는 그리는 순서와 묻는 순서가 전과 같습니다. prepare 는 rank 다음 맨 끝입니다.
- 라이벌 모드(list.rival)에서는 playerlamp 의 위치가 따로라서 lamp_graded 로 대신하지 않습니다(시험으로 고정).
- graded_lamp_index 는 막대 종류를 보지 않고 램프 id 3 과 등급만 봅니다. 플레이어는 차트 막대에만 등급을 채웁니다.
- MY RECORDS 등급: RecordRow::of 에 assist_grade 인자를 더했습니다. 최고 기록 줄은 BestScore.assist_grade, 최근 판은 PlayLog::assist_grade() 를 씁니다.
- 스킨에서는 등급 블록을 램프 칸 위에 덮어 그립니다. 그리는 조건에 램프==3 확인도 넣어, 등급 값이 잘못 와도 다른 램프를 덮지 않게 했습니다.
- 확장 숫자 id: MY_RECORD_ASSIST_GRADE 21087~21092, RANKING_ASSIST_GRADE 21093~21102 (RANKING_GRADE_SLOTS 는 ir::RANKING_SLOTS 에서 유도).

## 계획과 달라진 점

- 확장 숫자 id 범위를 넘었습니다. 지시는 21087~21099(13개)였지만 기록 6줄과 랭킹 10칸에 16개가 필요해서 랭킹 run 이 21100~21102 까지 갑니다. 정수 공간의 확장 대역은 21000~21199(EXTENSION_VALUE_LAST)라서 게이트·정의상 맞고, 불린 21100 대와는 공간이 달라 충돌하지 않습니다. 21085·21086(U6)과도 겹치지 않습니다. 범위 안에 두려면 랭킹 칸을 7칸으로 줄이는 수밖에 없어서 택하지 않았습니다. 메인 확인이 필요합니다.
- 소유 밖 파일 crates/rbms-render/src/skin_render/textures.rs 에 `name_all(&mut named, &list.lamp_graded);` 한 줄을 더했습니다. 이 줄이 없으면 lamp_graded 만 쓰는 소스 이미지가 로드 대상에서 빠집니다. rank 를 더한 방식과 같습니다.
- 확장 id 를 더하느라 계획의 U4 소유 목록 밖(U6 소유 영역이지만 웨이브 2)인 파일을 고쳤습니다: apps/rbms-player/src/skin_host/{extension.rs, ir.rs, mod.rs(라우트 2줄·import), select/browse.rs, tests.rs, ir/tests.rs, select/tests.rs, select/browse/tests.rs}, apps/rbms-player/src/stage/select/{browse_facts.rs, bars_tests.rs}, assets/skins/rbms-default/lua/props.lua. U6 가 병합할 때 skin_host/tests.rs 의 props 이름 표 길이(31→33)와 extension.rs 의 NUMBER_RUNS(7→9)가 겹칠 수 있습니다.
- rbms-skin 통합 시험(tests/skin_from_lua.rs, tests/skin_luaskin.rs)의 songlist 필드 목록에 lamp_graded 를 더했습니다.

## 남은 위험

- 실제 창이나 캡처로 막대와 기록 줄의 등급 색을 눈으로 보지 않았습니다. skin-dump 의 select 시나리오(apps/rbms-cli/scenarios/select.json)에는 램프 3 이나 등급 값이 없어서, 덤프는 등급 블록이 실제로 그려지는 경로를 지나지 않았습니다. 시나리오 파일은 소유 밖이라 고치지 않았습니다.
- 랭킹 줄의 등급은 서버 응답의 assist_grade 에 기댑니다. 구 서버가 0 을 보내면 LIGHT ASSIST 색으로 남습니다.
- 랭킹 run 이 21100~21102 로 넘어간 것은 메인의 범위 지시와 다릅니다(deviations 참고).
- U6(웨이브 2)와 같은 파일을 고쳤습니다: skin_host/extension.rs, skin_host/tests.rs 의 props 이름 표, props.lua. 병합할 때 배열 길이 상수가 겹칠 수 있습니다.
- list.lua·records.lua 는 U8(선곡 화면 개편)도 고칩니다. graded_lamps 블록이 U8 개편에서 위치를 따라가는지 U8 쪽 확인이 필요합니다.
