## 요약

U2 FULLSCREEN 구현을 마쳤습니다. WINDOW MODE 행에 독점 전체 화면을 셋째 값으로 넣었고, 이 Mac 에서 모든 전환을 실제로 실행해 확인했습니다.

1. `WindowMode::Fullscreen` 을 추가했습니다(토큰·라벨 `FULLSCREEN`). 행 순서는 WINDOWED → BORDERLESS → FULLSCREEN 이고 `WINDOW_MODE_COUNT = 3`, `WINDOW_MODE_LABELS` 도 셋입니다. 두 전체 화면 모드를 함께 판정하는 `WindowMode::covers_the_monitor()` 를 더했고, `DisplayOptions::fits_screen_shape()` 는 이 함수를 써서 FULLSCREEN 에서도 비율을 지킵니다.
2. 모드 고르기는 순수 함수 `nearest_video_mode(&[(w, h, mHz, depth)], wanted) -> Option<usize>` 입니다. 크기가 같은 모드를 먼저 고르고, 없으면 가로·세로 차이의 합이 가장 작은 모드를 고릅니다. 같은 거리면 큰 쪽, 같은 크기 안에서는 주사율이 높은 쪽, 그다음 색 깊이가 큰 쪽입니다. 고른 모드는 창이 있는 모니터(없으면 주 모니터)의 `video_modes()` 에서 가져와 `Fullscreen::Exclusive` 로 넘깁니다.
3. 독점 모드를 얻을 수 없으면 BORDERLESS 로 떨어집니다. 해당 경우는 Wayland(창 핸들의 `RawWindowHandle::Wayland` 로 판별), 모니터 없음, 모드 목록이 빈 경우입니다. 이때 세 언어 알림 `NoticeText::FullscreenFellBackToBorderless` 를 내고, 원인은 stderr 에 영어로 남깁니다. 설정값은 FULLSCREEN 으로 남으므로 매 프레임 다시 시도하지 않고 행이 바뀔 때만 다시 시도합니다.
4. 전환표(`changes`)는 아홉 쌍 전부를 다룹니다. FULLSCREEN 중에 RESOLUTION 을 바꾸면 그 크기의 모드로 바로 바꿉니다. BORDERLESS → FULLSCREEN 은 먼저 일반 창으로 나간 뒤 독점 모드로 들어갑니다(아래 deviations 참고).
5. 설정 화면 문구를 세 언어로 맞췄습니다. WINDOW MODE 설명에 FULLSCREEN 과 "macOS 의 BORDERLESS 는 시스템 전체 화면이고 Game Mode 가 동작함" 을 넣었고, RESOLUTION 은 FULLSCREEN 이 요청하는 모드라는 설명을, LETTERBOX 는 BORDERLESS·FULLSCREEN 이 항상 비율을 지킨다는 설명을 갖습니다. rbms-config 의 영어 행 설명 3개도 같이 고쳤습니다. 설정 행 수는 그대로입니다.
6. 이 Mac(내장 Liquid Retina XDR, 기본 2624x1696@120)에서 스크래치 HOME 과 `--server http://127.0.0.1:9` 로 실행했습니다. 화면 모드는 CoreGraphics 로, 창 위치·크기는 System Events 로 읽었습니다. 이 모니터가 보고하는 가장 작은 모드는 1920x1200 입니다.
   - 시작 시: WINDOWED 는 1280x752 창(제목 막대 포함), BORDERLESS 는 0,49 위치의 2624x1647 창, FULLSCREEN 은 RESOLUTION 1920x1080 에서 1920x1200@120 모드로 열렸고 창은 0,0 의 1920x1200 이며 16:9 레터박스로 그려졌습니다.
   - 실행 중 전환: W→B, B→F(1920x1200@120 모드, 창 0,0), FULLSCREEN 중 RESOLUTION 을 2560x1440 으로 바꿈(2560x1600@120, 창 0,0), F→B(원래 모드 2624x1696 으로 복귀), B→W(2560x1472 창), W→F 직접(2560x1600), F→W, W→B→F 를 0.4초 간격으로 연속 전환. 모두 창이 화면에 맞게 놓였고 패닉은 없었습니다.
   - FULLSCREEN 상태에서 프로세스를 강제로 끝내도 원래 모드 2624x1696@120 으로 돌아왔습니다.

## 결정한 것

- FULLSCREEN 은 창을 BORDERLESS 가 아니라 일반 창으로 연 뒤, 첫 sync 에서 독점 모드로 들어갑니다(`opening_rows` 가 Fullscreen 을 Windowed 로 바꿈). 실측 근거는 deviations 에 적었습니다.
- BORDERLESS → FULLSCREEN 은 `[LeaveFullScreen, EnterExclusive]` 두 단계로 갑니다. 모든 OS 에 같은 표를 써서 시험을 단순하게 했고, Windows·X11 에서는 한 번 깜빡일 수 있습니다.
- 가장 가까운 모드의 기준은 |Δw|+|Δh| 가 가장 작은 것이고, 동률이면 큰 면적, 주사율, 색 깊이 순입니다. 화면 비율은 보지 않습니다(LETTERBOX 가 맞춤).
- 모드 크기는 RESOLUTION 값을 물리 화소로 그대로 씁니다. macOS winit 의 `video_modes()` 는 HiDPI 가 아닌 픽셀 크기를 줍니다(CGDisplayModeGetPixelWidth, 옵션 null).
- 알림 문구에는 자리표시자를 두지 않았습니다. 원인 문자열은 영어 내부 정보라 stderr 에만 남깁니다(notices.rs 머리말 규칙).
- FULLSCREEN 을 얻지 못해 BORDERLESS 로 떨어져도 설정값은 FULLSCREEN 으로 둡니다. RESOLUTION 이나 WINDOW MODE 가 바뀔 때만 다시 시도합니다.
- `WindowChange::LeaveBorderless` 의 이름을 `LeaveFullScreen` 으로 바꿨습니다(소유 파일 안). 두 전체 화면 모드에서 나가는 단계를 함께 뜻합니다.

## 계획과 달라진 점

- 계획 주의사항('깜빡임을 줄이려면 BORDERLESS 로 열고 전환')과 다르게 FULLSCREEN 은 일반 창으로 엽니다. 이 Mac 에서 BORDERLESS 로 연 창을 Exclusive 로 바꾸면 화면 모드는 1920x1200 으로 바뀌지만, 창이 옛 모드의 틀에 남아 y=-496 에 걸리고 화면 아래 절반이 검게 남았습니다(winit macOS 의 (Borderless, Exclusive) 분기는 창 레벨만 바꿉니다). 일반 창에서 들어가면 0,0 에 1920x1200 으로 정확히 놓였습니다.
- 같은 이유로 BORDERLESS→FULLSCREEN 전환도 일반 창을 거칩니다. 계획 U2-3 의 전환표 내용 중 B→F 한 행이 두 단계가 되었습니다.
- 병합 주의 파일 중 `crates/rbms-config/src/{schema.rs,settings.rs,tests.rs}`, `apps/rbms-player/src/text/settings/descriptions.rs`, `apps/rbms-player/src/text/notices.rs` 에서 창 관련 줄과 알림 항목·골든 행 하나만 고쳤습니다. `lib.rs` 는 고치지 않았습니다(창 생성·동기화 호출부는 그대로 맞습니다).

## 남은 위험

- Windows·X11 의 독점 전환과 Wayland·모드 없음의 BORDERLESS 폴백은 실기로 확인하지 못했습니다. 3 OS CI 와 실기 점검이 필요합니다.
- winit 0.30.13 macOS 는 `video_modes()` 에서 모르는 픽셀 인코딩을 만나면 `unimplemented!()` 를 내고, `CGDisplayCapture`·`CGDisplaySetDisplayMode` 가 실패하면 assert 로 패닉합니다. 이 Mac 에서는 일어나지 않았지만 다른 디스플레이에서는 코드로 막을 수 없습니다.
- macOS 독점 전체 화면에서 Game Mode 가 켜지는지는 확인하지 못했습니다(계획 위험 항목과 같음). 문구에는 BORDERLESS 를 Game Mode 경로로 적었습니다.
- Windows 에서는 FULLSCREEN 으로 시작할 때 일반 창이 한 프레임 보였다가 전환되고, BORDERLESS→FULLSCREEN 에서도 한 번 깜빡일 수 있습니다.
- 알림과 설정 설명의 한국어·일본어 문구를 새로 썼습니다('화면 모드/画面モード', '주사율/リフレッシュレート' 는 용어집에 없는 말입니다). 용어집에 올릴지 메인이 검토해야 합니다.
- 실기에서 사용자의 디스플레이 모드를 잠시 바꿨지만 끝난 뒤 원래 모드(2624x1696@120)로 돌아온 것을 확인했습니다. 첫 두 장의 전체 화면 캡처에는 다른 앱 화면이 담겨서 바로 지웠고, 나머지는 창 영역만 캡처했습니다.
