## 요약

U9(M19)을 구현했습니다. 이제 사용자 오프셋은 스킨 문서 단위 그대로 읽힙니다. `DocumentOffsets::offset` 은 `stored.offset(id)` 를 그대로 돌려주고, 길이(x·y·w·h)·각도·알파·OFFSET_ALL 모두 저장값 그대로입니다. OFFSET_ALL 과 각도·알파는 원래도 환산하지 않았으므로 동작이 같습니다. 바뀐 것은 길이 성분뿐이고, 그동안 곱하던 `authored/target` 환산을 없앴습니다. 그래서 `units_per_pixel`, `ONE_TO_ONE`·`UNSCALED` 상수, 손으로 쓴 `Default` impl, `drawn_at(document, authored, target)` 을 지우고 `DocumentOffsets::new(document)` 와 `#[derive(Default)]` 로 바꿨습니다. `AppShared::skin_offsets(screen, target)` 는 `skin_offsets(screen)` 이 되었고, 호출부 6곳(play·select·result·decide·keyconfig·skin preview)을 정리했습니다. 쓰이지 않게 된 `OFFSET_ALL` import 도 지웠습니다. 문서 주석은 영어로 새 규칙과 이유를 다시 썼습니다. 이유는 창 크기·해상도·배율과 무관하게 같은 자리에 놓이고, 1280x720 문서는 자기 단위로 읽으며, 레퍼런스를 스킨 제작 해상도로 실행했을 때와 같은 결과가 나온다는 것입니다. skin_screen/preview.rs 모듈 문서의 "nudge 는 창 화소" 설명도 고쳤습니다.

이 환산에 기대던 다른 코드는 없었습니다. SKIN MENU·PLAY MENU 의 오프셋 행 숫자는 저장값을 그대로 보이고, 스킨 미리보기는 문서를 사각형에 맞춰 축척하므로 오프셋도 함께 축척됩니다. 오프셋 단위를 말하는 문구는 OffsetPlaceHelp·AutomaticPlaceHelp 두 개였고, 세 언어 모두 "skin pixels / 스킨 좌표의 픽셀 / スキン座標のピクセル" 로 고쳤습니다(스킨 lua i18n 에는 해당 문구가 없었습니다).

시험:
- `the_default_pack_moves_its_judgement_by_its_position_and_hides_it_when_told_to`: 기대 이동량을 `JUDGEMENT_MOVED_BY * HELD_SIZE.1 / 문서 높이` 로 바꿨습니다(960x540 에서 100 → 50 화소).
- `skin_screen/tests.rs` 의 화면 화소 기준 시험: `a_nudge_is_answered_in_the_documents_own_units` 로 바꿨습니다.
- `judge_sizes.rs`: `Stance`(Plain·Lifted·Raised)와 시험 `the_default_pack_raises_its_judgement_by_the_same_document_pixels_at_every_size` 를 더했습니다. 크기 목록은 늘리지 않았습니다.
- 외부 스킨: `stage/play/tests.rs` 에 `a_nudge_is_read_in_the_units_of_a_document_laid_out_at_another_size` 를 더했습니다. 1280x720 문서를 1920x1080 대상에 그리면 nudge 50 이 75 대상 화소만큼 움직이고, 예전 규칙의 50 화소 자리에는 그려지지 않는지 봅니다.

JUDGE POSITION y=30 측정표(판정 글자 잉크 중심 y, 문서 화소. 오프셋 0 일 때 1280x720 646.07, 1920x1080 646.19, 2560x1440 646.24, 1728x972 646.13, 1728x1117(늘림) 646.18):
- 고치기 전: 1280x720 601.07(45.00 위), 1920x1080 616.19(30.00), 2560x1440 623.74(22.50), 1728x972 612.80(33.33), 1728x1117 617.17(29.01)
- 고친 뒤: 616.07, 616.19, 616.24, 616.13, 616.18, 모두 30.00 위
- 판정선은 모든 경우 907.4~907.8 로 그대로입니다.

고치기 전 수치는 새 시험을 수정 전 코드로 돌려 쟀습니다. 첫 비교인 1280x720 에서 "15.12 document pixels" 로 실패했고, 모든 크기를 먼저 그린 뒤 단언하므로 표 전체가 출력됐습니다.

## 결정한 것

- 오프셋 한 점 전체(x·y·w·h·r·a)와 OFFSET_ALL 을 저장값 그대로 돌려줍니다. 전에도 각도·알파·OFFSET_ALL 은 그대로였으므로 분기가 필요 없어 `offset` 을 한 줄로 줄였습니다.
- `drawn_at` 은 인자가 document 하나만 남아 이름이 뜻과 맞지 않아 `DocumentOffsets::new` 로 바꿨습니다(같은 파일의 `FrameInputs::new` 관례를 따름).
- judge_sizes 의 JUDGE POSITION 변형은 크기마다 오프셋 0 판을 새로 그리지 않습니다. 오프셋 0 기준 판(1920x1080)의 판정 위 부분(글자·콤보·차이·타이밍)만 30 문서 화소 올린 값과 비교합니다(`raised_by`). 판정선은 움직이지 않습니다. 기준 크기도 비교에 넣어 '정확히 30' 을 직접 확인합니다. 그림은 6장이고 허용치는 기존 `assert_alike` 를 그대로 씁니다.
- judge_sizes 의 `judged_at` 에 시험 이름 인자를 더해 폴더 태그를 시험마다 나눴습니다. 전에는 plain·lifted 두 시험이 같은 `judge-sizes-plain-1920x1080` 폴더를 동시에 지우고 썼고, 시험 3개가 겹친 첫 실행에서 'score database ... database is locked' 출력을 실제로 봤습니다.
- 문구는 뜻이 틀리지 않게만 'pixels' 를 'skin pixels / 스킨 좌표의 픽셀 / スキン座標のピクセル' 로 고쳤습니다. 도움말 폭 시험 두 개가 그대로 통과합니다.
- 외부 스킨 규칙의 시험은 DocumentOffsets 가 더는 크기를 받지 않아 단위 수준에서는 의미가 없습니다. 그래서 1280x720 문서를 1920x1080 대상에 실제로 그리는 기존 고정물(`stage/play/tests.rs` 의 play_document) 시험으로 고정했습니다.

## 남은 위험

- 저장값의 뜻이 바뀝니다(M19). 1920x1080 물리 화소가 아닌 화면(예: 1280x720 창, 4K, Retina)에서 맞춘 오프셋은 이번 변경 뒤 한 번 다시 맞춰야 합니다. 이전 저장값을 옮기는 코드는 넣지 않았습니다(계획대로).
- 외부(beatoraja) 스킨의 오프셋 저장값은 레퍼런스에서는 출력 화소였습니다. 그 스킨을 레퍼런스에서 제작 해상도와 다른 크기로 쓰며 맞춘 값을 옮겨 오면 결과가 다를 수 있습니다. 문서 주석에 적은 대로 '제작 해상도로 실행한 레퍼런스' 와 같아지는 쪽을 택했습니다.
- 실제 창(GPU, Retina 배율)에서 JUDGE POSITION 을 움직여 보는 실기 확인은 하지 않았습니다. 헤드리스 CPU 캔버스 측정과 시험만 했습니다.
- 워크스페이스 전체 시험과 설정 계약 시험은 돌리지 않았습니다(메인 병합 뒤 게이트).
