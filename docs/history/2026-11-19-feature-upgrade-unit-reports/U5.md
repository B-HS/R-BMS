## 결정한 것

- 원인 코드(`apps/rbms-player/src/skin_screen.rs` 의 DocumentOffsets)는 소유 밖이고, 오프셋 단위는 레퍼런스 호환·기존 시험·설계 문서가 걸린 정책 결정이라 고치지 않고 보고했다(계획 4절, 공통 규칙).
- 텍스트 장치 화소 맞춤은 ADR 2026-10-22 가 받아들인 절충(O5)이라 바꾸지 않았다.
- 새 시험은 앱 전체 경로(FieldRun, 기본 팩, 헤드리스 CPU)를 쓰는 기존 하니스 `stage/capture/play_parts.rs` 의 자식 모듈로 두었다. 오프셋 환산과 텍스트 장치 화소 경로까지 실제로 거치는 곳이 거기뿐이다.
- 허용치: 이미지 부위는 0.5 문서 화소 또는 그 프레임의 반 장치 화소 중 큰 값. 렌더러가 GPU 와 같은 픽셀 중심 샘플링이라 720p 에서는 반 장치 화소가 0.75 문서 화소이고, 계획의 0.5 문서 화소는 물리적으로 지킬 수 없다(LIFT 를 켠 720p 에서 실측 0.54).
- Judge Position 오프셋 변형은 지금 해상도마다 달라서 시험의 단정에 넣지 않았다. 측정값만 보고에 적었다.

## 계획과 달라진 점

- 소유 파일 밖인 `apps/rbms-player/src/stage/capture/play_parts.rs` 에 `mod judge_sizes;` 한 줄을 넣었다. 새 시험 파일을 등록하는 데만 필요한 줄이다.
- 원인 1 의 수정 지점 `apps/rbms-player/src/skin_screen.rs:266-279`(DocumentOffsets::drawn_at/offset)은 소유 밖이라 고치지 않았다. 확인 실험으로 잠시 바꿨다가 백업에서 되돌렸다. git status 에 변경이 없다.
- 계획 U5 의 완료 기준 '고치기 전·후 측정표'는 '고치기 전' 표와 원인 1 의 확인 실험(문서 단위 환산) 결과로 대신한다. 실제 수정은 사용자 결정 뒤로 미뤘다.
- 계획의 '0.5 문서 화소 안' 기준을 'max(0.5 문서 화소, 그 프레임의 반 장치 화소)'로 바꿔 시험했다. 텍스트(FAST/SLOW)는 ADR 에 따라 한 장치 화소로 잡았다.

## 남은 위험

- 원인 1 은 고치지 않았다. 사용자가 판정 위치 오프셋을 0 이 아닌 값으로 두면, 해상도와 Retina 배율에 따라 판정 위치가 최대 3배까지 다르게 보이는 문제가 그대로 남는다.
- 사용자 설정이 오프셋 0 이라면 보고한 현상은 원인 2(FAST/SLOW 의 1~1.5 문서 화소 흔들림, 비 16:9 에서 글자 폭 변화) 정도라서 '살짝'과는 맞을 수 있지만 확정하지 못했다. 사용자의 실제 설정과 화면은 보지 않았다.
- 새 시험은 기본 팩을 10번 불러 3840x2160 까지 CPU 로 그리므로 디버그 빌드에서 약 35 s 걸린다. CI 3 OS 의 시험 시간이 늘어난다.
- 측정은 헤드리스 CPU 렌더러로만 했다. GPU 도 픽셀 중심 샘플링이라 같은 결과로 보이지만 GPU 로는 재지 않았다.
