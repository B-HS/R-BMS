## 요약

U7 의 할 일 1~6 을 모두 구현했습니다. 계획과 하나 다른 점이 있습니다. 기본 캡처 키를 C 대신 P 로 정했습니다(아래 1번).

1. **기본 캡처 키를 P 로 바꾼 이유**: 결과 화면은 모든 레인 키를 기준 구현의 키 표대로 읽습니다. 기본 C 는 모든 기본 배열에서 5번째 레인 키이고, 결과 화면에서 5번째 키는 "새 배치로 다시 플레이"(확정·페이드)입니다. 기존 시험도 `AFRESH_KEY: KeyCode = KeyCode::KeyC` 로 이것을 고정해 두었습니다. C 를 누르면 캡처와 동시에 결과 화면을 떠나므로, 계획 검토 5항("결과 화면에서 C 를 읽는 코드는 없다")이 틀린 것으로 봤습니다. 대신 P 는 기존 LAYOUT PICK·ReplayPlayLayout 키와 같은 규칙을 지킵니다. 어느 모드의 기본 레인 키도 아니고, 어떤 조작도 읽지 않으며, 결과 화면의 다른 단축키와 겹치지 않습니다. 이 규칙은 시험으로 고정했습니다. C 로 되돌리려면 `keyconfig.rs` 한 줄과 시험·스킨 문구를 함께 고치면 됩니다.

2. **미리보기는 내장 플레이필드를 실시간으로 흘리는 길로 했습니다(`PlaySample` 일반화는 버림)**. 코드를 읽고 판단했고, 줄 수를 실제로 재지는 않았습니다. 버린 이유는 세 가지입니다.
   - `PlaySample` 은 플레이 스킨 화면 전체(게이지 등 포함)를 사각형 안에 축소해 그립니다. 그러면 레인이 사각형 너비의 약 1/4 이 되어 레인 아래 번호를 쓸 수 없습니다.
   - 시계가 앱 전체가 함께 쓰는 스킨 타이머 표(`shared.skin_timers` 의 PLAY 타이머)와 씬 상태입니다. 일시정지·탐색이 없고, 넣으려면 PLAY MENU·SKIN MENU 미리보기 경로를 고쳐야 합니다.
   - 미리 적힌 손이 쳐서 판정이 나오는데, 이 화면에는 필요 없는 정보입니다.

   구현한 미리보기:
   - 새 `layout_pick/clock.rs` 의 `PreviewClock` 이 프레임 dt 로 시간을 셉니다. dt 0 이면 멈춰 있으므로 시험에서 시계를 세울 수 있습니다.
   - 차트를 읽으면 재생 중으로 시작하고, 끝(마지막 타임라인 + 1 s)을 지나면 처음부터 다시 흐릅니다. 배치를 고쳐 써도 흐르던 위치를 유지합니다.
   - 속도는 HI-SPEED 를 그대로 쓰고, 초록 숫자 고정이 켜져 있으면 `BpmStats::held` + `held_speed` 로 계산합니다(`PlaySample::shown_hispeed` 와 같은 식).
   - 레인 커버·히든은 `render_lane_cover` 로, 리프트는 `effective_lift`(필드 생성 설정)로, CONSTANT 도 반영합니다. `PREVIEW_HISPEED` 는 지웠습니다.
   - 조작: Space 재생/정지, Page Up/Down 네 마디, Home 처음, End 마지막 마디, 위/아래·턴테이블·휠 한 마디. 멈춰 있으면 마디 표시 앞에 STOPPED 를 씁니다.

3. **capture 저장소(`captured_layouts.rs`)**
   - 설정 폴더의 `captured_layouts.ron` 에 `#[serde(default)]`, `write_atomic` 으로 씁니다. 읽지 못하면 알리고 빈 목록으로 시작합니다.
   - 항목: md5, 제목+부제, 모드 이름, `random_label`, 시드, 사이드별 레인 순서(`lane_permutation` → `layout_of_permutation` → `layout_row_text`), 저장 시각(ms), EX, 램프 이름(`lamp_label_color` 로 어시스트 등급 반영).
   - 같은 (md5, 옵션, 시드)는 대소문자 무시로 한 번만 저장하고, 새 항목을 맨 앞에 둡니다.

4. **결과 화면 캡처**
   - `Shortcut::CaptureLayout`(`result_capture_layout`, Result 그룹, 패드 가능)를 더해 `ALL` 이 34개가 됐습니다. 키 편집기·키 가이드에는 `Shortcut::ALL` 을 따라 자동으로 나옵니다.
   - 캡처 정보는 판이 끝날 때 `ResultRun::of` 에서 실제 값(`config.play.random`, 빌린 배치 포함, `session.seed()`)으로 만들어 둡니다.
   - 키는 내장 화면, 스킨 씬, 스킨을 읽는 중 모두에서 바로 동작하고 씬을 건드리지 않습니다(페이드가 시작되지 않음).
   - 저장 대상은 RANDOM·R-RANDOM·MIRROR·ROTATE 입니다. ROTATE 는 레인 순열이라 넣었습니다.
   - 거절 사유는 S/H-RANDOM·ALL-SCRATCH, OFF, AUTOPLAY, 리플레이, 코스·연습, LAYOUT PICK 미지원 모드, 판 없음입니다. 성공·중복·거절 알림 모두 세 언어입니다.
   - 스킨 결과 바닥 안내(`i18n/result.lua` `result_hint_chart`)를 "RETRY, NEXT CHART AND CAPTURE LAYOUT … (R, N AND P AS SHIPPED)" 로 바꿨습니다. 기존 안내가 키 이름 대신 기본 키를 정적으로 적는 방식이라 그대로 따랐습니다.

5. **LAYOUT PICK 의 CAPTURED 목록**
   - 필드 오른쪽에 그립니다. 기본은 이 차트의 저장분이고 Tab(목록에서)으로 전체를 봅니다.
   - 입력란과 목록 사이 이동: 키보드는 Right/Left. SELECT(키보드·패드)는 1P → 2P → 목록 → 1P 로 돕니다.
   - 커서가 이 차트 항목에 오면 행 입력란과 미리보기가 그 배치가 되고, 시드 탐색 없이 `SeedLook::Captured` 가 됩니다. START/Enter 는 저장된 옵션 이름과 시드로 `borrow_layout` 을 부르고, 알림 출처는 저장 시각입니다. 행을 고쳐 쓰면 다시 RANDOM 탐색으로 돌아갑니다.
   - Delete 두 번으로 삭제합니다. 첫 누름에 확인 문구가 나오고, 다른 키를 누르면 취소됩니다.
   - 다른 차트 항목에서 Enter 를 누르면 라이브러리에서 md5 로 찾아 그 차트로 옮겨 가고, 없으면 알립니다.
   - 목록에 있을 때 레인 키(패드 포함)는 행을 쓰지 않습니다. 턴테이블과 KEY 1·2 는 커서 이동, KEY 3 은 범위 전환, KEY 4 두 번은 삭제입니다.
   - 안내 줄 세 개(HintTyping, HintCaptured, HintMoving)를 고쳤습니다.

6. 새 문구는 모두 세 언어입니다. 글자를 쓰는 test 하니스로 그린 LAYOUT PICK 화면을 PNG 로 저장해 확인했습니다(목록 2개, 노트가 보이는 상태, 경로는 captures). `notices.rs` 는 고치지 않았습니다. `notify_text` 가 아무 카탈로그나 받으므로 캡처 문구를 소유 파일의 `CaptureText` 에 두었습니다.

## 결정한 것

- 기본 캡처 키는 P(`KeyCode::KeyP`)로 정했습니다. C 는 모든 기본 레인 배열의 5번째 키이고, 결과 화면에서 5번째 키는 '새 배치로 다시 플레이'라서 캡처하면서 화면을 떠납니다. P 는 레인·조작·결과 단축키 어디에도 쓰이지 않습니다.
- 미리보기는 내장 플레이필드의 실시간 스크롤로 했습니다. PlaySample 은 화면 전체를 사각형에 축소해 레인이 너무 좁고, 앱 공용 스킨 타이머와 씬에 묶여 정지·탐색이 없으며, 판정을 내는 손이 들어 있습니다. 일반화하면 PLAY MENU·SKIN MENU 미리보기를 건드려야 합니다.
- 미리보기 속도는 HI-SPEED, 또는 초록 숫자 고정 중이면 그 차트에서 그 값을 지키는 속도(`PlaySample::shown_hispeed` 와 같은 식)입니다. 커버·히든·리프트·CONSTANT 를 반영합니다. 끝나면 마지막 타임라인 + 1 s 에서 처음으로 돌아갑니다.
- 저장 대상은 레인 순열인 RANDOM·R-RANDOM·MIRROR·ROTATE 입니다. ROTATE 는 계획의 셋에 없지만 레인 순열이라 포함했습니다. OFF 는 저장할 배치가 없어 거절하고 사유를 알립니다.
- 캡처 정보는 결과 화면이 만들어질 때(`ResultRun::of`) 판의 실제 배치(`config.play.random`, 빌린 배치 포함)와 `session.seed()` 로 만들고, 키를 누른 시각을 저장 시각으로 씁니다.
- LAYOUT PICK 에서 저장분을 시작할 때는 시드 탐색 없이 저장된 옵션 이름·시드로 `LayoutRequest` 를 만들고, 출처는 저장 시각(`fmt_datetime`)입니다. 행을 다르게 고쳐 쓰면 일반 RANDOM 탐색으로 돌아가고, 같은 배치로 다시 쓰면 다시 저장분 조건으로 돌아옵니다.
- 목록 조작은 다음과 같이 정했습니다. 키보드는 Right/Left 로 입력란과 목록을 오가고, 목록 안에서 Up/Down 이동, Tab 범위 전환, Delete 두 번 삭제입니다. SELECT 는 사이드들 → 목록 순으로 돕니다. 목록에 있을 때 레인은 턴테이블·KEY1·KEY2 이동, KEY3 범위 전환, KEY4 두 번 삭제입니다.
- 다른 차트 항목은 커서만으로는 옮겨 가지 않고 Enter/START 로 옮겨 갑니다. 커서를 움직일 때마다 차트를 다시 읽지 않게 하려는 것입니다.
- 캡처 문구와 저장소 로드·저장 실패 알림은 `notices.rs` 가 아니라 `text/menus/layout_pick.rs` 의 새 `CaptureText` 카탈로그에 넣었습니다. `notify_text` 가 아무 Catalog 나 받기 때문입니다.

## 계획과 달라진 점

- 기본 키: 계획 M14·U7 은 C 였지만 P 로 정했습니다(위 결정 참고).
- 소유 밖 파일 1: `apps/rbms-player/src/stage/select/mod.rs` 와 `stage/select/search.rs` 의 `Shortcut` 전체 match 에 `| Shortcut::CaptureLayout` 를 한 줄씩 더했습니다. 새 enum 값 때문에 컴파일이 안 되기 때문입니다.
- 소유 밖 파일 2: `apps/rbms-player/src/keyconfig_tests.rs` 에 새 단축키 시험 하나(`the_capture_key_ships_on_a_free_key_and_an_earlier_file_reads_as_it_did`)를 더했습니다. 과제가 요구한 '옛 키 설정 파일에서 새 단축키가 기본 키로 읽힘' 시험이고, LayoutPick 키 시험과 같은 형식입니다.
- `lib.rs` 는 `mod captured_layouts;`, AppShared 필드와 문서 주석, 필드 초기화 직전의 `let captured_layouts = …beside(&settings_path)`(settings_path 가 구조체로 이동되기 전에 읽어야 함), 필드 초기화까지 5줄만 더했습니다.
- `text/notices.rs` 는 고치지 않았습니다. 알림은 자기 카탈로그 `CaptureText` 를 씁니다.
- `stage/play/skin_preview.rs` 는 고치지 않았습니다(PlaySample 일반화를 하지 않음).

## 남은 위험

- 캡처 키를 사용자가 레인 키와 같은 키로 다시 지정하면, 결과 화면이 그 레인의 키 표 역할(확정·다시 플레이)도 함께 실행합니다. 기존 충돌 규칙(`Bindable::read_with`)이 단축키와 레인을 같이 읽히는 것으로 보지 않아 거절하지 않습니다. R·N 단축키도 같은 처지입니다.
- 내장(스킨 없는) 결과 화면의 안내 줄(`crates/rbms-render/src/text/result.rs` `HintSelectRetryNext`)에는 P 캡처가 없습니다. 소유 밖이고 골든 시험이 고정한 문구라 고치지 않았습니다.
- 목록에 들어가면 커서의 첫 저장분이 바로 행에 쓰여, 그 전에 직접 입력하던 행은 사라집니다. '고르면 행 입력란도 그 배치로'를 따른 결과입니다.
- 미리보기는 사용자 HI-SPEED 를 그대로 쓰므로, 속도가 낮은 사용자에게는 예전(네 마디 고정)보다 한 화면에 보이는 마디가 적습니다. 요구된 동작입니다.
- 판정 오프셋(JUDGE TIMING)은 미리보기 위치에 반영하지 않았습니다. 소리가 없어 의미가 없다고 봤습니다.
- 실제 창에서 세 언어 문구의 길이와 겹침은 보지 않았습니다. 한·일 문구는 HeadlessCanvas 로 그리지 않았고, 목록 문구는 `fit_text` 로 잘리게 해 두었습니다.
- 멀리 떨어진 커버·리프트 값을 화면에 들어온 뒤 바꿀 방법은 없습니다(옵션 오버레이가 이 화면에서 열리지 않음). 커버·히든·리프트 값은 들어올 때와 그릴 때 설정값을 읽습니다.
