1. 머리를 한 띠로 바꿨습니다. 모든 글자가 기준선 y 77 하나를 공유합니다.
   - 왼쪽(x 64~616): 맨 위 작은 줄 "MUSIC SELECT · SP · FREE PLAY"(caption, muted). 그 아래에 목록 위에 떠 있던 경로를 label 24 로 올렸습니다.
   - 가운데(x 736~1096, 정보창 오른쪽 끝에 맞춤): 검색칸. 비었을 때는 선 하나와 muted 라벨만 보입니다. 검색 중이거나 검색 결과를 보는 중이면 panel 채움과 accent 밑줄, sub 라벨로 바뀝니다.
   - 오른쪽(x 1128~1728, 목록 열에 맞춤): MODE·SORT·LN MODE 를 같은 모양의 한 줄 칩(높이 40, 이름은 caption, 값은 오른쪽 정렬 label)으로 바꿨습니다. 끝(1856)에 시계를 칩 없이 sub 글자로 둡니다.
   - 규칙: 정보는 맨글자, 조작할 수 있는 것은 칩과 칸입니다.
   - 진단: 머리 아래 선은 원래부터 64~1856 전체에 있었습니다. 오른쪽 필터 카드의 아랫변(96)이 선(104) 바로 위에 붙어 오른쪽 절반에만 이중선처럼 보였던 것이 원인이었습니다. 이제 칩은 88 에서 끝나고 선은 하나만 보입니다.
2. 제목 블록(136~272, 높이 200 에서 136 으로)
   - 제목을 title 64 에서 heading 44 로 줄였습니다(SHRINK_CUT 유지).
   - 장르는 label 24(sub), 부제는 24(sub), 아티스트는 body 32(text)로 맞췄습니다. 줄 기준선은 153/199/228/263 입니다.
   - 오른쪽 끝에 떨어져 있던 LEVEL·BPM 을 색 막대 바로 옆 104 폭 칸으로 옮겼습니다. LEVEL 은 장르 줄의 라벨과 제목 기준선의 num44, BPM 은 부제 줄의 라벨과 아티스트 기준선의 값입니다. 제목 길이와 상관없이 빈 띠가 생기지 않습니다.
   - 폴더·코스 막대에서는 제목 줄이 색 막대 바로 옆(x 96)에서 시작합니다.
3. 바닥을 한 줄로 바꿨습니다(중심선 y 1040).
   - 왼쪽: ENTER PLAY · ESC BACK · ↑↓ MOVE · H KEY GUIDE.
   - 문장형 둘째 줄과 i18n 키 `bar_hint_line`·`bar_hint_all_keys` 를 지웠고 `bar_hint_key_guide`(KEY GUIDE / 키 안내 / キーガイド)를 더했습니다. Inter 에 ↑↓ 글리프가 있는 것을 확인했습니다.
   - 키 표지(높이 28)와 버튼(높이 40)은 같은 중심선과 같은 글자 기준선을 씁니다.
   - REPLAY 묶음은 목록 열(1128)에서 시작하고 버튼은 1856 에서 끝납니다. 누르는 영역도 kit.button 의 같은 상자로 함께 옮겼습니다.
4. 정보창
   - 구획 머리를 `kit.section`(구획 폭의 선 + 12 아래 caption + 머리 높이 40) 한 부품으로 통일했습니다. CHART DATA·MY SCORE·NOTES RADAR·MY RECORDS/IR RANKING·SCORE TARGETS·CLEAR RATE·폴더(CHARTS, CLEAR LAMPS)·코스(STAGES, CONSTRAINTS)가 모두 이 부품을 씁니다. SCORE TARGETS 만 따로 쓰던 머리 간격 8·28 이 없어졌습니다.
   - 라벨 위·값 아래 칸은 `kit.value_baseline`(라벨 아래 10 + 값 높이) 한 식으로 맞췄고, 라벨은 구획 위에서 48 아래에 둡니다.
   - MY SCORE: 등급 상자가 라벨 위에서 큰 숫자 기준선까지 차지하고, 램프 이름과 `MAX -27` 은 그 아래 16 을 띄운 줄(기준선 +136)로 옮겨 겹침이 없어졌습니다.
   - 세로 배치: 제목 136~272 → 24 → 1행 296~552 → 24 → 2행 576~872(높이 256 에서 296 으로, 줄어든 머리 높이를 여기에 줬습니다) → 24 → 목표 줄 896~968. 위아래 끝(136·968)은 스크롤 막대 트랙과 같고, 머리 선 아래 32·바닥 선 위 32 로 대칭입니다.
   - MY RECORDS 줄 높이 36 → 42. 레이더 중심은 영역 위에서 168 아래로 옮겼습니다.
   - 웨이브 1 의 등급 램프(목록 막대 `lamp_graded`, MY RECORDS·랭킹 줄 덮개)는 `cell()`·`row_box()` 를 그대로 따르므로 새 자리에서도 램프 칸에 정확히 겹칩니다. recorded-scratch-auto 캡처에서 확인했습니다.

## 결정한 것

- 구획 사이 간격 24 는 세로(제목→1행→2행→목표 줄→바닥)에 일률 적용하고, 가로 간격은 격자 gutter 32 를 그대로 뒀습니다. 열 경계(352, 784, 1128)가 theme.grid 와 header·footer 정렬의 기준이기 때문입니다.
- 머리 아래 선은 parts.frame 의 64~1856(여백에서 여백까지, 바닥 선·결과·결정 화면과 같음)을 유지했습니다. 0~1920 은 다른 화면과 어긋납니다.
- SP/DP/9KEYS 와 FREE PLAY/COURSE 칩을 없애고 머리 왼쪽 첫 줄 문장(화면 이름 · 스타일 · 모드)으로 합쳤습니다. 새 문구는 없고 기존 i18n 을 씁니다.
- 검색어가 있는지·입력 중인지는 스킨이 직접 읽을 수 없습니다(SEARCHWORD 는 원본처럼 항상 빈 문자열이고 입력 중 플래그도 없습니다). 그래서 DIRECTORY 가 원본 SearchWordBar 제목 형식 "Search : '" 로 시작하는지로 판단합니다. 앱 쪽 값은 추가하지 않았습니다.
- 바닥의 '높이·기준선 맞춤'은 같은 중심선(1040)과 같은 글자 기준선으로 해석했습니다. 키 표지는 28 높이로 버튼(40)보다 작게 두어 누를 수 없는 표지임을 구별했습니다.
- LN MODE 칩 값은 LN/CN/HCN 약어입니다(위 5d).
- 모노톤과 강조색 규칙을 지켰습니다. 새 색은 없고 accent 는 기존처럼 켜짐 상태(검색 중 밑줄, 랭킹 켜짐, 리플레이 선택)에만 씁니다.
- 제목 블록의 LEVEL·BPM 은 오른쪽 끝이 아니라 색 막대 옆 고정 칸(104)에 둡니다. 제목 길이와 관계없이 바로 붙어 있습니다.

## 계획과 달라진 점

- 소유 파일 밖은 고치지 않았습니다. lua/parts.lua 의 frame 은 caption 없이 부르기만 했습니다.
- 계획서 U8 지침 1 은 '띠 아래 선은 화면 전체 너비'였으나, 선은 원래 여백에서 여백(64~1856)이었고 그대로 뒀습니다. 문제의 원인은 오른쪽 필터 카드의 아랫변이었고, 그것을 없애 해결했습니다.
- 지침 1 의 '입력 중이면 도드라지게'는 첫 글자를 친 뒤부터 적용됩니다. 검색 키만 누르고 아직 글자가 없는 순간에는 조용한 모양에 캐럿만 보입니다. 이 구간까지 하려면 스킨이 읽을 입력 중 값이 앱에 있어야 하는데, 지시대로 추가하지 않고 보고합니다.

## 남은 위험

- 캡처 하니스는 CJK 를 그리지 못해 한국어·일본어의 실제 모습은 보지 못했습니다. 폭은 계산으로만 따졌습니다. 칩 이름 칸(MODE 60, SORT 56, LN MODE 92), 바닥 라벨 64, REPLAY 76, ランキング 90/96, お気に入り 약 90/88 은 SHRINK_CUT 하한 0.75 안에 듭니다.
- 검색 강조는 DIRECTORY 의 원본 제목 형식 "Search : '" 에 기댑니다. 앱이 이 형식을 바꾸면 강조가 꺼집니다(검색 동작 자체는 영향 없음).
- LN MODE 칩이 약어(LN/CN/HCN)로 바뀌어 사용자에게 익숙한 전체 이름이 머리에서 사라졌습니다. 빠른 설정 패널에는 남아 있습니다.
- SORT 값 RIVALCOMPARE_SCORE·RIVALCOMPARE_CLEAR 는 칩 폭 136 에서 말줄임이 됩니다(드문 정렬).
- 긴 글 캡처의 MY SCORE 다음 등급이 'F --11000' 으로 보입니다. 시험 데이터의 EX 가 최대치를 넘어서 생기는 기존 next_rank 서식 문제이고, 이번에 손대지 않았습니다.
- 실창(Retina, 16:10 레터박스)에서는 확인하지 않았습니다. 판정은 메인의 캡처 검토에 맡깁니다.
