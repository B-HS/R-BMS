# PLAY 메뉴 — 플레이 옵션을 바꾸며 플레이 화면을 미리 보는 독립 화면 (웨이브 10B) 설계서

> 최종 갱신 2026-10-14 · 대응 커밋 7095ef7 · 작성 2026-10-11 · 상태: 구현 완료(골격, P1 미리보기, P2 메뉴 화면, 리뷰 발견 수정과 통합. 커밋 401ab3b). 웨이브 16 에서 CHART 묶음의 TARGET 아래에 TARGET FALLBACK·TARGET RATE 두 행을 더하고 목표가 없을 때의 물러남을 바꿨다(§4, §11.2, `docs/play-options.md` 11절). 이 문서는 최종 구현을 적는다. 단계별로 달라진 결정은 §18 에 모았다. 웨이브 10C 에서 플레이 스킨의 오프셋과 불투명도 행을 더했다(§4.1, §8, §10, §18). 웨이브 11 에서 숫자 행에 슬라이더와 직접 입력을 넣고 한 칸을 가장 잔 단위로 바꿨다(§8, §13.1). §4 와 §4.1 의 '한 칸 / Shift' 는 §13.1 의 표가 대신한다. 세 화면 밖(선곡 옵션 패널, 플레이 중 키, 연습 패널)의 걸음은 바꾸지 않았다(`docs/play-options.md` 7.3절 끝의 표). 웨이브 14 에서 스킨 행의 값을 같은 행을 가진 다른 화면에 놓는 `A` 키를 더했고(§4.2, §8), LANE 묶음에 기본 스킨의 색 옵션 행이 늘었으며(§4.2), 플레이 중 START + 턴테이블의 걸음이 이 메뉴의 LANE COVER·LIFT 행과 같은 한 칸(0.1%)이 됐다(`docs/play-options.md` 5.2절)
> 사용자 요청(원문): "5. 흰숫 녹숫으로 현재배율기준으로 잘 계산해주는듯한데 lift, lane cover를 기준으로 녹숫을 한번 설정해두면 다른 배속이 다른 곡에서도 해당 lane cover, lift에 맞게 자동으로 배속을 조절하는 기능도 필요해" / "6. 5번의 기능을 포함해서 플레이 옵션들도 skin 설정처럼 별도의 화면을 띄우고 실제로 보면서 조절할수있게하면되겠지"
> 관련 문서: 옵션 정의 `docs/play-options.md`(웨이브 10A), 짝이 되는 화면의 설계 `docs/plan/2026-10-11-skin-menu.md`, 사용자 설명 `docs/skin.md`

## 1. 목표와 요구 사항

| # | 요구 | 판정 기준 |
| --- | --- | --- |
| R1 | PLAY 메뉴는 독립 화면이고 SKIN 메뉴와 같은 양식·배치다 | `Stage::PlayMenu`. 제목, 모드 탭, 왼쪽 행 목록, 오른쪽 16:9 미리보기, 아래 정보 패널, 바닥 안내가 SKIN 메뉴와 같은 좌표에 있다. 두 메뉴가 `stage/preview_menu.rs` 의 같은 함수로 그린다 |

| R5 | 정보 패널에 계산 요약 | 예시 BPM 에서의 하이스피드, 이동 시간(ms), 녹색 숫자, 흰 숫자, 범위에 걸렸는지. 플레이 화면과 같은 함수(`rbms_config::held_speed` 등)로 계산한다 |
| R6 | 저장은 Settings 와 같은 파일, 같은 필드 | 설정 파일 형식 불변. Settings 에서는 옮긴 행이 빠지고 `PLAY MENU >` 단추가 생긴다. F1 오버레이와 선곡의 옵션 패널 1~3 은 그대로 |
| R7 | 들어가는 길과 조작 | 선곡의 단축키(`Shortcut::PlayMenu`, 기본 F8), Settings 의 단추와 같은 키. 나가기는 Esc(저장 후 왔던 화면). 조작은 SKIN 메뉴와 같다 |
| R8 | 자원 수명과 실패 | 메뉴를 떠나면 미리보기의 텍스처·Lua 상태 해제. 메뉴 아래의 선곡은 그대로. 문서가 없는 모드와 읽기 실패는 미리보기 자리에 이유를 글로 |
| R9 | 기존 동작 불변 | 실제 플레이, 내장 화면의 골든, 오디오 시계, 판정 경로, SKIN 메뉴의 화면 |

- 묶음 이름 5칸과 행 29개(웨이브 10B 의 기본 스킨 7키 기준. 스킨 옵션 5개 포함, LANE OPTION 제외)로 34칸이었다. 웨이브 10C 뒤에는 스킨 옵션 7개, JUDGE POSITION Y, SKIN 묶음 이름과 접이 둘이 더해져 접힌 채로 40칸이었다(§4.1). 그 뒤 웨이브 14 가 LANE 묶음에 스킨의 색 옵션 행을, 웨이브 16 이 CHART 묶음에 TARGET FALLBACK·TARGET RATE 를 더해 지금은 그보다 많다(칸 수는 미리보는 스킨이 선언한 옵션에 따라 다르다). 17칸씩 보인다.
- Shift 의 큰 단계는 숫자 행(GREEN NUMBER, HI-SPEED, HI-SPEED STEP, LANE COVER, LIFT, HIDDEN+, COVER FINE STEP, JUDGE OFFSET)과 스킨의 오프셋 행·불투명도 행에 있고 모두 가장 잔 단위 열 칸이다(§13.1). 설정 표의 숫자 행은 `rbms_config::move_number_steps(config, id, ±1 또는 ±10)` 한 통로를 탄다(`stage/play_menu/rows.rs` 의 `step_setting`. `SHIFT_STEPS` 는 `number_row.rs` 에 있고 세 화면이 같은 상수를 쓴다). 범위를 넘는 걸음은 범위 끝까지 간다. 토글·순환 행과 스킨 옵션 행은 Shift 와 무관하게 한 칸이고 `adjust` 를 탄다.
- LANE COVER·LIFT·HIDDEN+ 는 값을 걸음 수로 세어 `걸음 / 1000` 을 저장하므로 0.1% 격자 위에 선다(§13.1. 선곡 옵션 패널의 `adjust` 는 전과 같은 1% 격자다). 키로 올린 30.0% 는 흰색 숫자 300 이다.
- 읽기 전용 행은 좌우·Enter·클릭·0 에 움직이지 않는다. 커서는 선다(정보 패널에 왜 못 바꾸는지 나온다).
- LANE 묶음의 끝에는 스킨의 옵션(property)과, 그 뒤에 스킨이 선언한 위치·크기 오프셋의 축별 행이 온다(§4.1). 파일 칸은 SKIN 메뉴의 것이다.
- 0 키: 커서 행을 `Config::default()` 의 그 필드 값으로(`reset_setting`). PREVIEW BPM 은 150 으로, 스킨 옵션 행은 문서의 기본 항목으로(`SkinLibrary::reset_property_for`. 저장된 선택을 지우고 빈 항목은 `skin.custom` 에서 없앤다), 스킨의 오프셋·불투명도 행은 오프셋 0 으로(`SkinLibrary::number_for` 의 `shipped` 걸음을 `set_number_for` 로 쓴다. 불투명도는 100%). 접이는 움직이지 않는다.

### 4.1 플레이 스킨의 오프셋과 불투명도 (웨이브 10C)

사용자 요청: 부위별 불투명도를 조절하고, 판정 글자의 위치를 위·아래로 옮기거나 숨긴다. 두 값은 스킨 문서가 선언한 오프셋과 옵션이므로 SKIN 메뉴가 쓰는 곳(`config.skin.custom[문서]` 의 `offsets`, `properties`)에 그대로 읽고 쓴다. 행의 종류와 표시·걸음은 SKIN 메뉴와 같은 코드다(`SkinLibrary::kind_for`, `line_for`, `step_for`, `wide_steps_for`. `docs/plan/2026-10-11-skin-menu.md` §4.1).

| 행 | 놓이는 곳 | 근거 |
| --- | --- | --- |
| 스킨이 선언한 위치·크기 오프셋의 축별 행(기본 스킨: `JUDGE POSITION Y`) | LANE 묶음, 스킨 옵션 바로 뒤. 접지 않는다(`rows::declared`) | 판정 위치는 이 메뉴에서 찾는 값이다. 엔진 오프셋 15행과 한 접이에 두면 `JUDGE OFFSET Y`, `JUDGE DETAIL OFFSET Y` 와 섞여 어느 행인지 이름으로 가릴 수 없었다(리뷰) |
| 불투명도 행(알파 축만 가진 오프셋. 기본 스킨 7키 18개. 웨이브 13 에서 Key Display Opacity 가 없어지기 전에는 19개) | 목록 끝 SKIN 묶음의 접이 `OPACITY` | 행이 많아 펴 두면 목록이 두 배가 된다 |
| 엔진이 모든 플레이 스킨에 붙이는 오프셋(All offset(%), Notes offset, Judge offset, Judge Detail offset. 15행) | SKIN 묶음의 접이 `POSITION AND SIZE`. `SkinLibrary::is_automatic_for` 로 가른다 | 스킨과 무관하게 늘 있는 행이고 드물게 쓴다. 도움말이 `An offset the game adds to every play skin …` 으로 시작한다 |

| 접이의 동작 | 내용 |
| --- | --- |
| 표시 | 한 행. 값은 `HIDDEN (n)` / `SHOWN (n)`(n = 든 행 수). 든 행이 없는 접이는 목록에 없고, 접이가 하나도 없으면 SKIN 묶음도 없다 |
| 펴고 접기 | Enter, ← →, 왼쪽·오른쪽 클릭. 0 키는 움직이지 않는다. 설정에 쓰지 않고 미리보기에 알리지 않는다. 상태는 `PlayMenuState.folds` 이고 저장하지 않는다(열 때마다 둘 다 접힘) |
| 편 직후의 스크롤 | 든 행이 화면에 들어오게 한다(`reveal_fold`): 마지막 행까지 최소한으로 내린 뒤 접이 행이 보이게 올린다. 다 들어가면 전부 보이고, 17칸을 넘으면 접이가 첫 줄에 온다. 처음 구현은 커서 행만 보이게 해서, 목록 끝에 있는 접이를 펴도 값이 `SHOWN` 으로 바뀔 뿐 새 행이 하나도 보이지 않았다(리뷰) |
| 커서 | 접이 행에 그대로 둔다. 모드를 바꾸면 접이 행을 따라간다(그 모드의 스킨에 그 접이가 없으면 자리 기준) |
| 미리보기 | 오프셋·불투명도는 프레임마다 저장값에서 읽으므로 문서를 다시 읽지 않고 다음 프레임에 반영된다(`build_of` 불변). 옵션(JUDGE DISPLAY 등)은 문서를 다시 읽는다 |

## 5. 미리보기 전용 값

| 값 | 어디에 | 고르는 길 | 미리보기에 주는 것 |
| --- | --- | --- | --- |
| 모드 | `PlayMenuState.mode`(`PREVIEW_MODES` 의 자리) | Tab·Shift+Tab, 탭 왼쪽 클릭 | `PlayTarget.screen`(플레이 화면의 스킨 종류 번호) |
| 예시 BPM | `PlayMenuState.bpm`(`PREVIEW_BPMS` 의 자리) | PREVIEW BPM 행의 좌우·Enter·클릭·0 | `PlayTarget.bpm` |

- 둘 다 설정 파일에 쓰지 않고, `config.skin.screen`(SKIN 메뉴가 고른 화면)을 읽지도 바꾸지도 않는다. 메뉴를 열 때마다 7K·150 으로 시작한다.
- 예시 차트는 그 BPM 하나로 끝까지 간다(변속 없음). 시작·최소·최대·메인 BPM 이 같으므로 HI-SPEED FIX 가 무엇이든 유지 기준 BPM 이 예시 BPM 이고, CONSTANT 에서는 필드 템포 120 이다.
- 보이는 것: KEEP GREEN NUMBER 켬에서 BPM 을 바꾸면 녹색 숫자와 노트가 내려오는 시간이 그대로이고 하이스피드가 바뀐다. 끔에서는 하이스피드가 그대로이고 녹색 숫자와 노트 속도가 바뀐다.

## 6. 정보 패널의 계산 요약

`PlayTarget::readout(&config.play) -> SpeedReadout`(`apps/rbms-player/src/skin_preview/target.rs`) 한 곳에서 낸다. 메뉴의 행 값과 미리보기의 예시 스크롤이 같은 계산을 쓴다.

| 요약 항목 | `SpeedReadout` 필드 | 계산 |
| --- | --- | --- |
| 기준 BPM | `bpm` | `PlayTarget::scroll_bpm`: 예시 BPM. CONSTANT 이면 `stage/play/field.rs` 의 `CONSTANT_BPM`(120) |
| 하이스피드 | `hispeed`, `held` | 유지 켬이고 `rbms_config::held_speed(&HeldTravel::of(play, bpm))` 가 답하면 그 값(`held = true`). 아니면 저장된 `play.hispeed` |
| 이동 시간 | `duration_ms` | 유지: `HeldSpeed.duration_ms`. 아니면 `rbms_config::travel_duration_ms(bpm, hispeed, 커버가 켜져 있으면 커버)` |
| 녹색 숫자 | `green_number` | `rbms_config::green_of_duration(duration_ms)` |
| 흰 숫자 | `white_number`, `cover_on` | `(play.cover * 1000).round() as i32`(스킨 number 14 와 같은 반올림. `skin_host/play.rs` 의 14·314·315 도 반올림한다). 커버가 꺼져 있으면 `cover_on = false` |
| 범위에 걸림 | `limited` | `HeldSpeed.limited`(하이스피드가 0.01~20.00 의 끝에 머문다) |

- 양식: 패널의 너비를 고르게 나눈 다섯 칸(`figure_x`, 칸 160). 칸마다 작은 이름(`text_muted`) 아래 큰 숫자(흰색)가 있고, 숫자 뒤에 작은 말이 붙는다.

| 칸 | 숫자 | 뒤에 붙는 말(색) |
| --- | --- | --- |
| BPM | `150` | CONSTANT 이면 `120` 뒤에 `(CONSTANT)`(accent) |
| HI-SPEED | `2.24` | 유지 중이면 `(HELD)`(accent), 범위에 걸리면 `(LIMIT)`(경고색 `warn`, 호박색. 웨이브 15 전에는 `Color::YELLOW`) |
| TRAVEL | `500` | `MS`(`text_muted`) |
| GREEN | `300`(초록 `Color::GREEN`. 스킨이 녹색 숫자를 쓰는 색) | 없음 |
| WHITE | `300` | 커버가 꺼져 있으면 `(COVER OFF)`(accent) |

- 범위에 걸리면 숫자 줄 아래(y+39, 경고색 `warn`)에 `HI-SPEED IS AT THE END OF ITS RANGE: NO SPEED HOLDS THIS GREEN NUMBER AT THIS TEMPO` 한 줄이 나온다. 숫자 줄 오른쪽에 두면 WHITE 칸과 겹쳐서 줄을 따로 잡았다.
- 그리기는 `stage/preview_menu.rs` 의 `InfoFigure`·`draw_info_figures`, 내용은 `stage/play_menu.rs` 의 `summary`·`summary_note` 다. 칸마다 이름·숫자·붙는 말이 다음 칸 전에 끝나는지는 테스트가 지킨다(`what_the_menu_writes_fits_where_it_is_written`).
- 리프트와 HIDDEN+ 는 계산에 들어가지 않는다(`docs/play-options.md` §4.4). 요약에 싣지 않는다.
- 미리보기의 예시 스크롤과 같은지는 테스트가 지킨다: `PlaySample::shown_hispeed` 와 `readout.hispeed` 가 유지·CONSTANT 네 조합에서 같다(`stage/play/skin_preview/tests.rs`).

## 9. 들어가고 나가는 길

| 길 | 구현 | 상태 |
| --- | --- | --- |
| 선곡의 F8 (`PLAY_MENU_KEY`, `Shortcut::PlayMenu`) | `run_shortcut` 이 `Transition::Open(PlayMenuState::stage())`. 내장 선곡과 스킨 선곡이 같다. 키 설정 화면·가이드(H)·패드에서 바꿀 수 있고 설정 파일 키는 `play_menu` | 연결 |
| 검색어를 치는 중 | 입력을 확정한 뒤 연다(`WhileTyping::Opens`) | 연결 |
| Settings 의 바로 가기 | `PLAY MENU >` 단추와 같은 단축키(§7). Esc 는 보던 탭으로 돌아온다 | 연결 |
| 스킨의 버튼 | 넣지 않는다. 원본에 플레이 옵션 화면을 여는 이벤트가 없다(화면을 바꾸는 이벤트는 13·14 뿐). 번호를 새로 정하면 이 플레이어에서만 뜻이 있는 스킨 사양 확장이 되고, 기본 스킨 사이드 메뉴의 한 행을 위해 사양을 늘리지 않는다. 가이드(H)와 Settings 가 길을 알린다 | 넣지 않음 |
| 나가기 | Esc → `save_settings` → `Transition::Back`. `on_exit` 가 `SkinPreview::release` | 연결 |

기본 키를 F8 로 한 이유: 선곡이 읽지 않던 기능 키 가운데 운영체제가 따로 쓰지 않고(F10·F11 제외), 테스트가 다시 묶는 대상으로 쓰는 키가 가장 적다(F6·F7 제외).

이전 키 설정 파일: `keyconfig.ron` 에 `play_menu` 항목이 없으면 기본 키 F8 로 읽는다. 단, 그 파일이 같은 화면의 다른 단축키(FOLDERS 등)를 이미 F8 에 두었으면 PLAY MENU 는 미지정으로 읽는다(`KeyConfig::shipped_key_unless_given_away`). 사용자가 고른 키가 이기고, PLAY MENU 는 키 설정 화면·가이드에 키 없음으로, Settings 안내 줄에 `- PLAY` 로 나오며 단추로는 열린다. 기본 스킨의 선곡 바닥 안내 줄과 패널 3 의 주석이 PLAY MENU 를 가리킨다(`lua/select/controls.lua`, `sheet.lua`).

## 11. 미리보기 확장

### 11.1 대상 지정

| 결정 | 내용 | 이유 |
| --- | --- | --- |
| `SkinPreview` 하나가 두 대상을 지원한다 | `PreviewTarget::Configured`(SKIN 메뉴: `config.skin.screen` 을 매 프레임 읽는다)와 `PreviewTarget::Play(PlayTarget)`(PLAY 메뉴: 호출자가 준 화면과 BPM) | 문서 읽기·컴파일·장면·실패 문구·수명이 전부 같은 기계다. 두 번째 미리보기 타입을 만들면 `skin_preview.rs` 를 통째로 복제해야 한다 |

| 템포의 범위 | 30~999 로 묶는다(`STEADY_BPM_MIN`·`STEADY_BPM_MAX`) | 차트 헤더가 세 자리로 적는 범위. 메뉴는 100~200 만 준다 |

### 11.2 설정이 미리보기에 반영되는 경로

| 설정 | 반영 | 경로 |
| --- | --- | --- |

| GAUGE | 게이지의 종류와 색 | 값이 달라지면 예시 세션을 그 게이지로 바꾼다(11.3) |

| TARGET | 점수 그래프의 타깃 막대와 `TARGET +n` | `PlaySample::told` 가 `target::resolve(config.judge.target, config.judge.target_fallback, TargetContext { total_notes, custom_rate_percent, 나머지 없음 })` 의 EX 를 `PlayLive.target_score` 와 `Standing.target_score` 에, 이름(`legend`)을 스킨의 문자열 id 3 에 넘긴다. 기록·IR·라이벌이 없으므로 LOCAL BEST·IR BEST·RIVAL 은 TARGET FALLBACK(기본 RATE AAA)으로 떨어진다(웨이브 16 전에는 MAX) |
| AUTOPLAY | 스킨의 AUTOPLAY 표지 | `told` 가 `PlayKind::Autoplay` 를 넘긴다. 예시 손(적어 둔 입력)은 그대로다 |

### 11.3 끊임없이 내려오는 예시 (PLAY 메뉴 대상에서만)

| 사건 | SKIN 메뉴 대상(그대로) | PLAY 메뉴 대상 |
| --- | --- | --- |
| 차트가 끝남 | FINISHED → 페이드 → 장면을 다시 시작(약 31초 주기) | 장면을 떠나지 않는다. 마지막 노트 1초 뒤(`BEGIN_AGAIN_AFTER_MS`) 예시 세션과 피드를 새로 만들고 차트의 시각을 0 으로 돌려 PLAY 상태에서 이어 간다(`RunStart::Top`). 런의 결과를 말하는 타이머(FULLCOMBO, ENDOFNOTE 등)는 끈다 |
| 예시 BPM 이 바뀜 | 해당 없음 | 세션만 바꾼다(`RunStart::Carried`). 차트를 0 으로 돌리지 않고 같은 진행 비율에서 이어 간다: 새 세션을 그 지점까지 즉시 재생해 노트·콤보·점수·게이지가 그 템포로 거기까지 친 것과 같다. 0 으로 돌리면 값을 누를 때마다 첫 마디(1.2~2.4초) 동안 레인이 비어 변화를 볼 수 없다. 스킨을 다시 읽지 않으므로 검은 프레임이 없다 |
| GAUGE 가 바뀜 | 다음 장면부터 | BPM 과 같은 방식(같은 진행 비율에서 그 게이지로) |
| 모드가 바뀜 | 새 장면 | 새 장면(다른 문서) |

세션 교체는 `PlaySample::due_run`·`begin_run` 이 장면에 묻기 전에 처리하므로 장면 기계(`PlayScene`)는 늘 연주 중인 차트만 본다. 교체하는 프레임에 레인 타이머(봄·키빔·홀드)가 한 번 꺼졌다 켜지고 판정 글자가 다음 판정까지 빈다.

## 12. 경계 API

`apps/rbms-player/src/skin_preview.rs`, `skin_preview/target.rs`

| 항목 | 시그니처 | 계약 |
| --- | --- | --- |
| 대상 | `PlayTarget { screen: i32, bpm: u32 }`, `PreviewTarget::{Configured, Play(PlayTarget)}` | `screen` 은 플레이 화면의 스킨 종류 번호. `bpm` 은 예시 차트의 한 템포 |
| 생성 | `SkinPreview::new()` / `SkinPreview::of_play(target: PlayTarget)` | 아무것도 읽지 않는다. `of_play` 는 `config.skin.screen` 을 읽지 않는다 |

| 대상 읽기 | `target(&self) -> PreviewTarget` | `release` 뒤에도 같다 |
| 갱신·그리기·상태·어두운 대기 | `update(ctx)`, `draw(ctx, canvas, rect) -> &PreviewStatus`, `status()`, `waits_in_the_dark()` | SKIN 메뉴와 같다(`docs/plan/2026-10-11-skin-menu.md` §8) |
| 변경 통지 | `settings_changed(&mut self, shared)` | PLAY 메뉴는 행이 움직일 때마다 부른다(플레이 옵션이든 스킨 옵션이든). 스킨 옵션은 메뉴가 먼저 그 화면의 문서를 다시 읽게 해 둔다. 모드·BPM 은 여기가 아니라 `show_play` |
| 해제 | `release(&mut self, shared)` | 메뉴의 `on_exit`. 여러 번 불러도 된다 |
| 계산 요약 | `PlayTarget::scroll_bpm(self, &PlayOptions) -> f64`, `PlayTarget::readout(self, &PlayOptions) -> SpeedReadout` | 순수 함수. §6 |

| 스킨 옵션(화면 지정) | `SkinLibrary::{rows_for, line_for, step_for, reset_property_for, needs_reload_for, request_for}(config, screen, …)` | `config.skin.screen` 이 아니라 인자의 화면. 기존 `rows`·`line`·`step` 은 위임한다 |

호출 순서(PLAY 메뉴): `of_play` → 매 프레임 `update`(메뉴의 `update`) → `draw_preview`(메뉴의 `draw`. 공통 부품이 `draw` 와 상태 문구를 맡는다) → 행이 움직이면 설정을 쓰고 `settings_changed` → 모드·BPM 이 움직이면 `show_play` → `on_exit` 에서 `release`.

소유: 설정을 쓰는 것, 라이브러리에 다시 읽기를 요청하는 것, 모드와 BPM 을 정하는 것은 메뉴. 문서를 읽고 컴파일하고 그리는 것, 장면·예시 세션, 설정이 그려지는 방식은 미리보기.

## 17. 남은 위험

| 위험 | 대응 |
| --- | --- |
| 예시 차트가 한 템포라 HI-SPEED FIX 의 네 값이 미리보기에서 같아 보인다 | 의도한 것이다(요약의 기준 BPM 이 하나로 읽힌다). 행의 도움말이 실제 곡에서의 뜻을 말한다 |
| 유지 켬일 때 HI-SPEED 행이 읽기 전용이라 저장된 `play.hispeed` 를 볼 수 없다 | 유지 중에는 저장값이 쓰이지 않는다(`docs/play-options.md` §4.1). 끄면 저장값이 다시 보인다 |
| JUDGE OFFSET 의 한 칸이 Settings 의 옛 행(5 ms)과 다르다 | 표의 걸음을 1 ms 로 바꿔 선곡 패널 3·플레이 중 키와 통일했다. Shift 가 10 ms |
| Settings 의 탭 띠에 단추 둘이 안 들어갈 수 있다 | 탭 둘이 빠져 들어간다. `settings_view.rs` 의 너비 단언이 지킨다 |
| `SettingTab` 변형 이름이 바뀌어 다른 크레이트가 깨진다 | `rbms-cli` 와 `rbms-config` 의 쓰는 곳을 함께 고쳤다(§14) |
| 스킨 옵션 행이 모드마다 달라 커서가 다른 행으로 옮겨 간다 | 표의 행은 `SettingId` 로 따라가고, 스킨 옵션 행은 자리로 잡는다(SKIN 메뉴의 `refresh` 와 같은 규칙) |
| F8 이 사용자의 기존 키 설정과 겹친다 | 같은 화면의 다른 단축키를 F8 에 둔 파일에서는 PLAY MENU 가 미지정으로 읽혀 사용자의 키가 그대로 동작한다(§9). 선곡의 단축키는 플레이 조작·레인 키와 같은 순간에 읽히지 않는다(START·SELECT 만 예외). START·SELECT 를 F8 에 둔 사용자는 키 설정 화면이 충돌을 알린다 |
| 스킨 number 14·314·315 가 원본(버림)과 다르게 반올림한다 | f32 값이 천분의 일에 조금 못 미칠 때만 1 차이가 난다(원본은 299, 여기는 300). 내장 HUD 의 흰색 숫자는 이전부터 반올림이었다. 316 은 원본과 같은 버림 그대로다 |
| 미리보기의 픽셀 측정 테스트가 기본 스킨의 모양에 기댄다 | 기본 스킨의 플레이 배치나 색을 바꾸면 `skin_preview/tests.rs` 의 상수를 함께 고친다 |
| `Config::default()` 의 AUTOPLAY 가 켬이라 새 설정의 미리보기에 AUTOPLAY 표지가 보인다 | 실제 플레이 화면과 같은 표시다. 행을 끄면 사라진다 |

## 18. 단계별로 달라진 결정

| 처음의 설계 | 최종 | 이유 |
| --- | --- | --- |
| 요약은 `AT 150 BPM` 머리와 한 줄 | 이름 아래 큰 숫자의 다섯 칸, GREEN 은 초록 | 리뷰: 같은 크기·같은 색의 한 줄이라 이름과 값이 구분되지 않았다 |
| 읽기 전용 행은 값만 흐림 | 이름도 흐리고 값 뒤에 `AUTO` | 리뷰: 커서를 올리기 전에는 왜 좌우가 안 먹는지 알 수 없었다 |
| 머리의 부제 `PLAY 7KEYS  150 BPM` | `7KEYS  150 BPM` | 리뷰: 제목과 겹쳐 PLAY 가 두 번 나왔다 |
| 흰색 숫자는 버림, 비율 행은 0.01 누적 | 반올림, 격자 걸음 | 리뷰(major): 키로 정한 30% 가 299 로 읽혔다 |
| JUDGE OFFSET 은 메뉴가 `adjust` 를 우회해 1 ms | 표의 걸음이 1 ms, 메뉴는 `adjust` | 리뷰: 5 ms 경로가 어느 화면에서도 닿지 않는 죽은 값이었다 |
| BPM·GAUGE 변경은 차트 시각 0 부터 | 같은 진행 비율에서 이어 감 | P1: 0 으로 돌리면 첫 마디 동안 레인이 비어 변화를 볼 수 없다 |
| `LaneSettings.constant_on` 을 CONSTANT 에 맞춘다 | `false` 고정 | P1: 실제 플레이 화면이 항상 `false` 를 넘긴다. 미리보기만 다르게 하면 플레이와 어긋난다 |
| TARGET·AUTOPLAY 는 미리보기에 보일 것이 없다 | PLAY 메뉴의 런은 따른다 | 리뷰: 기본 스킨에 타깃 막대와 AUTOPLAY 표지가 있다 |
| 이전 `keyconfig.ron` 의 빈 항목은 기본 키 | 같은 화면의 다른 단축키가 그 키를 쓰고 있으면 미지정 | 리뷰: PLAY MENU 가 사용자가 옮겨 둔 단축키를 가렸다 |
| `SHIFT_STEPS` 가 두 메뉴에 따로, SKIN 메뉴 제품 파일에 테스트 전용 재수출 | 공통 상수, 테스트가 직접 import | 리뷰: 공통으로 올린 뒤 남은 중복 |
| (웨이브 10C) 스킨 행은 옵션만. 파일 칸과 오프셋은 SKIN 메뉴의 것 | 오프셋과 불투명도도 싣는다 | 사용자 요청: 판정 위치와 부위별 불투명도를 플레이 화면을 보며 바꾼다 |

| (웨이브 10C) 접이를 펴면 커서 행만 보이게 | 든 행이 보이게 스크롤 | 리뷰: 목록 끝의 접이를 펴도 새 행이 보이지 않았다 |
