# 기본 스킨 개별 객체 구현 사양

상태: 설계 확정, 기능 구현 대기. 이 문서는 화면 보정 사양 §4.1의 후속 계약이다. 기존 JSON5 모델과 렌더 경로를 먼저 확인했다. `image`·`value`·`floatvalue`·`text`·`slider`·`graph`·`bga`는 그리기 경로가 있지만, `note`·`gauge`·`judge`·`songlist`와 일부 결과 그래프는 문서 모델만 있고 화면 객체로 만들지 않는다. 현재 기본 문서도 각 화면에 배경·전경 이미지 두 개만 선언한다. 그러므로 새 문서만 작성해서 개별 객체 편집이 된다고 판정하지 않는다.

## 1. 공통 파일·합성 계약

1. 각 화면은 문서 객체 `id`, `source`, `destination`으로 이미지·글자·수치·그래프의 위치, 크기, 색, 표시 조건을 개별 지정한다. 여러 상태 값을 한 이미지의 고정 글자로 구워 넣지 않는다. 배경/전경은 장식으로만 유지한다.
2. 기존 `replace`·`overlay`와 다른 프리셋의 동작은 유지한다. 새 기본 문서의 `layered`에는 네이티브 출력 묶음별 대체 여부를 선언한다. 대체 묶음이 없는 문서는 기존 네이티브 UI가 그대로 보이고, 대체 묶음이 있는 경우 해당 묶음만 숨긴다. 목록·입력·기록 계산은 숨겨도 같은 엔진 상태를 사용한다.
3. 문서 로더는 대체 선언에 필요한 객체가 불완전하거나 컴파일에 실패하면 그 묶음을 숨기지 않고 경고한다. 지원하지 않는 필드를 조용히 무시한 채 네이티브 정보를 제거하지 않는다. 설정 저장·재실행 후 같은 문서/옵션 선택이 돌아와야 한다.
4. 기본 문서의 고정 자산은 `assets/skins/steel-neon-v2/`에 두고, 이미지 생성원·팔레트·RON·JSON5를 편집 가능하게 유지한다. 화면별 문서와 5/7/9/10/14키 배치는 별도 파일이다.

## 3. 실행 순서와 통과 조건

1. 결과 객체를 먼저 연결해 대체 묶음의 기본값·오류 폴백을 검증한다.
2. 플레이 HUD와 곡 상세를 연결한다. 문서의 동적 값은 기존 상태 공급자를 확장해 제공하고 한 화면의 값을 다른 화면에서 추측해 재계산하지 않는다.
3. 곡 목록과 옵션의 반복 행을 구현한다. 행 위치와 입력 영역은 한 배치 결과를 공유한다.
4. 노트·판정·게이지 객체를 세션에 연결한다. 5/7/9/10/14키의 레인 구성, 롱노트 시작·유지·종료, 판정 변화와 게이지 변화가 최소 검증 장면이다.
5. 위 기능이 컴파일·검증된 뒤 기본 JSON5 문서를 객체별로 작성한다. 문서 편집으로 각 대상의 크기·위치·색 또는 이미지가 바뀌는 증거와 실제 화면 캡처를 저장한다.

검증에는 값이 있는 곡 선택 5행, 옵션 11행, 노트·롱노트·판정이 있는 5/7/9/10/14키, 점수·기록·목표가 있는 결과를 포함한다. 화면 캡처만으로 입력 일치를 주장하지 않으며, 입력 테스트만으로 픽셀 배치를 주장하지 않는다. 실제 창의 GPU 및 오디오 지연은 별도 실기 확인 항목이다.
