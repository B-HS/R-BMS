# 기본 스킨 고도화 사양

## 입력과 판단 기준

- 입력은 사용자가 제공한 화면 9장과 화면 정의·이미지·소리 묶음이다. 화면은 실제 동작과 일부 다를 수 있으므로 배치와 정보 계층의 참고 자료로 사용한다.
- 원본 정의는 1920×1080 기반의 분기·포함 파일 9개와 이미지 압축 파일 1,004개로 구성된다. 현재 `apps/rbms-player/src/skin_select.rs`는 JSON/JSON5만 탐색하고 `apps/rbms-player/src/assets.rs`는 일반 이미지 디코더로 이미지를 연다. 원본 형식의 직접 로드나 전체 자동 변환은 현재 기능이 아니다.
- 원본 묶음에서 재배포 허가 문서를 확인하지 못했다. 저장소와 배포에 들어갈 화면 자산은 새로 작성하고 원본 바이너리는 복제하지 않는다.
- 신규 산출물의 파일명, 문서 본문, UI 문자열에 외부 스킨과 엔진의 고유 이름을 쓰지 않는다.

## 화면별 골격

| 화면 | 제공 화면 | 기본 화면 목표 | 보존할 동작 |
| --- | --- | --- | --- |
| 곡 선택 | 1 | 어두운 자주색 별빛 배경, 선택된 곡의 큰 제목·레벨·정보 영역, 대비가 강한 곡 목록, 하단 옵션 띠 | 검색·정렬·필터·폴더 이동·마우스 선택·기록·커버·미리듣기 |

## 기능 추가를 먼저 구현하는 순서

1. **화면 합성 모드**: JSON5 문서에 `composition: "overlay"`를 허용한다. 해당 모드는 실제 곡 목록의 클릭 영역과 플레이의 노트·판정·게이지를 기존 화면으로 그린 뒤, 문서의 장식을 위에 그린다. 생략 또는 `replace`는 기존 전체 교체 동작을 유지한다. 장식이 없는 문서는 기존 픽셀과 입력을 바꾸지 않아야 한다. 이 기능은 범용 렌더러에서 아직 지원하지 않는 곡 목록·노트 객체를 가진 기본 스킨이 기능을 잃지 않기 위한 필수 조건이다.
2. **곡 선택 열 배치**: 스킨 폴더의 `theme.ron`에 목록·상세 패널 사각형과 행 간격을 선언하고, 기존 화면의 렌더·커버·온라인 순위·필터·클릭 영역이 같은 좌표를 사용하게 한다. 새 기본값은 오른쪽 목록·왼쪽 상세이며, 이전 테마에 필드가 없으면 종전 좌표를 쓴다. 새 프리셋에서는 스킨 폴더의 테마를 읽고, 다른 프리셋에서는 기존 설정 폴더의 테마를 읽는다.
3. **기본 문서 설치**: 배포된 문서와 그래픽을 설정의 스킨 폴더 아래 `steel-neon/`에 생성한다. 이미 있는 파일은 덮어쓰지 않아 사용자의 수정을 보존한다. 업그레이드에서도 최초 한 번만 선택되지 않은 지원 화면에 기본 문서를 연결하고, 기존의 명시적 선택은 보존한다. 적용 완료 표시를 설정에 저장하여 이후 사용자가 내장 화면을 고르면 다음 실행에도 그 선택을 유지한다. 설치 실패 시 내장 화면으로 안전하게 폴백한다.
4. **파일 편집 경로**: `select.json5`, `decide.json5`, `result.json5`와 현재 지원 플레이 모드별 `play-5k.json5`·`play-7k.json5`·`play-9k.json5`·`play-10k.json5`·`play-14k.json5`에 각 요소의 위치·크기·조건을 둔다. `play-24k.json5`는 모드 활성화 시 사용할 준비 파일로 설치하되 현재 선택하지 않는다. 색과 프레임은 독립 PNG, 단일 필드의 좌표·노트·판정 색은 `play.ron`, 이중 필드는 `play-dual.ron`, 곡 선택 열 배치와 공통 UI 색은 스킨 폴더의 `theme.ron`에서 조정한다. JSON5 변경은 설정 화면의 스킨 다시 읽기로, RON 변경은 앱 재시작으로 반영한다.
5. **기본 적용**: 곡 선택·현재 지원 플레이 모드·결과는 합성 모드로 기능을 유지한다. 로딩은 제목·진행률을 문서의 동적 텍스트/그래프로 그리는 전체 교체 모드를 쓴다. 문서 오류는 기존 내장 화면으로 폴백한다.

## 자산·레이아웃 계약

- 기준 좌표는 1280×720이다. 문서는 화면별로 독립 파일이며 다른 화면 요소를 암묵적으로 참조하지 않는다.
- 공통 이미지의 원본은 직접 수정 가능한 절차적 생성 스크립트와 팔레트 파일로 제공하고, 실행 시 읽는 PNG도 함께 둔다. 단일·이중 필드의 영상 테두리는 별도 PNG로 제공한다. 사용자는 팔레트 변경 후 이미지를 다시 만들거나 PNG를 직접 교체할 수 있다.
- 이미지 외곽 장식은 현재 클릭 영역과 판정선·노트·핵심 숫자를 덮지 않는다. 합성 모드 문서에는 선택/플레이 입력을 가로채는 핫 영역을 넣지 않는다.
- 기본 제공 자산에 원본의 영상·음성·글꼴을 포함하지 않는다. 차트가 가진 BGA와 사용자 폰트는 현재 경로에서 계속 사용한다.

## 검증 기준

- 문서 파싱: 현재 지원 8개 기본 문서가 각 타입으로 로드되고, 상대 이미지가 스킨 폴더 안에서 해석되며 경고 없이 컴파일된다. 준비 문서 1개는 JSON5 구문과 타입만 확인한다.
- 화면: 곡 선택의 오른쪽 목록·왼쪽 상세·마우스 핫 영역, 5K/7K/9K/10K/14K 노트 필드, 결과의 점수·그래프, 로딩의 제목·진행률이 새 장식과 함께 보인다.
- 설정: 새 설치와 아직 기본 적용을 받지 않은 기존 설정에서 빈 화면만 기본 문서로 연결되고, 기존의 명시적 문서는 유지된다. 이후 내장 화면을 선택하면 재시작 후에도 유지되며, 편집한 파일은 설치 단계에서 덮이지 않는다.
- 회귀: 기존 `replace` 문서와 문서 미선택 시 렌더 동작은 유지된다. 최소 관련 테스트 뒤 `cargo fmt --all --check`, `cargo clippy --workspace --all-targets --all-features -- -D warnings`를 실행한다.

## 후속 정밀화

- 곡 목록·노트·판정·게이지를 JSON 객체로 완전 치환하려면 `rbms-render/src/skin_render/object.rs`의 미구현 객체와 앱 상태·입력 배선을 확장해야 한다. 현재 합성 모드는 이 요소의 기능을 유지하면서 그래픽 교체 범위를 먼저 제공한다.
- 제공 옵션 화면은 별도 스킨 정의가 아니라 호스트 설정 UI이므로, 별도 화면 타입을 신설하기 전에는 공통 테마로 맞춘다.
