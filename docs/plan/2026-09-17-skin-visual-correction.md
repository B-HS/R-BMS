# 기본 스킨 실화면 보정 사양

상태: 구현 전 확정. 기준 화면은 사용자가 제공한 곡 선택·재생 실행 캡처와 앞서 제공한 화면 구조 자료다. 외부 파일의 문구와 자산은 저장소로 복사하지 않는다.

## 1. 확인한 결함과 원인

| 화면 | 관찰값 | 코드 원인 | 합격 조건 |
| --- | --- | --- | --- |
| 곡 선택 | 목록이 왼쪽, 상세가 오른쪽이며 장식이 내용 위에 표시됨 | 문서는 새 선택 화면을 가리키나 `display.skin`이 WIDE로 남아 기존 테마가 적용됨. 문서 안의 전체 화면 이미지는 최상단 합성 | 1280×720에서 상세는 왼쪽, 목록은 오른쪽. 제목·수치·조작 힌트의 글자 영역을 장식이 관통하지 않음 |
| 선택 옵션 | 반투명 패널이 우측 상세 내용 위에 놓여 배경 글자가 비침 | 옵션 패널의 위치와 투명도가 코드에 고정됨 | 새 기본값은 중앙에 읽을 수 있는 불투명 패널. 배경과 명확히 구분되고 선택 행이 드러남 |
| 단일 재생 | 장식 테두리가 노트 필드·판정·그래프·수치를 가로지름 | WIDE 필드 x≈230~691과 새 배치 x≈83~467이 섞임. 새 BGA 틀 x≈478~942를 노트와 HUD 뒤에 그림 | 필드·BGA·그래프·판정·카운터 각각의 사각형이 충돌하지 않으며 장식은 노트/문자 앞을 가리지 않음 |
| 이중 재생 | 단일과 동일한 조합 위험 | 이중 필드와 문서·배치 선택이 독립적 | 양쪽 필드 및 BGA에 같은 계약 적용 |
| 기존 설치 | 수정 파일을 다시 배포해도 화면이 바뀌지 않음 | 설치가 `create_new`이며 `default_skin_installed`가 기존 번들을 건너뜀 | 기존 편집을 보존하면서 2차 번들을 선택할 수 있음 |

## 2. 선택·설치 계약

1. 화면 문서, 선택 테마, 재생 배치는 하나의 번들 버전으로 취급한다. 설정이 새 기본 프리셋이면 이 버전의 화면 문서와 `theme.ron`, 플레이 배치를 사용한다. NORMAL/WIDE 또는 명시적 외부 플레이 배치를 선택하면 이 번들의 장식 문서를 합성하지 않는다.
2. 첫 설치에서 별도 선택이 없는 화면만 기본 문서로 설정한다. 기존 외부 문서는 덮어쓰지 않는다. 사용자가 고른 NORMAL/WIDE 상태에서 이 번들 문서가 선택되어 있지 않으면 그 프리셋을 보존한다. 프리셋을 바꿀 때 즉시 테마를 다시 읽고 다음 플레이 시작 시 대응 배치를 사용한다.
3. 기존 1차 번들 설치는 버전이 다른 새 폴더에 2차 파일을 설치한다. 1차 폴더는 그대로 남긴다. 1차 문서를 자동 선택 중인 화면만 새 문서 경로로 전환하되, 원본과 해시가 다른 파일은 사용자 편집으로 판단해 전환하지 않는다. 이전 설치가 WIDE를 유지한 채 원본 그대로인 기본 문서들을 자동 선택했다면 잘못된 조합으로 판단해 새 프리셋으로 함께 이동한다. 새 폴더 내 기존 파일도 덮어쓰지 않는다. 사용자 편집이나 외부 문서가 섞인 상태에서는 구 번들 장식을 비활성화하여 좌표 충돌을 막는다.
4. 문서 선택을 바꾸거나 프리셋을 바꿔도 사용자 외부 경로를 삭제하지 않는다. 설정을 저장하고 다시 실행했을 때 동일한 조합이 활성화되어야 한다.

## 3. 화면 좌표와 레이어 계약

논리 캔버스는 1280×720이다. 창 크기 변경은 기존 스케일 동작에 맡긴다. 모든 영역은 별도 파일의 숫자로 편집할 수 있게 한다. 2차 기본 배치는 아래를 시작값으로 사용한다.

| 화면 | 기준 영역 `(x,y,w,h)` | 출처 |
| --- | --- | --- |
| 선택 상세 | `(24, 76, 590, 598)` | 테마 RON |
| 선택 목록 | `(628, 76, 628, 598)` | 테마 RON |
| 옵션 패널 | `(240, 122, 800, 476)` | 테마 RON의 옵션 영역. 11행·34px 간격을 수용 |
| 단일 노트 필드 | `(64, 48, 384, 578)` | 플레이 RON |
| 단일 BGA | `(472, 116, 440, 330)` | 플레이 RON |
| 단일 그래프 | `(928, 192, 170, 434)` | 플레이 HUD가 BGA 오른쪽 경계에서 계산 |
| 이중 BGA | `(850, 200, 280, 210)` | 이중 플레이 RON. 판정 수치 아래에 배치 |
| 이중 그래프 | BGA 오른쪽 x=1146부터 화면 오른쪽 여백까지 | 플레이 HUD가 BGA 경계에서 계산 |

- 필드, BGA, 그래프의 실사용 좌표가 장식 이미지의 테두리 위치를 결정한다. RON을 편집한 뒤에도 테두리가 이전 좌표에 고정되는 방식은 실패다.
- 배경은 네이티브 필드와 정보보다 먼저, 전경은 안전한 화면 외곽과 패널 경계에만 그린다. 노트·판정·수치·BGA 안쪽을 채우는 전경 이미지 사용을 금한다. 각 문서는 배경과 전경을 개별 source/destination 항목으로 갖는다.
- 선택 옵션은 새 기본 프리셋에서만 위 중앙 사각형을 사용한다. 다른 프리셋은 기존 배치를 유지한다. 옵션이 열릴 때 내용은 계속 보이되 배경 글자가 패널 속으로 비치지 않아야 한다.
- 단일 모드 5/7/9키와 이중 모드 10/14키 각각 레인 폭이 달라도 외곽 영역은 겹치지 않아야 한다. 24키는 데이터 준비 상태로 표시하고 동작한다고 주장하지 않는다.

## 4. 구현 순서

1. 엔진: 번들 버전 전환·설정 변경 즉시 테마 적용·프리셋별 문서 게이팅을 구현한다.
2. 엔진: 배경/전경 합성과 배치 기준 사각형을 연결한다. 선택 옵션의 사각형과 불투명도를 파일 값으로 읽는다.
3. 기본 파일: 곡 선택, 결정, 단일/이중 재생, 결과 문서와 비트맵·생성 스크립트를 새 배치에 맞춰 제작한다.
4. 확인: 설치/설정 조합 테스트와 실제 렌더 화면의 영역·가독성 검사를 완료한 뒤 결과를 기록한다.

## 4.1 남은 개별 요소 기능

첫 구현은 배경 이미지 한 장과 내장 UI 합성이 중심이었으므로 사용자가 요구한 모든 요소의 파일 편집성은 충족하지 못했다. 다음 기능은 화면 보정과 별개의 완료 조건이며, 지원 객체와 상태 원천을 정의하고 엔진 구현을 먼저 끝낸 다음 기본 문서를 요소별로 작성한다.

| 대상 | 필요한 파일 필드와 상태 원천 | 입력·판정 경계 | 완료 조건 |
| --- | --- | --- | --- |
| 곡 목록 | 행의 제목·레벨·모드·램프·선택 배경·서체·간격을 문서 항목으로 정의. 값은 기존 선택 장면에서 제공 | 검색·정렬·폴더 이동·클릭 사각형이 같은 행 좌표 사용 | 행 텍스트와 배경을 각각 이동해도 마우스 선택이 일치 |
| 곡 상세 | 곡명·장르·작곡자·커버·밀도·기록·목표를 개별 항목으로 정의. 값은 현재 선택 상세 장면에서 제공 | 차트 메타·기록 계산은 기존 모델 유지 | 항목별 크기·위치·색을 파일에서 개별 편집 |
| 재생 | 노트·판정 표시·게이지·키 입력/버튼·속도·점수·비교 그래프를 객체로 정의. 상태는 현재 플레이 세션의 판정/게이지/HUD 스냅샷 | 입력 타이밍·점수 계산·BGA 디코드는 엔진이 담당 | 5/7/9/10/14키에서 객체 이미지를 바꿔도 같은 타이밍과 값을 표시 |
| 결과 | 점수·클리어·판정표·추이·목표 비교를 개별 항목으로 정의. 값은 결과 장면에서 제공 | 기록 저장·재생 이동은 기존 경로 유지 | 각 정보 블록을 독립적으로 숨기거나 이동 가능 |
| 옵션 | 중앙 패널·탭·행 텍스트·선택 강조·값의 위치/색을 파일 설정으로 정의. 값은 설정 descriptor와 공유 | 키 조작·값 저장은 기존 경로 유지 | 옵션 파일 변경이 곡 선택 화면을 가리지 않고 반영 |

각 대상의 상세 스키마는 기존 문서 모델에 같은 표현이 있는지 확인한 뒤 확정한다. 지원하지 않는 객체를 조용히 무시하고 완성으로 표시하는 것은 실패다. 화면 보정 V3~V5에서 구현하지 못한 객체는 결과 문서에 미완료로 명시하고 별도 체크리스트 작업으로 이어간다.

## 5. 검증 장면과 실패 기준

- 첫 실행, 1차 기본 설치 후 재실행, 사용자 편집 문서 설치, WIDE 유지, 프리셋 왕복의 다섯 설정 장면에서 문서·테마·배치가 서로 일치해야 한다.
- 선택 기본/옵션 열린 상태, 7키/14키 플레이의 최소 네 장면을 렌더하여 위 영역과 실제 표시가 일치해야 한다. 옵션 텍스트가 비치거나 재생 장식이 필드·BGA·그래프·수치를 통과하면 실패다.
- 성공 증거는 테스트 명령과 생성된 화면 파일로 남긴다. 화면을 확인하지 않고 컴파일·단위 테스트만으로 시각적 완료를 선언하지 않는다.
