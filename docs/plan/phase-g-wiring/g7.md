# G7 배선 지시 — 멀티 IR (`ir_ext.rs`)

> 갈래 소유 파일: `apps/rbms-player/src/ir_ext.rs`, `apps/rbms-player/src/ir_ext/tests.rs`, `docs/reference/ir-multi.md`, 이 문서.
> 규칙·계약 정본: [`docs/reference/ir-multi.md`](../../reference/ir-multi.md). 스펙: `docs/plan/2026-09-09-phase-g-spec.md` §10, 테스트 요건 §11 순서 12.
> 아래 8개 패치가 G7 이 호출부에 필요한 전부다. 라인 번호는 쓰지 않는다 — 전부 심볼 앵커다.

`MultiIr` 가 이미 제공하는 것(추가 구현 불필요): 프로필 목록 생성(`from_network`), 프로필별 클라이언트 생성(`build_servers` / `build_servers_reusing`), 병렬 제출 + 프로필 단위 실패 격리(`submit_all`), 워커 위임(`spawn_submit_all`), 랭킹 패널용 primary 선택(`primary_server` / `set_primary`), 상태 줄(`submit_summary`), 레거시 중복 제출 방지(`secondary`).

## 패치 2 — `apps/rbms-player/src/lib.rs`: `AppShared` 필드 3개

**위치**: `struct AppShared` 안, `submit_rx: Option<Receiver<SubmitOutcome>>,` 바로 아래.

```rust
    /// The score servers this play is submitted to, and which one the ranking panel reads.
    multi_ir: MultiIr,
    /// One client per profile, index-aligned with `multi_ir.profiles`.
    profile_servers: Vec<Arc<dyn ScoreServer>>,
    /// The extra profiles' fan-out, in flight. `server_url` itself goes through `submit_rx`.
    profile_submit_rx: Option<Receiver<Vec<ProfileResult<rbms_ir::SubmitResponse>>>>,
```

**근거**: 스펙 §10 의 "프로필 선택 축". 프로필 목록과 클라이언트는 프레임마다 다시 만들 수 없고(HTTP 클라이언트 생성 비용), 팬아웃 수신부는 요청이 시작된 화면보다 오래 산다 — `submit_rx` 와 같은 이유로 `AppShared` 에 둔다.

## 패치 3 — `apps/rbms-player/src/lib.rs`: 기동 시 초기화

**위치 A**: `App::new` 계열 생성자, `let built = build_server(&config, session.token().map(str::to_string));` 바로 아래. (`config` 가 아래에서 `AppShared` 로 move 되므로 반드시 그 전에 읽는다.)

```rust
    let multi_ir = MultiIr::from_network(&config.network);
    let profile_servers = multi_ir.build_servers_reusing(Some(built.server.clone()));
```

**위치 B**: 같은 함수의 `AppShared { .. }` 리터럴, `submit_rx: None,` 바로 아래.

```rust
                multi_ir,
                profile_servers,
                profile_submit_rx: None,
```

**근거**: `build_servers_reusing(Some(built.server))` 는 레거시 프로필 자리에 **이미 열린 메인 클라이언트**를 그대로 꽂는다. `build_servers()` 를 쓰면 같은 URL 로 HTTP 클라이언트가 두 벌 생기고 health 프로브와 랭킹 패널이 서로 다른 커넥션 풀을 쓰게 된다.

## 패치 4 — `apps/rbms-player/src/app_network.rs`: `rebuild_server` 에서 프로필 축도 갱신

**위치**: `impl AppShared` 의 `rebuild_server`, `self.server_probe_stop = built.probe_stop;` 바로 아래(함수 끝).

```rust
        self.multi_ir = MultiIr::from_network(&self.config.network);
        self.profile_servers = self.multi_ir.build_servers_reusing(Some(self.server.clone()));
```

**근거**: `rebuild_server` 는 SERVER URL 변경·로그인·로그아웃마다 호출된다. 이 두 줄이 없으면 URL 을 바꾼 뒤에도 프로필 0(레거시)이 옛 URL·옛 토큰의 클라이언트를 계속 들고 있어 제출이 조용히 이전 서버로 간다.

## 패치 5 — `apps/rbms-player/src/app_ranking.rs`: 팬아웃 시작과 수거

**위치 A**: `impl AppShared` 의 `spawn_score_submit` 바로 아래에 새 메서드.

```rust
    /// Submit the same run to every extra IR profile, in parallel and off the frame thread.
    ///
    /// `server_url` itself is left to [`AppShared::spawn_score_submit`] — it is the profile that
    /// also uploads the replay — so this fans out over [`MultiIr::secondary`] and never submits
    /// there twice. One profile failing does not touch the others' results.
    pub(crate) fn spawn_profile_submits(&mut self, submission: &ScoreSubmission) {
        let secondary = self.multi_ir.secondary();
        if secondary.enabled_profiles().next().is_none() {
            return;
        }
        self.profile_submit_rx = Some(spawn_submit_all(secondary, self.profile_servers.clone(), submission.clone()));
    }
```

**위치 B**: 같은 `impl` 의 `poll_ir_jobs`, `self.poll_submit();` 바로 아래.

```rust
        self.poll_profile_submits();
```

**위치 C**: 같은 `impl` 의 `poll_submit` 바로 아래에 새 메서드.

```rust
    fn poll_profile_submits(&mut self) {
        let Some(rx) = self.profile_submit_rx.take() else {
            return;
        };
        match rx.try_recv() {
            Ok(results) => self.net_status = submit_summary(&results),
            Err(TryRecvError::Empty) => self.profile_submit_rx = Some(rx),
            Err(TryRecvError::Disconnected) => self.net_status = "profile submit worker stopped".to_string(),
        }
    }
```

**근거**: 스펙 §10 의 "제출은 enabled 프로필 전부에 대해 병렬로, 실패는 프로필별로 격리". `secondary()` 를 쓰지 않으면 레거시 서버가 `spawn_score_submit` 과 팬아웃 양쪽에서 **중복 제출**된다(서버가 중복을 200으로 접더라도 요청이 두 배). 빈 팬아웃을 조기 반환하지 않으면 프로필이 없는(=기존과 동일한) 설정에서도 매 결과마다 스레드가 하나씩 뜬다.

## 패치 6 — `apps/rbms-player/src/app_result.rs`: 결과 화면에서 팬아웃 시작

**위치**: `match block_reason` 의 `None => { .. }` 팔, `let replay = recorded_replay.as_ref()...;` 다음 줄(= `shared.spawn_score_submit(sub, replay);` **바로 앞**).

```rust
            shared.spawn_profile_submits(&sub);
```

**근거**: `sub` 가 `spawn_score_submit` 으로 move 되므로 반드시 그 앞에서 빌려 쓴다. 이 팔에 두는 이유는 게이트를 공유하기 위해서다 — `block_reason`(오토플레이·리플레이·판정폭 확대·스크래치 어시스트, G4 가 추가하는 practice 포함)이 있는 런은 **어느 프로필로도 나가지 않는다**(결정 12). `server_url` 이 없는 팔(`None if ... server_url.is_none()`)에는 넣지 않는다: 그 경우 레거시 프로필 자체가 없고, `ir_profiles` 만 설정한 사용자는 아래 패치 7 의 판단을 따른다.

> **선택 사항**: `server_url` 없이 `ir_profiles` 만 쓰는 구성을 허용하려면 `None if shared.config.network.server_url.is_none()` 팔을 `None if shared.multi_ir.primary_server().is_none()` 로 바꾸고 그 팔에서도 `shared.spawn_profile_submits(&sub);` 를 부른다. 기본 동작(레거시 없으면 오프라인)을 유지할지는 G8 판단.

## 패치 7 — `apps/rbms-player/src/app_ranking.rs`: 랭킹 조회를 primary 프로필로

**위치**: `start_ranking_fetch` 안, `let rx = spawn_query(self.server.clone(), move |server| {` 의 첫 인자.

```rust
        let source = self.multi_ir.primary_server().and_then(|index| self.profile_servers.get(index).cloned()).unwrap_or_else(|| self.server.clone());
        let rx = spawn_query(source, move |server| {
```

**근거**: 스펙 §10 "랭킹 패널은 primary 프로필만 조회한다". `primary_server()` 는 primary 가 비활성이면 첫 enabled 프로필로, 하나도 없으면 `None` 으로 답하므로 `unwrap_or_else` 가 기존 단일 서버 동작을 그대로 보존한다. 라이벌 행·`player_best` 도 같은 `spawn_query` 안에서 도니까 자동으로 같은 서버를 본다.

패널에 프로필 탭을 붙일 때는 `self.multi_ir.labels()` 를 탭 라벨로, 탭 전환은 `self.multi_ir.set_primary(index)` 로 한다. `set_primary` 는 범위 밖 인덱스를 거부하므로 별도 방어가 필요 없다. 탭이 바뀌면 그 곡의 캐시 항목을 `self.ranking_cache.remove(&md5)` 로 지우고 다시 `start_ranking_fetch` 를 부른다 — 캐시 키는 md5 뿐이라 서버가 바뀌면 stale 이다.

**코스 랭킹(G3 와의 접점)**: `course_ir.rs` 의 조회·제출도 같은 `primary_server()` 로 서버를 고른다. `ScoreServer::course_ranking` 의 기본 구현 `Err(IrError::Unsupported)` 는 오류가 아니라 "이 서버는 코스 랭킹 없음"이므로 **패널을 숨기고 토스트를 띄우지 않는다**(스펙 §10).

## 패치 8 — 설정 행 (`crates/rbms-config/src/settings.rs`)

`NetworkOptions.ir_profiles` 필드는 G0 이 이미 넣었다. 남은 것은 행(descriptor)뿐이다.

1. `enum SettingId` 에 `Rivals` 바로 다음으로 `IrProfiles,` 추가.
2. `pub const SETTING_COUNT: usize = 79;` → `80`.
3. `SettingId::ALL`(선언 순서 배열)의 `SettingId::Rivals,` 다음에 `SettingId::IrProfiles,` 추가.
4. 행 정의: `row(SettingId::Rivals, ...)` 다음에

```rust
    row(SettingId::IrProfiles, SettingTab::Network, "IR PROFILES", SettingKind::Action, "Extra score servers this play is also sent to"),
```

5. `display_value` 의 NETWORK 분기에 `SettingId::IrProfiles => config.network.ir_profiles.len().to_string(),`.
6. NETWORK 탭 id 를 열거하는 `match`/배열(파일 내 `| SettingId::Rivals` 가 나오는 곳)에 `| SettingId::IrProfiles` 추가.
7. 행 순서를 고정한 테스트 2곳(`SettingId::Rivals,` 가 나오는 테스트 배열)에 같은 위치로 추가.
8. `Config::sanitise` 에 다음 한 줄 — 빈 URL 프로필은 영원히 `NotConfigured` 를 내므로 로드 시점에 버린다.

```rust
        self.network.ir_profiles.retain(|profile| !profile.base_url.trim().is_empty());
```

플레이어 쪽 값 표시: `apps/rbms-player/src/app_network.rs` 의 `network_setting_line` 에 `SettingId::IrProfiles => self.config.network.ir_profiles.len().to_string(),` 를 `SettingId::Rivals` 옆에 추가한다(라벨은 `network_row_label` 이 descriptor 에서 가져오므로 추가 작업 없음).

편집 UI 는 `stage/settings.rs` 의 RIVALS 모달과 같은 모양이면 충분하다(`enter_network_row` 의 `SettingId::Rivals` 팔 참고): 목록 + 추가/삭제 + 항목별 이름·URL·토큰·enabled. 편집을 커밋한 뒤 반드시 `shared.rebuild_server()` 를 부른다 — 패치 4 가 프로필 축을 그때 다시 만든다.

**근거**: 스펙 §10 "필드 추가는 G8 소유". 행이 없으면 사용자는 `settings.ron` 을 손으로 고치는 수밖에 없다.

## 패치 9 — `apps/rbms-player/src/ir_ext.rs`: `#![allow(dead_code)]` 제거

**위치**: 파일 상단 모듈 문서 바로 아래의 `#![allow(dead_code)]` 한 줄, 그리고 그 이유를 적은 모듈 문서 마지막 문단(`The module is complete but not yet called: ...`).

**근거**: 배선 전에는 모듈 전체가 미사용이라 `-D warnings` 를 통과하지 못해 넣어 둔 것이다. 패치 1~7 이 들어가면 불필요해진다. 남은 미사용 심볼이 있다면 그것은 배선이 덜 됐다는 신호이므로, allow 를 되살리지 말고 그 호출부를 마저 붙인다.
