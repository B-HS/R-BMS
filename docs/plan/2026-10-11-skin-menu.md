# SKIN 메뉴 — 설정값을 바꾸며 스킨을 미리 보는 독립 화면 (웨이브 9B) 설계서

> 작성 2026-10-11 · 상태: 구현 완료(골격 → P1 미리보기 엔진·P2 메뉴 화면 → 리뷰 발견 9건 수정과 통합). 이 문서는 최종 구현에 맞춰져 있다. 커밋 전(작업 트리 기준, f8ed260 이후). 웨이브 10C 에서 불투명도 행과 엔진 오프셋의 도움말을 더했다(§3 의 바닥 안내, §4, §4.1)
> 사용자 요청(원문): "Settings 에서 SKIN을 설정하는데 SKIN을 아예 설정에서 빼서 SKIN 이라는 메뉴를 만들고 preview형식으로 좌측에는 스킨설정값, 우측에는 skin preview로 보면서 수정할수있게해줘"
> 관련 문서: 사용자 설명 `docs/skin.md`, 스킨 사양 `docs/plan/2026-10-09-lua-skin-compat.md` §4, 조사 색인 `docs/reference/skin-compat/README.md`

## 1. 목표와 요구 사항

| # | 요구 | 판정 기준 |
| --- | --- | --- |
| R1 | SKIN 은 Settings 에서 빠지고 독립 화면이 된다 | Settings 탭 띠에 SKIN 이 없다. `Stage::SkinMenu` 가 내장 화면의 글꼴·색·1280x720 논리 좌표로 그려진다 |
| R2 | 왼쪽은 설정 행 전부, 오른쪽은 지금 고른 화면 종류의 미리보기 | 팩 폴더·화면 종류·문서·로드 상태·다시 읽기·초기화·옵션·파일·오프셋 행이 스크롤되는 목록에 있다. 미리보기는 16:9, 실제 스킨 렌더러가 그린다 |
| R3 | 미리보기는 지어낸 예시 데이터로 움직인다 | 선곡·결정·플레이(5/7/9/10/14키)·결과·코스 결과. 사용자의 라이브러리·점수·계정 이름을 읽지 않는다 |

| R5 | 문서가 없거나 읽기에 실패하면 이유를 글로 | 미리보기 자리에 한 줄 제목과 이유(세 줄까지). 팩 폴더가 없거나 팩의 Lua 스킨이 헤더부터 읽히지 않아 문서가 없는 경우도 그 사실을 말한다. Lua 실패가 앱을 멈추지 않는다 |
| R6 | 들어가는 길 셋, 나가는 길 하나 | 선곡 F12, 스킨의 SKIN 버튼(이벤트 14), Settings 의 바로 가기. Esc 로 왔던 화면에 돌아간다 |
| R7 | 키보드와 마우스 | ↑↓ 행 이동, ←→·Enter 값 변경, Shift+←→ 오프셋 열 칸, 0 오프셋 초기화, Tab 화면 종류, 행 왼쪽 클릭(앞으로)·오른쪽 클릭(뒤로), 휠 스크롤. Settings 의 `BUILT-IN SCREENS ONLY` 표지는 그대로 |
| R8 | 자원 수명 | 메뉴를 떠나면 텍스처·동영상·Lua 상태 해제. 화면 종류를 바꾸면 이전 것 해제. 화면당 텍스처 예산 유지. 미리보기는 소리를 내지 않는다. 메뉴를 연 화면(선곡)의 컴파일된 스킨은 주차된 채 남아 돌아간 첫 프레임에 그려진다 |
| R9 | 기존 동작 불변 | 실제 플레이·선곡, 내장 화면의 프레임, 오디오 시계, 판정 경로 |

## 4. 조작

| 입력 | 동작 | 비고 |
| --- | --- | --- |
| ↑ / ↓ | 행 커서 이동 | 커서가 보이도록 스크롤 |
| ← / → | 커서 행의 값을 한 칸 | 이전 Settings SKIN 탭의 `step` 과 같은 호출 |
| Shift + ← / → | 커서가 오프셋 행이면 열 칸, 불투명도 행이면 25%(`SkinLibrary::wide_steps_for`: 오프셋 10, 불투명도 5걸음) | 오프셋은 ±2000 범위이고 키 반복이 없다. 다른 행은 한 칸 그대로(옵션·파일은 한 칸마다 문서를 다시 읽으므로 묶지 않는다) |

| PageUp / PageDown | 커서를 한 화면(17행)씩 | |

### 4.1 오프셋 행과 불투명도 행 (웨이브 10C)

| 항목 | 내용 |
| --- | --- |
| 행의 종류 | `SkinLibrary::kind_for(config, screen, row) -> Option<SkinRowKind>`: `Property`, `File`, `Offset(축)`, `Opacity`. 알파 축만 허용한 오프셋(`is_opacity`: 여섯 축 가운데 `a` 만 참)이 `Opacity` 다. 이름 규칙에 기대지 않는다 |
| 불투명도 행의 표시 | 축 이름 없이 문서가 준 이름 그대로(`LANE BACKGROUND OPACITY`), 값은 퍼센트(`opacity_percent`: `100 + a * 100 / 255` 를 반올림해 0~200 으로 묶는다). 100% 를 넘으면 더해지는 알파를 붙인다(`105% (+13)`). ModernChic 은 알파 0 의 덮개에 양수를 더해 쓰는 알파 전용 오프셋이 다섯 개라 범위를 100% 에서 끊지 않았다 |
| 불투명도 행의 걸음 | 5%(`OPACITY_STEP_PERCENT`), Shift 로 다섯 걸음. 저장은 `opacity_alpha(퍼센트) = round((퍼센트 - 100) * 255 / 100)` 를 그 오프셋의 `a` 에. 5% 격자 밖의 저장값은 그 방향의 가장 가까운 격자로 간다(`stepped_opacity`). 저장 형식과 설정 판은 그대로다 |
| 행 순서 | `rows_for`: 옵션, 파일, 불투명도가 아닌 오프셋의 축별 행(문서 선언 순. 헤더가 선언 오프셋 뒤에 엔진 오프셋을 두므로 엔진 오프셋이 뒤), 불투명도 행. 불투명도는 선언 위치와 관계없이 끝에 모인다 |
| 엔진 오프셋 | `SkinLibrary::is_automatic_for`: 헤더 오프셋 목록의 끝 `automatic_offsets(type).len()` 개. 도움말만 다르다(`automatic_offset_help`). PLAY 메뉴는 이 구분으로 접이에 넣을 행을 정한다(`docs/plan/2026-10-11-play-menu.md`) |
| 미리보기 | 오프셋은 프레임마다 저장값에서 읽으므로 문서를 다시 읽지 않고 다음 프레임에 반영된다(`build_of` 불변) |
| 하지 않은 것 | 목록의 묶음 머리(옵션 / 파일 / 위치·크기 / 불투명도)와 머리 단위 이동, 불투명도의 1% 미세 걸음. 행 모델이 Settings 와 같은 `settings_rows` 이고 바닥 안내 줄에 낱말을 더 넣을 폭이 없다. 후속 |

## 5. 들어가고 나가는 길

| 길 | 구현 | 상태 |
| --- | --- | --- |

## 7. 미리보기 엔진

### 7.1 구조

| 결정 | 내용 | 이유 |
| --- | --- | --- |
| 앱의 스킨 기계를 그대로 쓴다 | 문서는 `AppShared.skins`, 컴파일·텍스처·동영상은 `AppShared.skin_screens`, 타이머는 `skin_timers`. 미리보기는 "예시 상태를 가진 또 하나의 화면"이다 | 읽기·디코드·예산·격리·폰트 페이지·동영상이 전부 기존 경로를 탄다. 따로 만들면 `with_skin_frame` 을 통째로 복제해야 한다 |

### 7.3 문서 로드·재로드·실패

| 사건 | 처리 | 상태 |
| --- | --- | --- |
| 화면 종류나 그 화면의 문서가 바뀜(`update` 가 감지) | 이전 종류의 Lua 문서를 놓고(`end_skin_preview_of`), `begin_skin_preview_scene`(타이머 초기화, 장면 시계 0, 그 화면의 Lua 문서만 만료. 주차된 화면과 다른 화면의 Lua 는 건드리지 않는다), 예시 상태 새로 | `Loading` |
| 문서를 처음 요청한 프레임 | 읽지 않고 `Loading` 만 답한다(`keep_skin_preview`). Lua 스킨 전체를 도는 무거운 프레임 전에 메뉴가 `LOADING THE SKIN` 을 먼저 그리게 한다 | `Loading` |
| 그다음 프레임들 | `prepare_skin_preview(canvas, screen)` → Lua 문서가 대기 중이면 예시 호스트로 읽고 → 디코드가 끝나 컴파일되면 사각형 안에 그린다 | `Loading` → `Drawn` |
| 옵션·파일·RELOAD·RESET | 메뉴가 기존 호출로 설정을 바꾸고 `reload_skin` 을 부른 뒤 `settings_changed`. 미리보기는 문서 상태(`DocumentState`: build 번호, 대기, stale)를 마지막으로 본 것과 비교해 달라졌을 때만 반응한다. 장면은 멈췄던 자리에서 이어진다 | `Loading`(어둡게) → `Drawn` |
| 문서·팩 변경 | 문서 경로가 달라져 다음 `update` 가 새 장면을 시작한다 | `Loading` → `Drawn` |
| 길이가 있는 장면이 끝남 | 같은 화면으로 새 장면. Lua 스킨은 실제 화면 진입처럼 다시 읽는다(2~3프레임) | `Loading`(어둡게) → `Drawn` |
| 오프셋 | 저장된 값을 매 프레임 읽으므로 다음 프레임에 반영. `OFFSET_ALL` 은 컴파일된 화면이 고정하므로, 저장값이 고정값과 다르면 `resettle_skin_preview_whole_offset`(`SkinScreen::forget_whole_offset`)로 다음 프레임에 다시 읽게 한다. 문서도 화면도 다시 만들지 않는다 | `Drawn` 유지 |
| 문서 없음 | `skins.document_path` 가 `None` 이고 팩에 문제가 없다 | `Absent(NoDocument)` |
| 문서 없음, 팩 폴더가 디스크에 없음 | `SkinLibrary::pack_trouble` 이 `THE PACK FOLDER IS NOT THERE` 를 답한다. PACK FOLDER 행 값 앞에 `(MISSING) ` | `PackTrouble(이유)` |
| 문서 없음, 팩의 Lua 스킨이 헤더부터 읽히지 않음 | `pack_trouble` 이 `<파일> DID NOT READ (header pass): <이유>`(파일 이름순 첫 파일, 팩 폴더 경로 제외, 여럿이면 `(AND N MORE)`)를 답한다. 헤더가 없으면 어느 화면의 문서인지 알 수 없으므로 문서가 없는 모든 화면에서 같은 문구다 | `PackTrouble(이유)` |
| 지원하지 않는 화면 종류 | `is_supported_skin_type` 이 거짓 | `Absent(UnsupportedScreen)` |
| 읽기 실패(Lua 오류, 예산 초과, 파일 없음) | 라이브러리가 실패를 기록(`has_failed`), 다시 시도하지 않는다. 미리보기 자리의 이유는 `SkinLibrary::failure_line`: 이유의 첫 줄에서 문서 폴더 경로를 뺀 것(파일 이름으로 시작). LOADED 행은 `info()`: 첫 줄 전문(경로 포함, 스택 트레이스 없음). 알림은 `skin <파일> did not load: <이유>` | `Failed(이유)` |
| 프레임 바인딩 실패 | 인터프리터가 말한 이유의 첫 줄 | `Failed(이유)` |
| 디코드가 10초를 넘김 | 기존 `SCENE_HOLD_LIMIT`. 문서는 올 때까지 `Loading` | `Loading` |

- Lua 문서 읽기는 기존과 같이 프레임 루프에서 한 번에 돈다(로더 예산 안). 그 한 프레임이 길어질 수 있고(릴리스 실측 ModernChic 선곡 최장 25.8ms), 디코드는 작업자가 하므로 그 뒤로는 멈추지 않는다.
- 매 프레임의 Lua 호출은 기존 프레임 예산(`runtime.frame`)에 묶인다.
- 어두운 대기: 방금까지 프레임이 그려지던 문서를 다시 읽는 동안(`on_show`) 미리보기는 `waits_in_the_dark()` 를 참으로 답하고 메뉴는 상태 패널 대신 사각형을 검게 채운다. 끝난 장면은 검정으로 페이드했으므로 이어 보인다. 기다림이 0.5초(`QUIET_WAIT_SECONDS`, `update` 가 받은 `dt` 의 합)를 넘으면 `LOADING THE SKIN` 을 보인다. 이때는 요청 직후의 "읽지 않는 프레임"도 건너뛴다.

### 7.4 수명·예산·무음

| 항목 | 규칙 |
| --- | --- |
| 화면 종류 변경 | 새 장면을 시작하고 이전 종류는 부르지 않는다 → 다음 `finish_skin_frame` 이 컴파일된 화면·동영상을 놓고, 아무도 잡지 않은 텍스처를 쓸어 낸다. 이전 종류의 Lua 문서(인터프리터)는 그 자리에서 버린다(`SkinLibrary::drop_scripted_for`) |
| 메뉴를 떠남 | `release` 가 예시 상태와 미리본 화면의 Lua 문서를 버린다 → 그 화면을 실제로 그릴 때 자기 상태로 다시 읽는다. 컴파일된 미리보기 화면은 다음 프레임에 놓인다 |
| 메뉴 아래의 화면(선곡) | 미리보기는 주차를 풀지 않는다(`begin_skin_scene` 대신 `begin_skin_preview_scene`). 컴파일된 화면·텍스처·Lua 상태가 남아 Esc 로 돌아간 첫 프레임에 그려진다(Settings 왕복과 같다). 그 화면 자신을 미리본 경우에만 예시 상태로 다시 읽었으므로 돌아갈 때 다시 읽는다. 메뉴 아래 장면이 내던 스킨 소리도 끊지 않는다 |
| 텍스처 예산 | 화면당 1 GiB(`SKIN_TEXTURE_BUDGET_BYTES`)와 최대 변 길이. 기존 풀을 쓰므로 그대로. 주차된 화면과 미리보는 화면은 각각 자기 예산이다 |
| 무음 | 미리보기 프레임은 `host.take_calls()` 를 버린다. 소리·이벤트·쓰기 어느 것도 `finish_skin_frame` 으로 가지 않는다. 예시 플레이는 오디오 스트림을 열지 않는다 |
| 포인터 | 미리보기 프레임은 입력 지도를 남기지 않는다(`keep_input_map` 을 부르지 않는다) |

| CPU 캔버스 | 변경 없음 | `CpuCanvas::push_clip` 이 기존 통로 |
| wgpu | 변경 없음 | `Gpu::push_clip` → scissor 가 기존 통로 |

`Renderer` 트레이트 자체는 바꾸지 않았다. 이동은 어댑터의 산술이고 잘라내기는 양쪽에 이미 있던 clip 이라, 두 백엔드가 같은 그림을 낸다(테스트가 헤드리스와 GPU 프레임을 비교한다).

미리보기에서 지켜야 할 것

- 오프셋의 단위 환산(`DocumentOffsets::drawn_at`)과 Lua 에 알리는 창 크기(`host.window`)에는 사각형이 아니라 창 전체 크기를 준다. 오프셋 N 픽셀이 실제 화면에서 차지하는 비율이 미리보기에서도 같아진다.
- 포인터 위치(`SkinFrame.mouse`)는 `None`.

## 8. 경계 API

`apps/rbms-player/src/skin_preview.rs`

| 항목 | 시그니처 | 계약 |
| --- | --- | --- |
| 생성 | `SkinPreview::new() -> SkinPreview` | 아무것도 읽지 않는다 |
| 갱신 | `update(&mut self, ctx: &mut FrameCtx<'_>)` | 메뉴의 `update` 에서 프레임마다 한 번. `config.skin.screen` 이나 그 화면의 문서가 바뀌었으면 새 장면, 아니면 예시 상태를 `ctx.dt` 만큼 진행(프레임이 그려진 동안만, 프레임당 0.1초까지) |
| 그리기 | `draw(&mut self, ctx: &mut FrameCtx<'_>, canvas: &mut Canvas<'_>, rect: Rect) -> &PreviewStatus` | 메뉴의 `draw` 에서, 메뉴가 clear 한 뒤 한 번. `rect` 는 1280x720 좌표. `Drawn` 이 아니면 아무것도 그리지 않았다 |
| 상태 | `status(&self) -> &PreviewStatus` | 마지막 `draw` 의 결과 |
| 어두운 대기 | `waits_in_the_dark(&self) -> bool` | 참이면 메뉴는 상태 패널 대신 사각형을 검게 둔다(§7.3) |
| 변경 통지 | `settings_changed(&mut self, shared: &mut AppShared)` | 메뉴가 설정을 바꾸고(필요하면 `reload_skin` 까지 부른 뒤) 호출. 무엇이 바뀌었는지는 미리보기가 저장소에서 읽는다 |
| 해제 | `release(&mut self, shared: &mut AppShared)` | 메뉴의 `on_exit`. 여러 번 불러도 된다. 뒤이은 `update`·`draw` 는 처음부터 다시 |
| 상태 값 | `PreviewStatus::{Loading, Drawn, Absent(PreviewAbsence), PackTrouble(String), Failed(String)}`, `PreviewAbsence::{NoDocument, UnsupportedScreen, NoPreview}` | `is_drawn()`, `message() -> Option<&'static str>`(제목), `detail() -> Option<&str>`(이유. 한 줄이고 제어 문자가 없다) |
| 사각형 통로 | `region::with_region<'a, T>(canvas: &mut Canvas<'a>, rect: Rect, draw: impl FnOnce(&mut RegionRenderer<'_, NativeCanvas<'_, 'a>>) -> T) -> T` | §7.5 |

`AppShared` 쪽 통로(`skin_screen/preview.rs`): `draw_skin_preview`, `begin_skin_preview_scene(screen)`, `end_skin_preview_of(screen)`, `prepare_skin_preview(canvas, screen)`, `keep_skin_preview(screen)`, `resettle_skin_preview_whole_offset(screen)`, `skin_preview_is_ready(screen)`. `SkinLibrary` 에 더한 것: `failure_line`, `pack_trouble`, `expire_scripted_for`, `drop_scripted_for`. `rbms-render` 에 더한 것: `RegionRenderer`, `SkinScreen::forget_whole_offset`.

소유: 설정을 쓰는 것과 라이브러리에 다시 읽기를 요청하는 것은 메뉴(P2). 문서를 읽고 컴파일하고 그리는 것, 장면·예시 상태는 미리보기(P1). 상태 문구를 화면에 쓰는 것은 메뉴, 문구 자체는 `PreviewStatus`(P1 파일, 골격에서 확정).

## 13. 남은 위험

| 위험 | 대응 |
| --- | --- |
| Lua 문서를 읽는 한 프레임이 길다 | 기존 화면과 같은 동작. 처음 읽을 때는 `Loading` 을 먼저 한 프레임 그린 뒤 읽는다. 작업자 스레드로 옮기는 것은 범위 밖 |
| 미리보기가 읽은 Lua 문서가 실제 화면에 남는다 | 미리보는 화면을 떠날 때와 `release` 때 그 화면의 Lua 문서를 버린다(`drop_scripted_for`). 테스트: 메뉴 아래 화면을 미리본 뒤에는 다시 읽기가 예약되고, 미리보지 않았으면 같은 build 로 첫 프레임에 그려진다 |
| 옵션·파일 변경으로 같은 문서를 다시 읽을 때 플레이 예시의 타이머 드라이버 설정(판정 영역 수, 봄 판정 기준)은 첫 읽기 것이 유지된다 | `SkinFeed::adopt_skin` 이 한 번만 받는다. 판정 영역 수를 바꾸는 옵션이 있는 스킨에서만 드러나고 장면이 다시 시작하면(약 31초 주기, 또는 화면 종류를 바꿨다 돌아오면) 맞는다. 후속 |
| 반복 재시작과 옵션 변경 때 2~3프레임이 검다 | Lua 를 다시 읽는 동안 그릴 화면이 없다. 재시작 때 Lua 를 다시 읽지 않으면 없앨 수 있지만 Lua 내부 상태가 반복 사이에 남는다(스킨이 한 번만 켜는 플래그 등). 실제 화면 진입과 같은 쪽을 택했다 |
| 헤더가 읽히지 않는 팩 스킨의 문구가 문서 없는 모든 화면에 나온다 | 헤더가 없으면 어느 화면의 문서인지 알 수 없다. 문구가 파일 이름으로 시작하므로 무엇을 고칠지는 분명하다 |
| 예시 `PlaySession` 이 오디오 경로를 건드린다 | 오디오 스트림을 열지 않는다. 테스트: 예시 플레이 뒤 `shared.audio` 가 `None` |
| 65% 크기에서 작은 글자가 뭉개진다 | 스킨 렌더러의 기존 필터 그대로. 창을 키우면 미리보기도 커진다 |
| 왼쪽 384px 에 긴 옵션 이름이 안 들어간다 | `fit_text` 로 자르고 커서 행의 전문을 `INFO_RECT` 에 쓴다. 경로(PACK FOLDER)는 앞을 줄여 폴더 이름을 남긴다 |
| LETTERBOX 를 끈 16:9 가 아닌 창에서 미리보기가 16:9 가 아니다 | 메뉴 전체가 창 모양으로 늘어나며 미리보기도 같이 늘어난다. 실제 스킨 화면이 그 창에서 그려지는 모양과 같다. 수동 확인 G7 |
| 실제 창의 시스템 글꼴이 내장 글꼴보다 넓으면 Settings 의 `SKIN MENU >` 단추가 패널 오른쪽으로 밀린다 | 겹치지는 않는다. 수동 확인 G1 |
