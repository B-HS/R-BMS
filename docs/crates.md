### rbms-model
- **Role**: The foundational data-model crate for the rbms BMS rhythm-game project. It defines the in-memory chart representation (notes, timelines, song metadata, hashes) and the play-mode profiles, with all engine-agnostic timing constants. It contains pure data + lookup logic only; no parsing, audio, or rendering.
- **Public API**:
  - `Micros` — `i64` type alias; the global absolute-time unit in microseconds.
  - `US_PER_MEASURE_NUM` — `f64` const `240_000_000.0`; numerator of the `240_000_000 / bpm` measure-length invariant.
  - `measure_us(bpm: f64) -> f64` — microseconds per 4/4 measure at `bpm` (`US_PER_MEASURE_NUM / bpm`).
  - `LnKind` — enum `Ln | Cn | Hcn`; long-note flavor.
  - `NoteKind` — enum `Normal | LongStart { ln } | LongEnd { ln } | Mine { damage: f64 }`.
  - `NoteKind::counts_as_playable_note()` and `count_playable_notes(model) -> usize` — the one definition of the note count (the reference `TimeLine.getTotalNotes`): a normal note and a long-note head count 1, a long-note tail counts only for a CN/HCN, a mine counts 0. Everything that shows or uses a chart's note count goes through it; the BMSON conversion uses it too. It describes a decoded model in which every head has its tail and nothing sits between them, which `rbms-chart` guarantees.
  - `Note` — a single note: `kind`, `wav: i32`, `start_us`, `duration_us`, `time_us`, `section: f64`, plus `layered: Vec<Note>` for stacked notes. `Note::normal(wav, time_us, section)` builds a `Normal` note with long-note fields zeroed.
  - `TimeLine` — one timing row: `time_us`, `section`, per-lane `notes`/`hidden` (`Vec<Option<Note>>`), `bgnotes: Vec<Note>`, `section_line: bool`, `bpm`, `stop_us`, `scroll`, `bga: i32`, `layer: i32`. `TimeLine::empty(lanes, time_us, section, bpm)` allocates `None`-filled lane vectors with default scroll `1.0`, `bga`/`layer` `-1`.
  - `ModelMeta` — song metadata (title, subtitle, artist, subartist, genre, play_level, difficulty, rank, total, stagefile); `Default` zeroes/empties all.
  - `Model` — top-level chart: `mode`, `meta`, `wavmap`/`bgamap: Vec<String>`, `init_bpm`, `timelines: Vec<TimeLine>`, `md5`, `sha256`.
  - `Mode` (re-exported from `mode`) — a play-mode profile struct: `name`, `key`, `player`, `scratch: &[usize]`, `channel_assign: &[i8; 18]`.
  - `Mode` constants `BEAT_7K`, `BEAT_5K`, `BEAT_10K`, `BEAT_14K`, `POPN_9K`, and `Mode::ALL` slice.
  - `Mode::is_scratch(lane) -> bool` — is this logical lane a scratch lane.
  - `Mode::lane_of_raw(raw) -> Option<usize>` — maps a raw 18-wide channel index to a logical lane.
- **Key invariants & algorithms**:
  - **Measure-length invariant**: `measure_us(bpm) = 240_000_000 / bpm`. This is the core timing constant; `240_000_000` is microseconds per measure at 1 BPM (4 beats × 60s × 1e6). It is NOT guarded — see gotchas.
  - **Channel mapping is data, not code**: `channel_assign` is a fixed 18-entry table indexed by a raw channel where P1 occupies raw `0..9` and P2 occupies raw `9..18`. Value `-1` means "ignored"; any other value is the logical lane. New key modes are intended to be added as new `Mode` constants/tables only, never by branching engine logic.
  - **`lane_of_raw` algorithm**: returns the table value only when `0 <= value < self.key`, else `None`. `key` therefore both bounds owned lanes and is what makes a 7K mode (`key 8`) ignore the P2 lanes that 14K (`key 16`) keeps — the same `BEAT7`/`BEAT5` tables are shared across 1P and 2P modes, with `key` selecting how many lanes are live. Out-of-range raw (>=18) yields `None`.
  - **Shared tables**: `BEAT7` is shared by `BEAT_7K` (key 8) and `BEAT_14K` (key 16); `BEAT5` by `BEAT_5K` (key 6) and `BEAT_10K` (key 12); `POPN` by `POPN_9K` (key 9). Scratch lanes: 7K→`[7]`, 5K→`[5]`, 10K→`[5,11]`, 14K→`[7,15]`, popn→`[]`.
  - **Note time fields**: `time_us` is the note's absolute play time; `section` is its measure-relative position; `start_us`/`duration_us` are populated only for long notes (zeroed by `Note::normal`). `layered` holds stacked/overlaid notes at the same position.
  - **TimeLine defaults**: `scroll` defaults to `1.0`, `stop_us` to `0`, `bga`/`layer` to `-1` (sentinel for "none"), `section_line` to `false`. `notes` and `hidden` are independently allocated `Vec<Option<Note>>` of length `lanes`.
- **Gotchas / edge cases**:
  - `measure_us` is intentionally unguarded: BPM `0.0` returns `+inf` (positive), and negative BPM returns a negative length (e.g. `-120.0 → -2_000_000.0`). Both are pinned by tests and flagged in-code as "suspect" — do not add guards without checking callers/tests.
  - `Note::wav`, `time_us`, and `section` accept and preserve negative values (no validation).
  - `lane_of_raw` is total over all `usize` inputs (out-of-range, `usize::MAX` → `None`) because it uses `slice::get`.
  - `Mode::ALL` has exactly 5 entries; tests assert distinct names, `player ∈ {1,2}`, 2-player scratch modes have exactly 2 scratch lanes, and scratch lanes are `< key` and reachable via `lane_of_raw`.
  - Every logical lane `0..key` is produced by exactly one raw index (a pinned bijection invariant) — breaking the table's uniqueness/coverage fails tests.
  - `NoteKind::Mine` carries `f64 damage`, so `NoteKind` is `PartialEq` but not `Eq`; `LnKind` and `Mode` are `Eq`.
- **Tests**: Inline `#[cfg(test)] mod tests` in both files. `src/lib.rs` covers the `measure_us` invariant (known values, monotonicity, inverse proportionality, zero/negative BPM), `TimeLine::empty` defaults/lane allocation/independence, `Note::normal` zeroing and negative-value preservation, enum equality, `ModelMeta::default`, and `Note` clone round-trip. `src/mode.rs` covers exhaustive `lane_of_raw` maps for all 5 modes (raw `0..18`), out-of-range raw handling, `lane_of_raw`-vs-`key` invariants, the full-key-range bijection, `is_scratch` behavior, `channel_assign` self-consistency (no duplicate lanes, `-1`-only sentinel, P1-group values `< key`), and `Mode` constant invariants (distinct names, key counts, value equality, player/scratch-count rules).

### rbms-parser

- **Role**: Pure lexical/structural parser for BMS-family charts (`.bms`/`.bme`/`.bml`/`.pms`). Turns raw file bytes into a `BmsSource` (headers, resource maps, per-measure channel objects) plus content hashes, resolving `#RANDOM`/`#IF` control flow but doing no timing/BPM integration.

- **Public API**:
  - `parse(bytes: &[u8]) -> BmsSource` — parse with default options (seed 0).
  - `parse_with(bytes, opts: ParseOptions) -> BmsSource` — parse with an explicit `random_seed`.
  - `ParseOptions { random_seed: u64 }` — only knob; `Default` is seed `0`.
  - `BmsSource` — top-level result: `headers`, `wav`/`bmp` (`BTreeMap<u32,String>`), `bpm_def`/`stop_def`/`scroll_def` (`BTreeMap<u32,f64>`), `measures: BTreeMap<u32,Measure>`, `base: u32`, `md5`, `sha256`.
  - `Headers` — all `#`-header scalar fields (title, artist, `init_bpm`, `rank`, `total: Option<f64>`, `lnobj: Option<u32>`, `lntype`, `lnmode`, `difficulty`, etc.) with a non-trivial `Default`.
  - `Measure { rate: f64, channels: Vec<ChannelData> }` and `ChannelData { channel: u32, objects: Vec<Obj> }`.
  - `Obj { num, den, c0, c1 }` — one placed token; `value(base)`/`value16()` decode the pair, `pos()` returns `num/den` as `f64`.
  - `digit(c: u8, base: u32) -> Option<u32>` and `parse_pair(c0, c1, base) -> u32` (re-exported from `base.rs`) — radix decoding for 2-char tokens.

- **Key invariants & algorithms**:
  - **Base 36 vs 62**: default `base` is `36`. It is upgraded to `62` only by a `#BASE 62` directive — detected in a *first pre-pass* over all lines (so it applies regardless of where the directive sits), and again in the header handler. In base 62 lowercase `a..z` map to `36..61`; otherwise lowercase aliases uppercase (`a..z` == `10..35`).
  - **Channel codes are always parsed in base 36** (`parse_data_line` calls `parse_pair(b[3],b[4],36)`), independent of `src.base`. Object *values* are stored raw (`c0`,`c1`) and decoded lazily via `Obj::value`.
  - **Channel 2 = measure length scale** (`#xxx02`): parsed as a single `f64` into `Measure.rate` (default `1.0`), not as objects.
  - **Object placement**: data string is split into 2-char tokens; `len = chars/2`. Each token at index `i` becomes `Obj { num: i, den: len }`, so position is `i/len`. `00` tokens and tokens with non-ASCII or non-base-36 digits are skipped. Empty channels are not pushed.
  - **Control flow (`control.rs`)**: deterministic LCG RNG seeded with `seed.wrapping_add(0x9E3779B97F4A7C15)`; `next_rng` is the classic `6364136223846793005 * x + 1442695040888963407`, returning `rng >> 33`. `#RANDOM n`/`#RONDAM` draw `1..=n` (n==0 -> 1); `#SETRANDOM` forces a value. `#IF`/`#ELSEIF`/`#ELSE`/`#ENDIF` use a `Frame` stack with `active`/`matched` flags; `current_random` reads the nearest enclosing `Random` frame; nesting honored via `active_excluding`. `handle()` returns `true` for any control line (consumed); non-control lines are skipped entirely when `ctrl.active()` is false.
  - **Header dispatch**: head/rest split on first whitespace, head uppercased. Indexed resources keyed by fixed-length head: `#WAVxx`/`#BMPxx`/`#BPMxx` (len 5, id from bytes 3..4), `#STOPxx` (len 6, bytes 4..5), `#SCROLLxx` (len 8, bytes 6..7). `#BPMxx`/`#STOPxx`/`#SCROLLxx` only insert when `rest` parses as `f64`.
  - **Lines** end where the reference's `BufferedReader.readLine` ends them: at `\n`, at a lone `\r` and at `\r\n` (`reference_lines`), so a chart saved with old Mac line ends is read line by line, not as one long title with no notes. Each line is then trimmed of Unicode whitespace at both ends before it is looked at, which the reference does not do (`reference-divergences.md`, "줄 앞 공백").
  - **Hashing**: `md5` and `sha256` are computed over the **raw input bytes** (before any decode), lowercase hex.
  - **Text decode (`encoding.rs`)**: one encoding is chosen for the whole file, because the keysound and image names are in the same encoding as the title. In order: a UTF-16 byte order mark is believed; well-formed UTF-8 is UTF-8 with or without the mark; bytes behind a UTF-8 mark that are not well-formed stay UTF-8 while the byte sequences that are no UTF-8 character do not outnumber the non-ASCII characters that are (`mostly_utf8`: one damaged character costs that character, not every name in the file); everything else is Shift_JIS or EUC-KR (`detect_legacy`). The two legacy encodings are told apart by scoring what kind of character each pair of bytes would be in each reading, not by "which one decodes" (about half of all Shift_JIS charts are also well-formed code page 949). A tie stays Shift_JIS. `decode_text` is the only entry point; nothing of the module is public. `PARSER_VERSION` in `rbms-library` is 5: 2 made a library scanned by the Shift_JIS-only parser read again once, 3 does the same for the note counts the decoder changed when it began settling long notes (`rbms-chart`), 4 for `#TOTAL` read as Java reads a number, and 5 for lone `\r` line ends and the `#TOTAL` line cut as the reference cuts it.

- **Gotchas / edge cases**:
  - `parse_pair` is lenient: a bad digit silently contributes `0` (via `unwrap_or(0)`), so malformed pairs decode rather than error.
  - `is_data_line` requires `len >= 6`, three leading ASCII digits, and a `:` at byte index 5 — channel chars at 3..4 are *not* validated here, so a non-base-36 channel still routes to data parsing (and `parse_pair` will fold the bad digit to 0).
  - Measure index is computed only from the first three digit bytes (`xxx`), so it caps at `999`.
  - `#PLAYER`/`#RANK`/`#BPM`/`#LNTYPE`/etc. fall back to `Default`-ish literals on parse failure (`unwrap_or`), e.g. `init_bpm` -> `130.0`, `rank` -> `3`, `player` -> `1`. `#LNOBJ` instead becomes `None` on failure. `#TOTAL` is read as the reference's `CommandWord.TOTAL` reads it: a number Java's `Double.parseDouble` takes (a trailing `d`/`f` read past, `Infinity`/`NaN` spelled Java's way, no hexadecimal) and above zero sets it, and any other line is passed over and leaves what an earlier line set, `None` when none did (`parse_java_double`). The line is matched and cut as the reference's `CommandWord` dispatch does, not by the header dispatch above: `#TOTAL` is a case-blind prefix of the line, the one character after it is passed over whatever it is (`#TOTAL:300` and `#TOTALS 300` read 300), and the rest is trimmed as Java's `String.trim` trims, of characters up to U+0020 only (a trailing `0x1A` or NUL goes, a trailing ideographic or no-break space stays and leaves a number Java cannot read) (`TOTAL_COMMAND`, `reference_total_argument`).
  - `#LNOBJ` is decoded with the *current* `src.base`; only the first 2 bytes of `rest` are used.
  - Object `den` equals the token count of that single channel line; multiple lines on the same channel/measure are stored as separate `ChannelData` entries (not merged), each with its own `den`.

- **Tests**: `#[cfg(test)] mod tests;` declared at the bottom of `lib.rs` (lives in a sibling `tests.rs` / `tests/` module under `crates/rbms-parser/src/`). Expect coverage of radix decoding (base 36/62), data-line object placement and `00`-skipping, channel-2 rate, header parsing/defaults, hash stability, and `#RANDOM`/`#IF` branch selection determinism under a fixed seed.

### rbms-chart
- **Role**: Converts a parsed `BmsSource` into a playable, timed `Model` (lane assignment, note/LN/mine/BGA/BPM/STOP/SCROLL resolution, absolute-time stamping) and provides the derived gameplay math: note-density stats, scroll/offset geometry, and deterministic lane-shuffle ("note option") transforms.
- **Public API**:
  - `detect_mode(src, filename) -> Mode` — infer play mode from used channels + extension (`.pms`→POPN_9K, P2 channels→14K, keys 6/7→7K else 5K).
  - `to_model(src, mode) -> Model` — main builder: events→sorted timelines→`assign_times`, plus meta/wavmap/bgamap/hashes.
  - `count_playable_notes(model) -> usize` — re-export of the `rbms-model` definition: excludes mines, a plain LN/Normal counts **1** (its tail is excluded), a CN/HCN counts **2** (head + the release end, judged separately). The judge engine's `total_notes` equals it for every decoded model because the decoder settles long notes (below); `crates/rbms-play/tests/note_count.rs` pins that.
  - `struct NoteDensity { bins, peak, avg, end }` + `note_density(model, total_value) -> NoteDensity` — per-second density histogram and the three scalar readouts (reference port).
  - `scroll::LaneGeometry { hu, hl }` with `height()` — lane pixel geometry (`hl`=judgment line, `hu`=top edge).
  - `scroll::green_number(bpm, hispeed, scroll, lanecover) -> f64` — IIDX green number (lane traversal ms).
  - `scroll::closed_form_offset(...)` — closed-form pixel offset above the judgment line (fast path / test oracle).
  - `scroll::visible_offsets(timelines, microtime, hispeed, lane_height)` — FLOATING scroll: exact BPM/SCROLL/STOP segment walk, returns `(timeline_index, pixel_offset)`.
  - `scroll::constant_offsets(...)` — CONSTANT (green-number-fixed) scroll, BPM-independent.
  - `shuffle::NoteOption` (8 variants `Off/Mirror/Random/SRandom/RRandom/Rotate/HRandom/AllScratch`) with `ALL`, `label()`, `from_str()`.
  - `shuffle::lane_permutation(option, mode, seed) -> Vec<usize>` — whole-chart `perm[old]=new` (MIRROR/RANDOM/R-RANDOM/ROTATE).
  - `shuffle::apply(model, option, seed)` — apply an option in place (dispatches per-row options to internal walkers).
- **Key invariants & algorithms**:
  - `SECTION_EPS = 1e-7`: events whose fractional `section` differ by less than this collapse into one `TimeLine`; events are sorted by `section` before timelines are built, and `to_model` emits one bar-line `TimeLine` per measure.
  - Channel→role map in `role()` uses decimal-parsed channel numbers (e.g. 37–45 = base-36 `11`–`19` key lanes, 73–81 = P2, `1020`=SCROLL ch `SC`); P2 lanes add `+9` to the raw lane index. Unknown lanes → `Role::Ignore`.
  - Time math in `assign_times`: `dt_us = 240_000_000 * Δsection / prev.bpm`; STOP µs = `240_000_000 * s / (192 * bpm)`; non-positive/zero BPM falls back to prior bpm, init bpm defaults to **130** if `≤0`. STOP accumulates additively into `stop_us` and is added to the *previous* segment when advancing.
  - LN handling: `#LNOBJ` converts the *prior* normal note in that lane into a `LongStart`/`LongEnd` pair (tracked via `last_normal`); channel-based LNs (181–225) pair up per lane in `long_note.rs` (`LnLane`), after the reference `Section`: objects alternate head, tail; a normal note under the head's tick plays as background unless it is the head's own sample; at the tail every note strictly between head and tail leaves the lane (normal notes become background sounds, mines and anything else are dropped); an object on the tick the lane's previous long note ended on is swallowed together with its partner; a head the chart never closes is removed. `long_note::repair` then enforces the shape on every lane (heads and tails alternate, nothing between them, no unclosed head) for what the event pass cannot see, such as a tail overwritten by another object. The result is a model with no overlapping note and no unpaired half, so `count_playable_notes`, the judge engine and the song database count the same notes. `#LNMODE` 2→Cn, 3→Hcn, else Ln — the kind is recorded on the note and now drives judging: `rbms-judge` scores a CN/HCN as two judgments (head + release end) vs a plain LN's one (see that crate). Known differences from the reference: a normal note listed after the tail in a later channel line of the same measure is swept here and survives there; an orphan `#LNOBJ` object stays a normal note here and is dropped there (`docs/acknowledge/reference-divergences.md`).
  - `note_density`: bins sized from the last *note-bearing* timeline (not the trailing bar-line) +2; 7-category per-second array (scr/key × LN-head/body/normal + mine). `peak`=busiest second; `avg`=mean over seconds ≥ `total_notes/bins/4`; `end`=max 5-second-window density after the gauge "border" (`total_notes*(1-100/total_value)`). `total_value ≤ 0` ⇒ standard-BMS default `(7.605*N/(0.01*N+6.5)).max(260)`.
  - Scroll: `visible_offsets` integrates segments exactly and freezes during STOP (full segment height held); `constant_offsets` uses `pps = hispeed*lane_height/2_000_000` and is calibrated so CONSTANT == FLOATING at 120 BPM. Both binary-search `microtime`, emit only future timelines (`i>cur`), and break once `y > lane_height`. Negative `scroll` flips offset sign.
  - Shuffle: deterministic xorshift64 `Rng` (seed 0 remapped to `0x9E3779B97F4A7C15`); scratch lanes never move under key shuffles; DP shuffles stay within a player side (no P1↔P2 crossing — that FLIP is unimplemented). Per-side seed is `seed + side * GOLDEN`. Anti-jack windows: `HRAN_THRESHOLD_US = 125_000` (ceil(15000/120)ms) for key lanes, `SCRATCH_THRESHOLD_US = 40_000` for the scratch lane under ALL-SCRATCH. Long notes are pinned head→tail to the same remapped lane across all options.
- **Gotchas / edge cases**:
  - ALL-SCRATCH / H-RANDOM concentration is a *preference, not a guarantee*: jacks closer than the threshold spill back to key lanes, so tests only assert `>= a few`, not exact placement.
  - `lane_permutation` returns the **identity** for `Off/SRandom/HRandom/AllScratch` — their real work is per-row inside `apply` (don't assume the perm reflects the final layout).
  - `apply_perm`/per-row walkers only act on timelines whose `notes.len()` equals `mode.key`; mismatched rows are skipped silently.
  - Note count is invariant under every option (heavily test-pinned), including dense full rows where notes exceed fresh lanes — the loop falls back to the source lane (`s`) when the pool is exhausted, so it never panics or drops notes.
  - Mine notes use `Note::normal(0,0,..)` with `kind` overwritten to `Mine` and lane wav `0`; mines are excluded from `count_playable_notes` and density note totals, and a plain LN's tail is excluded too — but a CN/HCN end *is* counted (the charge note's separately-judged release).
  - `BgaBase` and `BgaPoor` both map to `EvKind::Bga` (POOR currently shares the base BGA channel handling).
- **Tests**: `lib.rs` has `#[cfg(test)] mod tests;` (external `tests.rs` file, not shown). `scroll.rs` in-file tests cross-check the segment walk vs. closed form under constant BPM, hi-speed/BPM/scroll linearity, STOP freezing, green-number guards, and the future-only/break-at-height window behavior. `shuffle.rs` in-file tests pin: `from_str`/`label` round trips, per-mode bijection + scratch-fixed permutations, DP side isolation, note-count preservation across all options for 5K/7K/9K/10K/14K, LN head/tail alignment, ALL-SCRATCH concentration, determinism per seed, and no-panic on dense/empty charts.

### rbms-judge
- **Role**: The judging engine for a BMS rhythm-game player: it matches key presses/releases against chart note timings, classifies them into judges, and tracks combo, EX score, per-judge tallies, and the groove gauge. Pure, deterministic, stateful logic with no I/O or rendering.

- **Public API**:
  - `Judge` (enum) — one judgment outcome: `PerfectGreat`, `Great`, `Good`, `Bad`, `Poor`, `Miss` (discriminant order = severity, 0..5).
  - `JudgeWindows` (struct) — timing windows `pg/gr/gd/bd/ms`, each `(late_bound, early_bound)` in µs; consts `SEVENKEY_NOTE`, `SEVENKEY_LN_END`, `POPN_NOTE`, `POPN_LN_END`.
    - `JudgeWindows::note_for_mode(&Mode)` / `ln_end_for_mode(&Mode)` — pick the note/LN-release table by mode (`"POPN_9K"` vs everything else).
    - `JudgeWindows::scaled(judgerank_percent)` — scale PG/GR/GD/BD by a percent; MS stays fixed.
    - `JudgeWindows::judge(dmtime) -> Option<Judge>` — classify a signed delta, `None` if outside MS.
  - `rank_to_judgerank(rank) -> i32` — `#RANK` index 0..4 → judgerank percent `[25,50,75,100,125]`, clamped.
  - `JudgeEngine` (struct) — the stateful matcher. Key fns: `new(per_lane_times, windows)`, `from_pairs(per_lane (head,Option<end>), windows)`, `from_model(&Model, windows)`, `set_gauge(kind,total)`, `set_windows(w)`, `set_ln_end(w)`, `set_autoplay(bool)`, `set_gauge_shift(GaugeShift)`, `set_playback_rate(percent)` (a practice slice's FREQUENCY: the engine stays on the chart's clock, stretches every window, the long-note margin, the candidate gate and the hell-charge tick onto it, and reports every timing -- `JudgeResult::delta_us`, `JudgedNote::delta_us`, a note's play time -- in the player's own time, as the reference judges the chart `BMSModelUtils.changeFrequency` retimed), `press(lane,us)`, `release(lane,us)`, `auto_press(lane,at_us)`, `auto_release(lane,at_us)`, `update(now_us)`, `settled_us()`, `failed()`, `failed_at_us()`, `total_notes()`, `total_judged()`, `avg_judge_us()`, `clear_lamp()`. `note_marks()` walks every note's marks (head, then end; each `NoteMark` carries the reference's `play_time_us`, which an empty POOR overwrites, and `judged_us`, the timing of the judgment that consumed the object, which the play trace reports); `judged()` lists every counted judgment (`JudgedNote { lane, judge, delta_us, note_us, combo }`, `note_us` the chart time of the object it was taken on, so an empty POOR's press is `note_us - delta_us`); `touched()` names, oldest first, every note (`NoteAt { lane, index }`) whose marks may have changed since the engine was built -- each `update_micro` and each note `set_ln_mode` gave a flavour to -- and both it and `judged()` are made room for when the engine is built, two entries per note object (the judgment that resolves it and one 空POOR, `JUDGMENT_ROOM_PER_OBJECT`), so a run inside that never grows them in the middle of play; and `note_marks_at(NoteAt)` reads one note's marks, so a screen keeping a copy of the marks follows a run without walking the chart every frame. Public fields: `combo`, `max_combo` (the streak the player sees, carried across a course's stages), `stage_combo`, `stage_max_combo` (the chart's own, which its record and its full-combo lamp read), `counts[6]`, `ex_score`, `gauge`, `last_judge`, `last_fast`, `fast`, `slow`, `early[6]`, `late[6]`, `empty_poor`.
  - `JudgeResult` (struct) — `{ judge, lane, note_index, fast, delta_us, counted }`. `counted` is false only for the press that takes a plain long note's head into the hold: it reports how the head was timed, but the note is judged once, at its end (`JudgeManager.java:426-438`), so the tallies, the judge sound and the AUTO ADJUST step of a judgment belong to the end alone.
  - `JudgeEngine::vanished() -> &[Judge]` — the judgment of every note the run has consumed so far, in the order it consumed them: one entry for each of the first `total_judged()` notes, the reference's `JudgeManager.ghost` (`JudgeManager.java:137-140, 639-646`). It is written in the `vanish` branch of `update_micro` before a consumed 見逃し POOR is left uncounted (`MissCondition::One`), so a consumed POOR that is not counted still takes its place, and an 空POOR, which consumes nothing, is not in it. Room for one entry per note object (`count_objects`) is made when the engine is built, so it never grows in play, and nothing in the engine reads it back. Judging rules are untouched. The player turns it into a stored run's EX after each number of notes (`apps/rbms-player/src/ghost.rs`).
  - **Autoplay does not press a key.** `auto_press` / `auto_release` judge the note whose head or end sits at the given time PGREAT with a timing error of 0 and leave the lane's key state alone (`JudgeManager.java:251-283`, which only sets `auto_presstime`); a mine damages only a key that is down (`:244`), so an autoplayed lane never pays for one. A normal note is taken whatever its lane holds, a long head only by a lane holding none, and a charge or hell-charge end is judged on the spot whichever way a scratch lane would have had to spin by hand (the back-spin rule belongs to a key that is pressed). `set_autoplay(true)` is the reference's `autoplay` of the hell-charge tick (`:289-293`): with no key down the lane still counts as held.
  - `Gauge` (struct) + `GaugeKind` (AssistEasy/Easy/Normal/Hard/ExHard/Hazard), `ClearType` (NoPlay/Failed/AssistEasy/Easy/Normal/Hard/ExHard/FullCombo/Perfect/Max), `clear_lamp(gauge, counts, max_combo, total_notes)`.
  - `AssistGrade` (`None`, `Easy`, `Clear`, `Hard`, `ExHard`; `COUNT` = 5, `ALL`, `id() -> u8` 0 to 4, `from_id(u8)` reading an id past the last as `None`) and `assist_grade(lamp, Option<GaugeIndex>) -> AssistGrade`: only a `LightAssistEasy` lamp that did not come from the ASSIST EASY gauge has a grade, and it is the lamp the gauge would have awarded without the demotion, full combos left out: EASY → `Easy`, NORMAL or CLASS → `Clear`, HARD or EXCLASS → `Hard`, EX-HARD, HAZARD or EXHARDCLASS → `ExHard`; the ASSIST EASY gauge, an unknown gauge and every other lamp (a widened run's `AssistEasy` included) → `None`. The score store keeps an integer mirror of the table (`rbms_store::assist_grade_of`) because it does not depend on this crate; `apps/rbms-player/src/format.rs`'s `the_score_store_grades_every_stored_run_as_the_engine_does` holds the two equal for every lamp and gauge.
  - `clear_type_id(ClearType) -> u8` / `clear_type_from_id(u8) -> ClearType` — the reference implementation's lamp ids, the shape score records and
    IR submissions share. Id `3` (LightAssistEasy) has no rbms variant, so `clear_type_from_id(3)` folds to `AssistEasy` and the round-trip is
    deliberately asymmetric; ids are strictly monotonic so "best clear" is a max over ids. Moved here from the app so persistence and the engine
    read the same table.
  - `data` (module) — the judge/gauge tables as data: `JudgeWindowsData`, `JudgePropertyData`, `JudgeTables`, `GaugeModifier`, `GaugeParams`,
    `GaugeSet`, `GaugeTables`, `JudgeDataError`, `builtin_judge_tables()` / `builtin_gauge_tables()` (RON embedded with `include_str!`),
    `load_judge_tables(path)` / `load_gauge_tables(path)` for a user override. `data/judge.ron` carries all six modes; `data/gauge.ron` carries
    eight sets: `BEAT_5K`, `BEAT_7K`, `BEAT_10K`, `BEAT_14K`, `POPN_9K`, `KEYBOARD_24K`, `LR2` and (2026-10-23) `IIDX`; a row may state `guts_edge`, which is written only when it is `AtOrBelow`, so a data file of the original shape reads as before and the data version stays 1. **The data files are what the engine actually reads**: `JudgeProperty::for_mode` and `gauge::params` look the row up in the
    bundled tables and fall back to the compiled-in `JudgeProperty::defaults_for_mode` / `gauge::default_params` only when there is no row for the
    mode. **Parity guard tests assert the parsed tables equal those compiled-in consts field by field**, which is what keeps the values Phase A
    matched to the reference from drifting; a second pair of tests asserts the lookups really go through the data file, so the data path cannot
    quietly become dead code.
  - `algorithm` (module) — `JudgeAlgorithm` (`Combo` / `Duration` / `Lowest` / `Score`, `#[default] Duration`), `NoteType`, `NoteRef`, and
    `JudgeAlgorithm::prefer(best, cand, ptime_us, windows, note_type) -> bool`, the reference's pairwise candidate-selection predicate.
    `JudgeEngine::set_algorithm` swaps the policy; the default reproduces the nearest-`|Δt|` loop this engine always had
    (see `acknowledge/reference-divergences.md` C-D1).
  - `gauge_tables` (module; 2026-10-23, `GaugeSetId`, `GAUGE_TABLE`, `CourseGaugeMode`) — the nine gauges of six tables. `GaugeSetId` is the reference's five (`FiveKeys`, `SevenKeys`, `Pms`, `Keyboard`, `Lr2`) and the IIDX table this engine adds (`Iidx`, data key `IIDX_GAUGE_KEY`; `COUNT` is 6). `GaugeSetId::course_ceiling()` is the strongest course gauge a table offers (`ExHardClass`, but `ExClass` for IIDX, which has the DAN and EX-DAN gauges and no third), and `GrooveGauge`'s BEST CLEAR and SELECT TO UNDER shifts in a course stop there. `GaugeSetId::course_gauge_for(GaugeKind)` is the course gauge a stage starts on for the player's GAUGE setting (`GrooveGauge.java:164`): ASSIST EASY, EASY and NORMAL play CLASS, HARD plays EXCLASS, EX-HARD and HAZARD play EXHARDCLASS, held to the ceiling. `CourseGaugeMode` (`Lr2` default, `Beatoraja`, `Iidx`; the COURSE GAUGE setting) picks the table: `gauge_set(&Mode)` is the LR2 table, the table the reference picks for the mode (`GaugeSetId::for_mode`), or the IIDX table. The IIDX row copies the seven-key gauges outside the course slots; its CLASS is the DAN gauge (start 100, `[0.16, 0.16, 0.04, -1.5, -2.5, -1.5]`, damage halved at or below 30 through `GUTS_IIDX = [(30.0, 0.5)]`, fails at 0) and its EXCLASS and EXHARDCLASS are EX-DAN (`[0.16, 0.16, 0.04, -3.0, -5.0, -3.0]`, no softening). `data::GutsEdge` (`Below`, the reference's `value < gut[0]`, or `AtOrBelow`) is what lets one row soften at the threshold itself; only the IIDX DAN row uses `AtOrBelow`, and `GaugeParams` / `GaugeElement` carry it. A gauge is built at any slot with `GrooveGauge::at_index` and its value set with `set_value_at`, which is how a course stage starts every slot where the stage before left it.

- **Key invariants & algorithms**:
  - **Delta convention**: `dm = note_time - press_time`. `dm > 0` = pressed EARLY/FAST; `dm <= 0` = LATE/SLOW. `dm == 0` (exact) is counted as LATE, not early, and is neither fast nor slow.
  - **Window tables** are the reference implementation `JudgeProperty` values at judgerank 100, µs. NOTE PG `±20k`, GR `±60k`, GD `±150k`; BD is **asymmetric** `(-280k, +220k)`; MS `(-150k, +500k)`. Because `ms.0 == gd.0 == -150k`, there is **no late POOR** — every late delta is GD/BD until it falls off the BD edge into `None`. POOR exists only on the early side `+220_001..=+500_000`.
  - **Empty poor (空POOR)**: a press landing only in MS (beyond BD, i.e. far-early) is an empty poor: increments `empty_poor`, applies the MS gauge penalty (`gauge.update(Judge::Miss)`), sets `last_judge=Poor`, but does **not** consume the note, does **not** touch `counts`/`early`/`late`/`fast`/`slow`/timing, and does **not** break combo. The note stays hittable. Empty poors never block a full combo. This was a recent fix — previously such presses ate notes and broke combo on slightly-early/jack presses.
  - **press()** scans from the lane cursor for the nearest-by-`|dm|` unjudged, non-holding note within the gate `[gate_late=w.bd.0, gate_early=w.ms.1]`; the gate is derived from the *active scaled* windows (not constants) so it tracks judge width. Non-LN: marks judged, applies, records timing. LN head: sets `holding=true`, stores the head's judgement (`start_judge` of the lane's `LaneHold`), scores nothing yet for a plain LN (combo/EX advance only on release).
  - **release()** finds the holding note, classifies `dm = end - release` against `ln_end`, and for a plain LN the final judge is the worse of that and the head's (`worse(band, start_judge)`, worse = higher discriminant), with the larger of the two timing errors. A release early enough to be a BAD or worse is deferred (`release_us`, `end_judge` BAD) and confirmed after the long-note margin unless the key comes back (`confirm_deferred`); otherwise it marks judged, applies and records timing.
  - **Time moves in the order things happen, not per frame.** `update(t)` walks from one instant something falls due to the next (`next_due_us`: a mine, a hell-charge note's head or end, a hell-charge tick, a deferred release past its margin, a plain long note held past its end, a note past its last chance) and settles each there with the keys as they stood (`settle_at`); `press`/`release`/`auto_press`/`auto_release` first settle up to their own instant. Something due at the same instant as an input is settled before it; something an input makes due at its own instant (a release deferred by a margin of nothing) right after it. Hell-charge ticks run on the time held (`run_hell_charges`, one per 200 ms past, not at most one per call). With a `GaugeShift` the auto-shift is taken after every instant that changed a gauge, and under NONE an emptied gauge ends the run at that instant (`failed_at_us`): the engine then takes no input and settles no time. So one `update` to a far instant leaves the engine exactly where any number of calls on the way would. See `acknowledge/2026-10-15-adr-event-time-judging.md`.
  - **update(now_us)** sweeps: an unhit note becomes a 見逃し POOR (the POOR slot, `counts[4]`) only when `head - now < miss_bound (= bd.0)` — strict `<`, so exactly at the bound it is not yet swept. A held plain LN is finalised with its head's judgement once the clock passes its end (`end < now`); a held CN/HCN whose end passes unheld is swept the same way as a note. A held note blocks its lane cursor until then. **All sweep events are recorded as LATE.** The release margin (`ln_margin`: `JudgeProperty.longnote_margin` scaled by the LN MARGIN rate, the scratch table's `longscratch_margin` unscaled) applies to a deferred early release only. update is idempotent after sweep (cursor advances past judged notes).
  - **LN window** (`ln_end`) is a separate field, wider than the note head (PG `±120k`). `from_model` sets it from `ln_end_for_mode(mode).scaled(rank_to_judgerank(rank))` so releases respect mode + `#RANK` + JUDGE WIDTH (recent fix — was previously a hardcoded 100% constant). Mode-less constructors default `ln_end` to `SEVENKEY_LN_END`.
  - **LN flavour per note** (`JNote.ln: Option<LnKind>`): `from_model` carries the chart's real `LnKind` (Ln/Cn/Hcn) through an internal `from_triples`; the public `from_pairs`/`new` (tests) treat any long note as a plain `LnKind::Ln`, so their signatures are unchanged. `is_charge(ln)` gates the charge-note behaviour to `Cn`/`Hcn` only.
  - **CN/HCN = two counted judgments, plain LN = one.** A charge note (CN/HCN) is judged twice — the **head at press** (committed immediately: `apply`+`record_timing` in `press`) and the **release end at key-up** (its own judge, not capped by the head). A plain LN remains a **single** judgment scored only at release as the worse of the head's and the release's. The same split holds in the `update` sweep (charge head already counted; the end is the swept judgment). `total_notes` (and thus EX/gauge denominators) counts a CN/HCN with an end as **2**, every plain LN/Normal as **1**, matching `rbms_chart::count_playable_notes`.
  - **Charge release, scratch spin, HCN gauge are complete.** An early BAD/POOR CN/HCN release stores `release_us`/`end_judge`; a re-grab before `longnoteMargin` cancels it, otherwise `update` confirms it. `press_dir`/`release_dir` record the scratch owner: BSS ends a charge note with the opposite direction, same-direction input re-grabs it, and the matching-direction mid-spin release is accepted only outside the scratch-end window; MSS releases ownership for the next alternating spin. HCN tracks the passing span in `LaneHold` and pays one tick for every 200 ms held or let go (`run_hell_charges`, as many as the time passed, not one per call): half a GREAT while held (or after a GOOD-or-better end), half a BAD while unheld. Ticks preserve counts, combo, EX, and timing statistics. Full spec: `docs/reference/cn-hcn-judgment.md`.
  - **from_model** builds per-lane notes from `model.timelines`: `Normal` → point note; `LongStart`/`LongEnd` pair into `(head, Some(end), Some(ln))` (kind preserved); `Mine` is skipped; an unterminated `LongStart` (no matching `LongEnd`) is dropped (`pending_start` never flushed). Then sets `ln_end` and `set_gauge(Normal, meta.total)`.
  - **EX score** = `2·PG + 1·GR` only. PG/GR/GD keep combo; BD/POOR/MISS break it (`combo = 0`). `max_combo` is updated in `apply()`.
  - **avg_judge_us** = mean signed `dm` over timed hits (press/release, excludes empty poors and sweeps); 0 when nothing timed. It is the run's lean, sent as `extra.mean_offset_us`; the reference's `avgjudge` is `rbms_play::PlayRecord::avg_duration_us`. `early[i] + late[i] == counts[i]` always holds.
  - **clear_lamp(gauge, counts, combo, pass_notes, total_notes)**: FAILED off a gauge that did not clear; a full combo (MAX/PERFECT by GREAT and GOOD) when the combo standing at the end equals the notes got through (`BMSPlayer.java:868`); the gauge's lamp otherwise.
  - **Gauge**: deltas are pre-modified at construction. TOTAL modifier (AssistEasy/Easy/Normal) scales only positive deltas by `total/notes`; LIMIT_INCREMENT (Hard/ExHard) caps PG gain via `pg = clamp((2·total-320)/notes, 0, 0.15)`, then scales positives by `pg/0.15`; Hazard (`Modifier::None`) leaves deltas raw. `notes` is `max(1)`; `total <= 0` falls back to 200. HARD guts soften negative deltas at low values (first matching band of `[(10,0.4),(20,0.5),(30,0.6),(40,0.7),(50,0.8)]`). `is_cleared` requires `value > 0 && value >= border` (so a survival gauge sitting exactly at 0 border is *not* cleared). Total gauges floor at min 2.0 (never permanently dead); survival gauges hit 0 and stay dead (`update` returns early once `value <= 0`).
  - **clear_lamp**: `NoPlay` if 0 notes; `Failed` if gauge not cleared; else if no break (`counts[3]+[4]+[5]==0`) and `max_combo == total_notes`: `Max` (no GR/GD), `Perfect` (no GD), else `FullCombo`; otherwise falls to the gauge-kind lamp (Hazard maps to `ExHard`).

- **Gotchas / edge cases**:
  - BD asymmetry means a `+250ms` press is an (early) empty POOR while `-250ms` is still a real BAD — symmetric reasoning is wrong.
  - The miss/force-finalize bounds are strict inequalities; tests pin the exact 1µs boundary (`update_miss_bound_is_exclusive_strict_less`: `1_280_000` not swept, `1_280_001` swept).
  - Plain-LN head reported judge ≠ scored judge: `press` on a plain LN head returns the head judge with `counted == false` and scores nothing (counts/combo/EX unchanged) until `release`; CN/HCN heads are the two-judgment exception and count at press. A caller that tallies judgments (the session's instrumentation, AUTO ADJUST, the judge sound) must skip a result that is not `counted`. A far-early press on an LN head is an empty poor and must **not** arm a hold.
  - `release` finds the holding note by `position(|n| n.holding)`, not by lane cursor; releasing with nothing held, or on an invalid/empty/out-of-range lane, returns `None`. A consumed note can't be hit twice.
  - `scaled` uses truncating integer division and clamps percent to `>= 1` (never zero-width). MS is intentionally never scaled.
  - `POPN_NOTE`/`POPN_LN_END` currently mirror the SEVENKEY tables (placeholder pending verified PMS values) but are kept as distinct consts so tuning pop'n never touches the beat table.
  - `worse(a,b)` compares enum discriminants — relies on the `Judge` variant ordering being severity order.

- **Tests**: `tests.rs`와 각 모듈의 `#[cfg(test)]`가 window classification, press/release/update matching and gating, empty-poor, plain-LN force-finalize, early/late split + `early+late==counts`, EX/combo/`max_combo`, determinism, `from_model` wiring을 고정합니다. CN/HCN 2-판정 픽스처 외에 `a_charge_note_release_inside_the_margin_is_rescued_by_a_re_grab`, HCN held/dropped tick·remainder, BSS opposite/same direction·ignored release, MSS alternating spins를 검사합니다. `windows.rs`는 정확한 경계·scale·mode 선택을, `gauge.rs`는 gauge init/modifier/guts/clamp/clear lamp를 검사합니다. `vanished()`는 `a_run_lists_every_note_it_consumed_in_the_order_it_did`(소비 순서, 空POOR 제외)와 `a_consumed_poor_that_is_not_counted_still_takes_its_place`(`MissCondition::One` 의 세지 않는 POOR)가 고정하고, 용량 테스트 두 개가 목록이 플레이 중 커지지 않음을 확인합니다.

### rbms-audio
- **Role**: Real-time, allocation-free software audio engine for BMS keysounds: decodes audio files, owns the cpal output stream, and mixes scheduled keysounds with sample-accurate timing. Crucially, it exposes a master clock derived from `samples_played / rate` (not the frame/vsync clock) as the project's authoritative play-position timing source.

- **Public API** (re-exported from `lib.rs`):
  - `AudioError` — enum: `NoDevice`, `Decode(String)`, `Stream(String)`, `Unsupported(String)`; impls `Display` + `std::error::Error`.
  - `DecodedAudio` — struct `{ samples: Arc<[f32]>, channels: u16, rate: u32 }` holding interleaved f32 PCM at native rate, already in the shared form the mixer plays from: `decode_bytes` makes it on the thread that decodes, and `insert_decoded` moves it into the bank without copying the samples.
  - `decode_bytes(bytes: Vec<u8>, ext: Option<&str>) -> Result<DecodedAudio, AudioError>` — symphonia-based decode of WAV/OGG/FLAC/MP3 from memory.
  - `AudioEngine` — top-level host handle: owns stream, RT command queue, clock, and the keysound `bank`.
    - `new()` (512 max voices) / `with_max_voices(n)` — open default device, start stream.
    - `out_rate()`, `clock_frames()` (frames played), `clock_us()` (clock in µs).
    - `load(id, bytes, ext)` — decode + insert; `insert_decoded(id, DecodedAudio)` — insert pre-decoded sample (skips CPU-heavy decode so a host can decode off-thread in parallel).
    - `loaded()`, `has_sample(id)`, `sample_duration_us(id) -> Option<i64>`.
    - `play(id, gain, pan, pitch, at_us)`, `stop(key)`, `set_master_gain(g)` — push RT commands.
  - `Mixer` — RT-safe mixer: `new(out_rate, out_channels, max_voices)`, `clock_frames()`, `apply(Command)`, `mix(&mut [f32])`.
  - `Command` — enum `Play{ sample, gain, pan, pitch, key, at_frame }`, `Stop{ key }`, `MasterGain(f32)`.
  - `SampleData` — struct `{ pcm: Arc<[f32]>, channels: u16, rate: u32 }` with `frames()`.

- **Key invariants & algorithms**:
  - **Master clock = sample count, not frames/vsync.** `AudioEngine.clock` is an `Arc<AtomicU64>`; the cpal callback stores `mixer.clock_frames()` with `Release` after each block, read with `Acquire`. `clock_us = frames * 1_000_000 / out_rate.max(1)`. This is the explicit "timing-source fix vs the reference implementation."
  - **Time→frame conversion**: `play`'s `at_us` becomes `at_frame = at_us.max(0) * out_rate / 1_000_000`; in the mixer `delay = at_frame.saturating_sub(clock)` — scheduling in the past clamps to play-immediately, never negative.
  - **Per-voice resampling = pitch.** `stride = (sample.rate / out_rate.max(1)) * pitch.max(0.0001)`. One fractional read stride handles both device-rate resampling and pitch shift. `pitch <= 0` is floored to `0.0001` (never zero stride). `out_rate == 0` is treated as 1.
  - **Equal-power pan**: `angle = (pan.clamp(-1,1)+1)*0.5*FRAC_PI_2`; `lgain=cos`, `rgain=sin`, so `lgain²+rgain²==1`. Center gains ≈ `FRAC_1_SQRT_2`.
  - **Linear interpolation with tail clamp**: partner sample is `next = (i+1).min(nframes-1)` — at the tail it clamps to the last sample so the final (and single-frame) source frame still plays. This was a deliberate fix; it previously dropped the last frame and silenced 1-frame samples.
  - **Voice allocation**: fixed pool of `max_voices` (engine default 512); `alloc_slot` round-robins from `alloc_cursor` to find a free slot, otherwise **steals** the slot at the cursor. `play(key)` first `stop(key)`s, so re-triggering the same key cuts the previous voice (only one voice per key).
  - **Output routing**: mono out (`oc==1`) writes `(l+r)*0.5`; stereo writes `l`/`r`. `out_channels==0` is treated as 1. Mono source duplicates to L/R; stereo source routes channels independently.
  - **Master gain** applied last, output hard-clamped to `[-1.0, 1.0]` (negative master inverts phase). Default master gain `1.0`.
  - **RT safety**: `mix` does no allocation/locking; `scratch` buffer is resized only when `data.len()` changes. Commands flow through an `rtrb` SPSC ring of capacity 8192; pushes/pops are best-effort (`let _ =`), so a full queue silently drops commands.
  - `clock` advances by **frames** (`out.len()/oc`), not raw samples, every `mix` call.

- **Gotchas / edge cases**:
  - `decode_bytes` returns `AudioError::Decode("empty audio")` if zero channels or no samples; `ResetRequired` and `UnexpectedEof` end decoding gracefully, `DecodeError` packets are skipped (lossy).
  - `play(id, ...)` on an unknown id is a silent no-op (bank lookup misses); `stop`/`MasterGain` of unknown keys are no-ops.
  - `_stream` is held only to keep the cpal stream alive; dropping `AudioEngine` stops audio.
  - `SampleData::frames()` returns 0 when `channels == 0` (guards divide-by-zero).
  - cpal sample formats: only F32/I16/U16 supported; anything else → `AudioError::Unsupported`. Output samples are converted via `T::from_sample`.
  - Pitch floor literal `0.0001f32` widens to ≈`9.9999997e-5` as f64 — tests compare with tolerance, not equality.

- **Tests**: Inline `#[cfg(test)]` modules in `decode.rs` and `mixer.rs` (no `tests/` dir). `decode.rs` builds in-memory 16-bit PCM WAVs (mono + stereo helpers) and covers: successful decode, channel/rate/sample-count preservation, normalization to `[-1,1]`, silence round-trip, determinism, no-extension-hint probing, and error paths (empty/garbage/truncated/zero-length-data). `mixer.rs` (~40 tests) pins: clock accounting (frames vs samples), sample-accurate delay across mix boundaries, stride resampling/pitch combos and floors, equal-power pan constant-power invariant, mono/stereo channel routing, voice gain + master-gain clamping/phase, voice lifecycle (retrigger-cuts, coexistence, stealing, round-robin cursor, stop), and end-of-sample tail behavior (all frames play, single-frame audible, position persists across calls).

### rbms-render
- **Role**: Backend-agnostic 2D rendering for every BMS screen — playfield, HUD, song-select, result — plus text shaping, a data-driven skin/theme system, and a CPU reference canvas. All composers draw through the `Renderer` trait, so the wgpu and CPU backends share identical layout code.
- **Public API**:
  - `Renderer` (trait): `size`/`clear`/`fill_rect` — the only primitive every composer uses. `Color` (rgba u8, with named consts), `Rect`. Textures: `register_texture` takes a whole image; `update_texture(tex, rgba, TexelRect)` writes one rectangle of a held texture again from the whole image's pixels and answers `false` (the default) when the backend cannot, in which case the caller registers the whole image. The wgpu backend and `CpuCanvas` implement it and every wrapper (`ScaledRenderer`, `RegionRenderer`, `OffsetRenderer`, the player's canvases) passes it on. The wgpu upload hands rows over tight (`Queue::write_texture` takes any stride), so an upload copies nothing on the frame thread. `device_scale() -> (f32, f32)` (default (1, 1)) says how many pixels of the target at the bottom one unit of this renderer spans on each axis, and `fill_rect_device(Rect, Color)` fills a rectangle given in those target pixels (the default divides by the scale and calls `fill_rect`, which is the same call at scale one). `ScaledRenderer` multiplies its factor into the inner renderer's and hands `fill_rect_device` down untouched; `RegionRenderer` forwards the factor and moves a device rectangle by its corner measured in target pixels, rounded to a whole one; the player's `Canvas` answers `scale_between(UI_SIZE, native_size)` and fills straight on the native target. `OffsetRenderer` (a skin's OFFSET_ALL stretch, `skin_render/whole.rs`) leaves the default (1, 1) on purpose: the engine's own glyphs inside a stretched skin (a stand-in for a font that did not load, a note field's labels) are drawn in the skin's pixels and stretched with the screen, as the reference's transform stretches its batch, so an external Lua skin's pixels did not change.
  - `CpuCanvas`: deterministic software RGBA8 backend; `new`, `pixel_at`, `pixels`.
  - `Skin` / `SkinConfig`: resolved per-lane geometry+colours vs. its RON config. `Skin::build(cfg, mode, screen_w, screen_h)`, `default_for`, `lane_count`/`lane_height`/`lane_center`/`note_color`.

The skin's row colours (`tint`) never reach these notes. With the slice empty, or with no colour picked, drawing is as before, so the golden signatures did not move.

  - Text: `draw_text`/`draw_text_centered`/`draw_text_right`, `text_width`, `fit_text`, `load_font`, `set_ui_family`/`reset_ui_family`, and their `*_styled` forms (`draw_text_styled`, `draw_text_centered_styled`, `draw_text_right_styled`, `text_width_styled`, `fit_text_styled`; also `TextContext` methods) that take a `TextStyle { scale, weight: FontWeight }` (`TextStyle::new`, `TextStyle::regular`; `FontWeight(u16)` with `REGULAR` 400, `MEDIUM` 500, `SEMIBOLD` 600, `BOLD` 700). A heavier weight sets wider glyphs, so a line is aligned and fitted with the same style it is drawn with. A plain call sets the face's own weight, regular for the bundled Inter, and a regular style draws the same pixels as the plain call. No screen calls the styled forms yet: the default pack's bold text is its own `Inter-Bold.ttf` drawn by the skin renderer, and the styled calls are pinned by tests only.
- **Key invariants & algorithms**:
  - **Built-in screens are laid out in 1280×720 (16:9)**; most pixel constants (select panel rects, result/modal layout) are hard-coded for it, and the app draws them through `ScaledRenderer` on larger targets. A skin screen is not: its logical size is the physical viewport left after letterboxing, and the document's own `w` x `h` is scaled onto it. `SkinConfig` mixes units: `field_x`/`field_width`/`dual_gap` are *fractions of screen width*; `top_y`/`judge_y`/`note_height`/`bga` are *pixels in 720p*.
  - **Theme is a thread-local** `RefCell<Theme>` (`theme.rs`); `set_theme` once at startup, every composer reads `theme()`. Rendering is single-threaded (also true of the font `ENGINE` thread-local). Both `ThemeConfig::parse` and a malformed RON theme fall back to all-defaults so a broken theme can't brick the UI; `resolve` merges set fields over `Theme::default`. The default palette is achromatic (black ground, grey steps shared with the default skin pack's Mono palette, white for what is chosen); the one field with a hue is `warn`. A colour left as a literal in a composer is a meaning (judgement, lamp, rank, FAST/SLOW, gain/loss), not chrome.
  - **Font engine** (`font.rs`): bundled Inter (OFL), a variable font whose weight axis both shaping and rasterisation follow; cosmic-text falls back to system fonts for CJK/Thai/Arabic. `scale` is a legacy unit → `px_for(scale)= round(scale*8.5).max(8)` logical pixels (not "14 px × scale", as `reference/ui-design.md` once said). Two caches: shaped layout (`family→(px, weight)→text→Laid`, so a skin alternating fonts keeps both; weight 0 means the face's own) and run-length-merged rasterized glyph pixels keyed by `(CacheKey, packedRGB)`; `merge_runs` coalesces contiguous same-colour/coverage pixels into one rectangle fill per run. `LAYOUT_CACHE_LIMIT` (512 lines) and `RUN_CACHE_LIMIT` (4096 entries) are swept to 75% when full; both caches are cleared on a family change.
  - **Text is rasterised on the target's own pixels** (since 2026-10-22; before it the built-in screens drew their text at 1280×720 and enlarged every pixel, 2×2 at double size and uneven 1-and-2-pixel blocks at 1.5). `device_text_scale(r)` asks the renderer for `device_scale()`. At (1, 1) the old path runs unchanged and draws the same pixels (the golden signatures did not move). At another factor that is uniform on both axes the line is still shaped once in logical pixels, then each glyph is rasterised at `px × s` (the sub-pixel x bin taken in target coordinates, the baseline at `trunc(line_y) × s` so the line sits where the old enlarged one did) and its pixels go out through `fill_rect_device` at `round(x·sx)`, `round(y·sy)`. The factor counts as uniform when the two axes differ by no more than rounding each edge of the target to whole pixels explains, `0.5 × (1 + longer / shorter)` pixels over the longer edge (about 1.39 on a 16:9 target; a letterboxed viewport is off by at most 0.889), and the smaller axis is the scale used. A target stretched out of shape (LETTERBOX off and a window dragged to another aspect) keeps the old path and is stretched with the rest of the screen. `GlyphPainter::paint` is the one raster-and-replay loop both paths share: it bakes a glyph with `SwashCache::get_image_uncached` and `lit_pixels` (the meaning cosmic-text's `with_pixels` gives a mask, a colour image and a sub-pixel mask), so the swept `runs` cache holds the only copy of a glyph's pixels. The rasteriser's own image cache is never swept, and a window drag asks it for a glyph at a new fractional size every frame (restoring `with_pixels` makes the test `a_window_drag_rasterizes_past_the_rasterizers_unbounded_image_cache` fail with 13,480 images after 48 drag frames). The atlas path still uses `with_pixels`.
  - **Faces and weights**: `name_for` gives the bare family name (`Inter`) only to a family's regular cut (weight 400, upright, normal width) and `<family> <weight>` (`Inter 700`) to any other, whichever order a skin loads them in, so the built-in screens (`face("Inter")`) stay regular when the default pack also loads `Inter-Bold.ttf` (`the_built_in_screens_stay_regular_whichever_cut_of_their_family_a_skin_loads_first`). A user font (`--font`) with no weight axis is matched to the nearest cut its family has when a weight is asked for, so it may not get heavier; a family with no regular cut gets `<family> <weight>` names and the `font: path (family)` start-up log line shows that name.
  - **Built-in `Skin` lane layout** (used by the built-in play screen only): `dual` DP (two fields, P1 left/P2 right, turntables on the *outer* edge, ignoring SP `scratch_left`) only when `dual_field && players>=2 && key%players==0`; the right field is sized to clear the BGA column (`right_limit = bga.x − 24`); a BGA whose right edge lies within `DUAL_LEFT_BGA_LIMIT` of the screen width counts as sitting *left* of the fields and the two fields start after it (`DUAL_MARGIN`) instead of collapsing beside it (v3 dual documents). SP uses `scratch_left` to order scratch first/last. `lift` clamps to `0.0..=0.9` and raises `judge_y` toward `top_y`; `beam_height_frac` clamps to `0..=1`. `lane_bg`/`outline`/`divider` keep their configured alpha (not forced opaque). `bomb_us = bomb_duration_ms * 1000`.
  - **Playfield** (`playfield.rs`): uses `constant_offsets`/`visible_offsets` from `rbms-chart`. A note exactly at its time is *excluded* (its timeline is `cur`; iteration starts at `cur+1`) — it's judged and gone. LN bodies: head on-screen uses its offset; head past line clamps body bottom to the line; end above window extends to `top_y`; whole-LN-above-window or LN-past-line is **skipped** (else it tints the whole lane). `LongEnd` notes are never drawn as a cap (the body bar is the hold). Beams: `BEAM_RELEASE_US=120_000`µs linear fade, `BEAM_SLICES=6` gradient brightest at the line; `beam_on`/`beam_off` are per-lane µs timestamps, `i64::MIN`=inactive, pass `&[]` to omit. `render_lane_cover` clamps to `0.0..=0.9`. Judgment line / decor drawn *per field* so they don't bridge the DP gap.
  - **Result/HUD**: DJ-LEVEL bands sit at **ninths of max EX** (`RANK_BOUNDS`, `F`<2/9 … `AAA`≥8/9); `dj_rank` guards `max_ex==0`→F and `ex>max`→AAA. HUD spans the *full* note area (both DP fields), score-graph drawn in the gap between field and BGA, judge counts pinned right of the field/over the BGA. Gauge colour switches at skin `gauge_clear_threshold`/`gauge_warn_threshold`.
- **Gotchas / edge cases**:
  - `CpuCanvas::fill_rect` **always forces stored alpha to 255**, even for `a==0` (a transparent fill is *not* a true no-op — rgb is preserved but alpha is stamped). Tests therefore compare lanes against a reference empty lane rather than against `skin.lane_bg`.
  - `fill_rect` floors origin / ceils extent, clips to canvas, draws nothing for zero/negative size; a sub-pixel rect still paints ≥1 cell. `pixel_at` does **no** bounds check (panics out of range — pinned by a `#[should_panic]` test).
  - `render_select` suppresses row/record hot-rects while the modal is open (the modal owns clicks). Focused list row is highlighted colour-only (side rails, no box) and does not grow. Detail-panel pixel offsets are tightly tuned (stat grid must clear the DENSITY section); density histogram uses sub-pixel bar `step` so the last bin lands inside the box.
  - `wrap_two` / `fit_text` are character-wrap (CJK has no spaces); a single over-wide glyph collapses to a lone `…`; non-positive width is a no-op.
  - `SkinConfig`/`ThemeConfig` use `#[serde(default)]` so partial RON inherits defaults; `SkinConfig` also carries the **HUD presentation** (judge colours/labels, gauge, bomb, combo/judge/fastslow y-offsets) so a skin restyles the play HUD without code.
- **Tests**: Extensive `#[cfg(test)]` modules in each file. `skin.rs` pins lane layout (SP/DP dual fields, outer scratches, BGA clearance, lift/beam clamps, uniform width, bomb µs). `playfield.rs` pins note/LN positioning and all LN edge cases, beam fade math, lane cover, key bomb, determinism. `font.rs` pins `merge_runs` coalescing, `fit_text`, multilingual shaping, the uniform-scale decision (six viewports from 1366×768 to 3456×1944, the 200 rounded windows from ×1.01 to ×3.00, five stretched ones that keep the old path), the drag test above, `lit_pixels` and the face names. `tests/primitives.rs` pins that the atlas draws the same pixels as the fill path (`the_glyph_atlas_draws_the_same_pixels_as_the_fill_path`), and `skin_render/whole.rs` that a stretch of the screen enlarges the unstretched text (`text_drawn_through_a_stretch_is_the_unstretched_text_enlarged`). `result.rs` pins `dj_rank` ninth boundaries/monotonicity and result smoke. `theme.rs` pins default/partial/malformed resolve + thread-local round-trip. `cpu.rs` pins the source-over blend math and clipping. No tests shown for `hud.rs`/`select.rs` beyond what their helpers exercise elsewhere.

### rbms-ir
- **Role**: Defines the rbms "IR-superset" score-server contract: the `ScoreServer` trait, all wire DTOs (serde JSON), plus two concrete clients (HTTP reference, offline null). It is a pure data/contract crate — no backend, no audio/judge/UI logic lives here.
- **Public API**:
  - `ScoreServer` (trait, `Send + Sync`): the score-server contract; 8 required methods (`health`, `submit_score`, `chart_ranking`, `player_best`, `player_profile`, `rivals`, `submit_course`, `upload_replay`) + 17 optional extension methods with default `Err(Unsupported)` bodies (`course_ranking`, `download_replay`, `get_settings` / `put_settings`, `register` / `login` / `whoami` / `revoke_current_token`, `put_rivals`, `chart_ranking_page` / `course_ranking_page`, `player_scores`, `chart_replays`, `upload_trace`, `version`, and the player's folders `user_folders` / `user_folder`).
  - `HttpScoreServer` — REST+JSON reference client over `reqwest::blocking`, optional bearer token.
  - `NullScoreServer` — offline stub; every required method returns `NotConfigured`; optional extensions retain `Unsupported`.
  - `IrError` (enum): `NotConfigured | Network | Unauthorized | Forbidden | NotFound | Conflict | SettingsConflict | PayloadTooLarge | RateLimited | Server(u16,String) | Decode | Unsupported`; impls `Display` + `std::error::Error`.
  - `API_VERSION: u32 = 1` — contract version stamped into every submission.
  - `GUEST_PLAYER_ID = "guest"` — the one id an unauthenticated submission may use; the server flags it `GUEST` and leaves it out of the ranking.
  - DTOs (re-exported by name, not by glob, so the crate's surface is a list rather than whatever `dto` happens to hold): `ChartId{md5,sha256}`, `SubmittedChart` (a `ChartId` plus the title, artist and whole-number level the chart writes, each left out when absent, so the server can name a chart nobody has submitted before and never overwrites what it holds), `PlayerId{id}`, `ScoreSubmission`, `ScoreRecord`, `SubmitResponse` (`accepted`, `rank`, `previous_best`, `message`, and the later `ranked`, `flags`, `is_new_best`, `score_id`, each with a serde default) with `ScoreFlag` (`Autoplay`, `ScratchAuto`, `Assist`, `JudgeWidth`, `TotalOverride`, `UnknownBuild`, `Guest`; unknown future flags stay as raw strings), `CourseSubmission` (with optional `scratch_auto` and `assist`, left out of the body when no stage had one), `PlayerProfile`, `ServerInfo`/`ServerCapabilities`/`VersionInfo`, `JudgeBreakdown`, `PlayOptions`, `ReplayData`/`ReplayEvent`/`ReplayMeta`, `SettingsBlob`/`SettingsPutResult`, `PlayTrace` (the play trace, `play-options.md` §10.12: format `TRACE_FORMAT` generation `TRACE_FORMAT_VERSION`, `TraceNotes` columns with the `TRACE_KIND_*` kinds, `TraceEmptyPoors`, `TraceGauge`, `TraceGaugeBounds`, `TraceSpeeds` / `TraceSpeed` / `TraceSpeedChange` with `TraceSpeed::changes_to` over `TRACE_SPEED_FIELDS`, `TraceTempo`; `to_json` / `from_json`; `TRACE_MAX_BYTES` = 2 MiB, `TRACE_MAX_SPEED_CHANGES` and `TRACE_MAX_TEMPO_POINTS` = 4,096 each, past which a client keeps the first and the last half) and `TraceUploadResponse { id }`, `AuthRequest`/`AuthResponse`, `UserFolder`/`UserFolderIndex`/`UserFolderItem`/`UserFolderSummary` with `is_path_safe_folder_id`, and the query types.
  - `mapping` (feature, on in the player): the client's reading of a run into wire terms — `assist_level` (0 none, 1 `LIGHT_ASSIST` for SCRATCH AUTO, 2 `CUSTOM_JUDGE_ASSIST` for a widened judge), `assist_flags` (`AUTO_SCRATCH`, `CUSTOM_JUDGE`), `combo_breaks`, `submitted_chart`. `worker` — `spawn_submit` / `spawn_query` run a call on a thread and hand back a receiver (a submission is first brought into the server's bounds, `ScoreSubmission::clamp_to_server_bounds`: `played_at` not below `MIN_PLAYED_AT_MS` = 0, a non-finite gauge sent as `FALLBACK_GAUGE_VALUE` = 0.0), `is_replay_upload_warranted` says whether a run's replay is worth uploading.
  - `sync` — pure classification of one answer for a run a client keeps sending until the server holds it, with no thread or state: `submit_verdict(&Result<SubmitResponse, IrError>) -> SubmitVerdict` (`Accepted { score_id, already, replay_warranted }`, `Rejected(Rejection)`, `RateLimited`, `Transient { detail }`, `StopSync { detail }`) and `upload_verdict` for a replay (`Uploaded`, `Rejected`, `RateLimited`, `Transient`, `StopSync`). `Rejection` carries the HTTP status, the error code, the field and reason the server named, and one readable line. A 2xx answer that is not accepted, and a 4xx, is a rejection; 429 is rate-limited; a network or decode failure and 5xx (`SERVER_FAILURE_STATUS_FLOOR` = 500) are transient; 401, no server and an endpoint the server lacks (`Unsupported`) stop the sync. All three are `#[serde(default, skip_serializing_if = ...)]`, so a course kept by an earlier build is sent again in its old shape and a server that predates them drops them (Zod's `z.object` ignores unknown keys; it answers no 400). `contract/client-requests/course-normal.json` and `course-scratch-auto.json` carry them.
  - Enums: `ClearLamp` (11 variants `NoPlay..Max`), `GaugeType` (9 variants), `RandomOption` (9 variants) — all externally-tagged (serialize to the bare variant-name string).
- **Key invariants & algorithms**:
  - **Superset, not subset**: charts carry both `md5` and `sha256` (BMS IRs key only on MD5); the HTTP client routes ranking/best/replay endpoints by `chart.md5` only (`/charts/{md5}/...`), while `sha256` rides along in the body.
  - **Early/late judge split is additive**: `JudgeBreakdown` mirrors the reference implementation `IRScoreData`'s 12 `epg..lms` fields; the documented invariant is `epg+lpg == pgreat`, `egr+lgr == great`, … `ems+lms == miss`. Plus `avgjudge` (the reference's mean note distance in **µs**, a note never hit counting a second, `i64`; a body without `extra.rule_version` predates it and carried the mean signed offset) and rbms-only `empty_poor`. `ScoreSubmission::state_mean_offset`/`mean_offset` and `state_rule_version`/`rule_version` read and write `extra.mean_offset_us` and `extra.rule_version`.
  - **Forward-compat via serde defaults**: the 9 basic judge fields (`pgreat..combobreak`) and 7 basic `PlayOptions` fields (`gauge,random,random_p2,scratch_auto,lntype,input_device,assist`) are **required**; everything else (`#[serde(default)]`) — including `seed`, `judge_algorithm`, `rule`, `skin`, `client_build_sha256`, `client_platform`, `extra`, and all extended `PlayOptions` — defaults so pre-superset payloads still decode. `extra: HashMap<String,Value>` is a plain field (NOT `#[serde(flatten)]`), so unknown sibling keys are **ignored, not captured**.
  - **Replay format is lossless µs events**, not a byte stream: `ReplayEvent{t_us:i64, lane:u32, press:bool}`, format string `"rbms-us-v1"`; `t_us` is `i64` so pre-song-start (negative) times survive; `seed: Option<u64>` lets the server reproduce the exact shuffle/lane layout (paired with `ScoreSubmission.seed`).
  - **Capability discovery**: `health()` returns `ServerInfo{name,version,ir_compat,capabilities}`; `ServerCapabilities` (all-`bool`, defaults all-false) is how a client learns which superset endpoints exist before calling them.
  - **HTTP client specifics** (`http.rs`): **5-second** request timeout (`REQUEST_TIMEOUT`; the folder reads use `FOLDER_REQUEST_TIMEOUT`, 30 s); `try_new` / `try_with_timeout` report a builder failure as `IrError::Network`, and the infallible `new` keeps the failure and answers every call with it instead of falling back to an unbounded client; base URL has trailing `/` stripped at construction; non-2xx → typed `IrError` variants (401 Unauthorized · 403 Forbidden · 404 NotFound · 409 Conflict/SettingsConflict · 413 PayloadTooLarge · 429 RateLimited · else `Server(code, body)`); network failure → `Network`; JSON decode failure → `Decode`. `put_settings` expects 200 `{ updated_at }` (the stored lock stamp, epoch ms) and treats a body-less 204 from older servers as success with the sent stamp (`SettingsPutResult { from_server: false }`). `upload_replay` POSTs and unwraps a local `{ "id": String }` response into a bare `String`; `upload_trace` POSTs `/charts/{md5}/traces` the same way under `TRACE_REQUEST_TIMEOUT` (30 s).
  - Endpoint map (under the configured base, `https://bms.hyuns.uk/api` by default): `/health`, `POST /scores`, `/charts/{md5}/ranking?limit=`, `/charts/{md5}/best?player=`, `/players/{id}`, `GET|PUT /players/{id}/rivals`, `POST /courses`, `POST /charts/{md5}/replays`, `/courses/{hash}/ranking?limit=`, `/replays/{id}`, `GET|PUT /players/{id}/settings/{name}`, `POST /auth/register`, `POST /auth/login`, `GET /auth/me`, `/charts/{md5}/ranking?…` and `/courses/{hash}/ranking?…` with the paging query, `/players/{id}/scores?…`, `/charts/{md5}/replays?…`, `/version`, `/players/{id}/folders` and `/players/{id}/folders/{folderId}` (read through `get_bounded`, which refuses an answer past its size cap).
- **Gotchas / edge cases**:
  - **`NotConfigured` vs `Unsupported` are deliberately distinct**: `NullScoreServer` returns `NotConfigured` for the 8 required methods but inherits the trait-default `Unsupported` for every optional (superset) method (it does NOT override them). Tests pin this difference — don't "fix" it by making them uniform.
  - **`gauge_value` is a bare `f32` (and `f64` math fields like `hispeed` likewise non-optional)**: a NaN `gauge_value` serializes to JSON `null` and then **fails to decode** — silently lossy. A test (`submission_nan_gauge_value_serialises_to_null_which_then_fails_to_decode`) pins this behaviour of the type itself. Every send path clamps first (`clamp_to_server_bounds` in `worker::spawn_submit`, the records sync and the course body), so a NaN gauge leaves the client as 0.0 rather than as a 400.
  - `played_at` and `t_us` are `i64` (signed) on purpose — negative values round-trip.
  - Enum decode is **case-sensitive** and rejects unknown variants (`"normal"` and `"Bogus"` both error) — adding a lamp/gauge/random value is a wire-breaking change for older decoders.
  - `option: i64` in `PlayOptions` is the reference implementation's raw option bitmask, kept verbatim for round-tripping (don't reinterpret).
  - `HttpScoreServer` is **blocking** (`reqwest::blocking`) — callers must not invoke it on an async/UI thread without offloading. The player performs network work off its UI frame.
  - URL path segments (player id, chart md5, settings name, course hash) are interpolated **without escaping** — assumed safe/hash-like; not URL-encoded.
- **Tests**: Inline `#[cfg(test)]` modules, `contract_tests` (fixtures of the bodies the client and the server exchange) and HTTP mock regression tests cover `ScoreSubmission` round-trips (full superset + minimal/legacy decode), `ReplayData`, early+late additive splits, auth/settings/replay/ranking HTTP paths, typed error mapping, DTO defaults/required-field failures, and the offline `NullScoreServer` distinction between required `NotConfigured` and optional `Unsupported` methods.

### rbms-table
- **Role**: Fetches, parses and groups BMS difficulty tables into level-ordered chart lists, and reads the copy of a fetched table that is kept on disk. A table is reached from the address a user registers, which is normally the table's web page. Pure data layer — no UI, no audio. Where a copy is kept, when a table is fetched again and when a copy is dropped are the player's (`apps/rbms-player/src/tablesrc.rs`), not this crate's.
- **Modules**: `lib.rs` (`DifficultyTable`, `Md5Index`, parsing, grouping), `fetch.rs` (the chain from an address to a table, and the HTTP client), `saved.rs` (`SavedTable`: the copy on disk), `html.rs` (the `bmstable` meta tag), `dto.rs` (`TableEntry`, `TableHeader`), `error.rs` (`TableError`, `TableStage`).
- **Public API**:
  - `DifficultyTable` (struct) — resolved table: `name`, `symbol`, `level_order: Vec<String>`, `entries: Vec<TableEntry>`, `skipped: usize` (body items left out because they name no chart), `course: Option<serde_json::Value>` (the header's courses as the header wrote them; kept in the copy, and read as courses by `rbms_course::courses_from_table_header`, which the player calls for the COURSE folder of a table).
  - `DifficultyTable::from_parts(header: Option<TableHeader>, entries) -> DifficultyTable` — merge header metadata + body; derives `level_order` when missing/empty.
  - `DifficultyTable::fetch(url) -> Result<_, TableError>` — HTTP fetch. `url` may be the table's web page, a header or a body; which one is read from the first meaningful byte of the answer (`[` body, `{` header, anything else a page). A page's `<meta name="bmstable" content="…">` names the header, the header's `data_url` names the body or bodies, and each relative address is relative to where the answer it was read from finally came from (after redirects). For a bare body a sibling `header.json` is fetched best-effort.
  - `SavedTable { table, source, fetched_at: Option<u64> }` — the copy of a fetched table: the whole table, the address it was fetched from and when (seconds since the Unix epoch). `SavedTable::json_of(&table, source, fetched_at) -> Result<String, serde_json::Error>` is what a keeper writes (with its own durable write; this crate writes no file), `SavedTable::from_bytes(bytes) -> Option<SavedTable>` and `SavedTable::read(path) -> Option<SavedTable>` read one back. A file that is missing, damaged, cut short or larger than `MAX_RESPONSE_BYTES` is `None`: no copy, so its table is fetched again. A copy written before `source` and `fetched_at` were kept (the earlier versions' cache in the temporary folder) still reads, with an empty `source` and no `fetched_at`.
  - `DifficultyTable::by_level() -> Vec<(String, Vec<usize>)>` — entries grouped by level (values are indices into `entries`), in `level_order`, levels the table has no entry in dropped, unknown levels appended first-seen.
  - `DifficultyTable::parse_body(bytes, header) -> Result<_, TableError>` — parse a JSON-array body with optional header.
  - `DifficultyTable::match_levels(library_md5s: impl Iterator<Item = &str>) -> Vec<(String, Vec<usize>)>` — join the table against the local
    library and group the **library** indices by level. It takes md5s rather than `SongEntry`s precisely so `rbms-table` does not depend on
    `rbms-library` (the app calls `table.match_levels(library.md5s())`); matching is case-insensitive and each library index appears once per level.
    A level none of whose charts are owned is kept with an empty list: the levels are the table's, so a table nothing is owned of is still its folders.
  - `Md5Index::new(library_md5s) -> Md5Index` and `DifficultyTable::match_levels_in(&Md5Index) -> Vec<(String, Vec<usize>)>` — the same join against an index of the library built once. The player loads every table against one index (`tablesrc::read_and_match_all`, `apply_finished_fetches`) instead of hashing the library's md5s again per table; `match_levels` is `match_levels_in` over an index it builds for the one call.
  - `DifficultyTable::named_symbol() -> Option<&str>` (2026-10-23) — the symbol the header names, or `None` for no header, no symbol in it, an empty one or the `"*"` stand-in (`ABSENT_SYMBOL`); the player titles each level folder `symbol + level` with it (`st3`, `★12`), as the reference does (`TableDataAccessor.java:185`), and `LV n` when it is `None`.
  - `DifficultyTable::missing_levels_in(&Md5Index) -> Vec<Vec<usize>>` (2026-10-23) — for each level `match_levels_in` hands back, in the same order and the same number, the indices into `entries` of the charts whose md5 the library does not hold, in the table's order and each md5 once. An entry that names a chart by `sha256` alone is in neither this nor `match_levels_in`.
  - `TableEntry` — one chart. Every field is read leniently (`md5`, `sha256`, `level`, `title`, `artist`, `url`, `url_diff`; a number is the text of that number). `names_a_chart()` is false for an item with neither hash, which is skipped and counted rather than failing the body. Entries with only a `sha256` parse but are not matched (the library is matched by md5).
  - `TableHeader` — `name`, `symbol`, `data_url: Vec<String>` (one address or a list), `level_order` (numbers and text mixed are accepted).
  - `TableError` (thiserror) — `BodyParse`, `HeaderParse`, `MissingDataUrl`, `NoTableMeta`, `HttpStatus`, `TooLarge { limit }`, `TimedOut { limit }`, `Read`, `Request`, and `At { stage, url, source }`, which is what a failed step is reported as: `header https://…/header.json: HTTP 404 Not Found`. `TableStage` is `Address`, `Header` or `Body`. The `Display` text is what the player shows and what the tests pin.
- **Key invariants & algorithms**:
  - **Level ordering** — `level_key(s)` returns `(u8, i64, String)`: numeric levels parse via `i64::parse` → tag `0`, sort ascending by value; everything else → tag `1`, sort by full string. So numerics come first ("9" < "10", negatives before positives) and non-numerics ("???", "beginner") sort last by string. Overflow beyond i64, leading space, underscores, `0x` hex, `5_000`, and empty string all fall into the non-numeric bucket; `+5`, `05`, `-0` parse as numeric.
  - **Derivation** — `derive_level_order` sorts then dedups *by `level_key`*, so numerically-equal textual forms ("5"/"05") collapse to **one** entry, keeping the **first-seen** textual form (stable sort).
  - **Defaults** — missing `symbol` → `"*"`; an *explicit empty string* symbol is preserved. Missing `name` → `""`. `level_order` that is `None` **or** an explicit empty `Vec` triggers derivation; a non-empty explicit `level_order` is used **verbatim, not re-sorted**.
  - **Text encoding** — JSON is read as UTF-8 with an optional byte order mark. Bytes that are not UTF-8 are read as Shift_JIS when they are well-formed Shift_JIS (the old Japanese tables: the name and symbol stay what the table calls itself, and a character whose second byte is a backslash does not escape the quote after it), and lossily otherwise.
  - **Meta tag** (`html.rs`) — a scan for `<meta …>` tags, not an HTML parser: attribute order, quoting, case and a self-closing slash vary, `&amp;` is the one character reference undone, and a commented-out tag is not a tag.
  - **URL joining** — `join_url` uses reqwest's re-exported `url::Url` (RFC 3986). Unparseable base → returns raw `rel`.
  - **Limits** — every request goes through one blocking client per load (`user_agent("rbms-table")`). `SILENCE_TIMEOUT` (15 s) is how long the server may go without answering: connecting, the start of the answer, and each further piece of it. `LOAD_TIMEOUT` (30 s) is how long all the requests of one table may take together; it is checked before each request and before each piece read (`read_within`), so a server that keeps sending a little at a time ends as `TimedOut` rather than never. An answer larger than `MAX_RESPONSE_BYTES` (64 MiB) is refused as `TooLarge`.
  - **The copy** (`saved.rs`) — a JSON object: `name`, `symbol`, `level_order`, `entries`, `course` (when the header listed any), `skipped`, `source`, `fetched_at`. It holds the resolved table, so a run that reads it is the table without the network. Reading is lenient about the fields a copy written earlier does not have and strict about everything else: a body that does not parse is no copy. An empty `level_order` is derived again from the entries.
- **Gotchas / edge cases**:
  - `TableEntry` derives `Serialize` + `Deserialize`; `TableHeader` derives **only `Deserialize`**. `DifficultyTable` has **no `Debug` impl** — tests `match` on the Result instead of `unwrap_err()`.
  - Body must be a JSON **array**; an object, malformed JSON or empty input → `body parse: …`. Unknown fields are ignored.
  - A level the header lists but the table has no entry in is not a folder (`by_level` drops it); a level nothing is owned in is an empty one (`match_levels` keeps it).
  - A table that was read and lists nothing has no levels, so the player shows no folder for it and says so (`NO CHARTS LISTED` in the table manager).
- **Tests**: `lib.rs` (`level_key`, `derive_level_order`, `by_level`, `from_parts`/`parse_body`, lenient fields, Shift_JIS JSON, `match_levels` and `match_levels_in` agreeing), `saved.rs` (a copy reads back as the whole table with where and when it came from, a copy without the address and the time is still the table, a damaged copy and a missing file are no copy, a file past the limit is not read), `fetch/tests.rs` (the whole chain against a site that lives in the test: page → header → body, redirects, relative addresses, split bodies, byte order marks, every failure's wording, an answer that trickles in without end, an answer that is too large), `html.rs` (the meta tag in the shapes sites write it). No test leaves the process: the requests go through a function the tests replace.

### rbms-store
- **Role**: Persistence for the player's local play history and replays. Owns the SQLite `scoredb` history/best/profile store, legacy `scores.ron` and `replays/*.ron` compatibility, the durable-write helper every RON file goes through, and the judging-rule generation stamped on each record.
- **Public API**:
  - `write_atomic(path, contents) -> std::io::Result<()>` — temp file (named by the process id and a per-process sequence number, so neither two instances nor two threads of one share it) + rename, so a crash mid-write cannot truncate a good file. Every persisted file in the app (config, keyconfig, scores, replays) goes through it. `StagedWrite` splits it: `create` makes the temp file (where a missing folder or a refused permission shows), `finish` writes, flushes and renames, possibly on another thread; dropped unfinished it removes the temp file. `write_atomic_private` / `StagedWrite::create_private` are the same for a file that holds a credential: on Unix the temp file is created `0600` (and set to it, so a leftover temp file of the same name cannot lend its mode), which the rename carries to the target; the settings file and its backups are written this way. `restrict_to_owner(path)` closes a regular file an older build left open to `0600` (a folder or a link is left as it is; nothing on Windows, where the profile folder's access list is inherited).
  - `SCORE_RULE_VERSION: u32` (4) — the generation of the judging rules a record was produced under: 2 is the judge-parity pass, 3 changes SCRATCH AUTO alone (`SCRATCH_AUTO_LEAVES_THE_TURNTABLE_RULE_VERSION`), 4 records a run as the reference does (`REFERENCE_RECORD_RULE_VERSION`: `avgjudge`, `minbp` with unreached notes, stage combo, full combo, TOTAL assist). `scoredb::charged_minbp(log)` is a row's `minbp` as compared (an older row charged the notes it never reached); `merge_best` folds `avgjudge` from generation 4 on only, and `ScoreDb::migrate` refolds both bests from the history on every open. `ReplayJudge::total_override` (`REPLAY_CHART_TOTAL` = none) is the TOTAL a replay was played on. `sets_best(assist, rule_version)` says whether a record may set a chart's bests (`SCRATCH_AUTO_ASSIST` = 1). `SCORE_LN_MODE_FROM_CHART` is the long-note key of a record whose chart states its own flavour. `is_stale_rule_version(v)` answers whether a record predates generation 2; how that is *shown* ("`  *`", "`   OLD RULE`") belongs to the app's `format.rs`, so no layout string lives in a persistence crate.
  - `ScoreRecord` — one finished run: `md5`/`title`/`mode`, `clear` (lamp id), `ex_score`/`max_ex`, `counts[6]`, `empty_poor`, `max_combo`, `total_notes`, `gauge`/`gauge_value`, `random`, `played_at`, `replay_file`, `rule_version`, `ln_mode`, `assisted`, `assist` (the scorelog's assist level, `ASSIST_UNRECORDED` = -1 when never recorded). `ScoreRecord::assist_grade()` / `lamp()`, `PlayLog::assist_grade()` / `lamp()`, `BestScore.assist_grade` and `ScoreBook::best_lamp_for_md5` (and `_in_ln_mode`) answer the lamp with its grade. Every field added since the format existed is `#[serde(default)]`, so an old `scores.ron` still parses.
  - `ScoreBook` — RON compatibility history: `load(path)` (a malformed file is renamed to `.ron.bak` and the book starts empty rather than failing the launch), `try_save` / `save`, `from_records`, `push`, `rebuild_index`, `records()` (read-only slice), `for_md5` (newest first), `best_ex_for_md5`, `best_clear_for_md5`, and `best_record_with_replay_in_ln_mode(md5, ln_mode)`: the record of a chart under one LN mode that holds its best EX and kept a replay, which is the oldest run that scored that EX and has a replay (the reference keeps the run that first reached a best, since a run replaces it only with a higher EX: `ScoreData.java:550-564`; a run of that EX with no replay kept -- AUTO REPLAY off, a failed save, a replay since pruned -- gives way to the next one), `None` when no run of the best EX has one. Assisted runs never count. The player judges that run's replay again as the run a BEST figure or a LOCAL BEST target is held against.
  - `scoredb::ScoreDb` — SQLite storage with schema migration, play history/bests/profile/day statistics, score-book import, backup and replay-GC planning. The player opens `scoredb.sqlite` and imports `scores.ron` when needed. `open_read_only(path)` opens a second connection that only reads (WAL), which the records sync's worker picks from while the frame thread writes.
  - **What a run is sent with, and what the server answered** (`scoredb/sync.rs`, `scoredb/courses.rs`; schema generation stays 1, the tables come by `CREATE TABLE IF NOT EXISTS` and the later columns by `ADDED_COLUMNS`): `record_play_kept(log, updates_best, Option<KeptSubmission { body, played_as }>)` writes the history row, the best and the submission body (`play_submission`) in one transaction, and `keep_trace(log_id, body)` the play trace (`play_trace`) in a write of its own after it (the player calls it on the save thread), so a trace that cannot be written costs the play nothing; `put_submission` adds a body later. `ir_sync` holds one `IrSyncRow` per run and server: `SyncState` (`Accepted`, `Rejected`, `Retry`, `Skipped`), the `score_id`, the HTTP status, error code, field and reason, `refused_under` (the client and server builds a refusal was given under), attempts, and the replay's `ReplayState` (`None`, `Pending`, `Uploaded`, `Failed`, `Rejected`, `Skipped`, `Missing`) written by `put_replay_state`, and the trace's (`TraceState`, the same states, with `trace_id`, `trace_error`, `trace_refused_under`) written by `put_trace_state(log_id, server, TraceAnswer)`; `trace_candidates(walk)` picks the accepted runs with a `play_trace` row whose trace is still to go up or was never asked for (`none`: the server took the run before its trace was written; narrowed by `only` too), `trace_body(log_id)` reads one, and every `SyncCandidate` says `has_trace`. A play stored before its client kept traces gets one later (`scoredb/backfill.rs`): `untraced_plays(after, up_to, limit)` reads the plays with a replay file, no `play_trace` row and no `trace_backfill_refused` row, oldest first, each as an `UntracedPlay { log, body }`; `keep_backfilled_traces(&BackfillBatch { traces, refused, from, through })` writes in one transaction the traces made for them with `INSERT OR IGNORE` (a play that has a trace by then keeps it), the plays that will never get one into `trace_backfill_refused`, and the `meta` key `trace_backfill_through` = `through` only when the mark still stands at `from`, so a batch after one that was not written moves it no further (`BackfillWritten { kept, marked }`); `trace_backfill_through()` reads that mark (`TRACE_BACKFILL_NOT_STARTED` before any); `kept_courses()` and `plays_ended_by(second, limit)` are what the player tells a kept course's stages by. `SyncWalk { server, login_id, only, up_to, courses_up_to }` is one sync's question: `sync_candidates` (oldest first, runs the server failed to answer behind the rest; another account's runs and generation-2 SCRATCH AUTO runs left out), `replay_candidates`, `newest_play_id`; `sync_states(server)` reads the states for the screen, `backfill_sha256` fills a migrated row's hash. Courses: `put_course` (`course_submission`), `course_candidates`, `newest_course_id`, `put_course_sync_state` / `course_sync_states` (`course_sync`, `CourseSyncRow`).
  - **A run kept on the side** (`scoredb/pending.rs`): `PendingRun { log, updates_best, body, played_as, trace }` with `to_ron` / `from_ron` is the file the player writes into `pending-runs/` (`PENDING_RUN_SUFFIX` = `.ron`) when the database cannot take a run; `import_pending_runs(dir) -> PendingImport` reads each in through `record_play_kept` and then `keep_trace`, removes its file, reads only the trace of a play the history already holds (a file the player kept for the trace of a stored run, or one read in before), leaves a file whose play or trace the database refused for the next import, and reports a file it could not read, read in or remove without holding back the files after it.
  - `Replay` / `ReplayEvent` + `Replay::load(path) -> Result<_, StoreError>`, `save` / `try_save`. `ReplayJudge` records the JUDGE settings a run was played under; its `offset_steps: Vec<ReplayOffsetStep { from_event, offset_ms }>` lists the judge offsets a run recorded in waves 10A to 12 moved through while its offset adjusted itself, when the offset still moved the instant an input was judged at. It is empty for a run judged at the one `offset_ms` throughout, which is every older file, and for every replay written since wave 13, whose `offset_ms` is 0 as well: the offset now moves where the notes are drawn and no judgement, so a new replay is judged the same whatever offset its watcher holds. `ReplayOffsetStep::in_force_at(steps, index)` answers the offset the recorded input at `index` was judged at, which is what plays an old file back as it was judged. `ReplayJudge.clock` is the replay's generation for how time moved its judgements: `REPLAY_EVENT_CLOCK` (`"EVENT"`) for a run recorded since judging stopped depending on frames, which reproduces exactly at any frame rate, and `REPLAY_LEGACY_CLOCK` (`"FRAME"`) for a file without the field, played back the same way but able to differ from its own score where the recording machine's frames decided something (`acknowledge/2026-10-15-adr-event-time-judging.md`). A replay rebuilt from a server download carries no generation and reads as `FRAME`.
  - **Lamp grade** (`score.rs`; `play-options.md` §10.13): `RecordLamp { clear, assist_grade }` (ordered by lamp id, then grade), `assist_grade_of(clear, gauge, assist, rule_version) -> u8` (a grade only for lamp id `LIGHT_ASSIST_CLEAR_ID` = 3 whose assist level was recorded and whose rule is not older than the judge-parity pass; the gauge id goes through `ASSIST_GRADE_OF_GAUGE`, `[0, 1, 2, 3, 4, 4, 2, 3, 4]` for gauge ids 0 to 8), `ASSIST_GRADE_NONE` … `ASSIST_GRADE_EXHARD` (0 to 4), `ASSIST_GRADE_COUNT`. The `score` table has an `assist_grade` column (`ADDED_COLUMNS`; schema generation 1 unchanged). `merge_best` raises a row when `best.lamp() < log.lamp()` and then takes the play's `clear`, `assist_grade`, `option`, `seed`, `gauge` and `assist`; `ScoreDb::best` orders by `clear DESC, assist_grade DESC, EX DESC, minbp ASC`; `chart_best_many` folds `MAX(clear * 5 + assist_grade)`. `ScoreDb::migrate` runs `refold_assist_grades` after `refold_reference_bests` on every open: each `score` row takes the best grade among the `scorelog` rows of its lamp (the earliest play on a tie; only rows of lamp 3 are scanned) and, when the grade is above none, that play's gauge and assist level; a row of any other lamp is put to none; a second open writes nothing. `ScoreDb::put_course_stages_on_class(&[stage ids]) -> usize` (`scoredb/courses.rs`) moves the given rows whose gauge id is below `GAUGE_CLASS` (6) onto it and refolds, because a build before 2026-10-22 stored a course stage on the settings' gauge while the stage ran on a course gauge; the player finds the ids with `trace_backfill::course_stages` when it opens the database.
  - `StoreError` (thiserror) — read / parse / write, replacing the old `Result<_, String>`.
- **Key invariants & algorithms**:
  - **Lamps and judgments travel as numeric ids, not engine enums.** That is what keeps `rbms-judge` out of the persistence layer; the app converts with `rbms_judge::clear_type_id`.
  - **`index: HashMap<md5, Vec<usize>>` is `#[serde(skip)]`** and rebuilt on load / maintained by `push`. Lookups were a linear scan over every record per query, which the select screen does once per visible row; they are now a hash lookup. The file format is unchanged — the index is derived state.
  - md5 keys are compared lowercased, so a record written with an uppercase hash still matches.
  - **A record that may not set bests is history and a lamp.** `assisted` is `!sets_best(assist, rule_version)`: a widened judge, and a SCRATCH AUTO run of a rule older than `SCRATCH_AUTO_LEAVES_THE_TURNTABLE_RULE_VERSION` (3), which counted the turntable as perfect greats. The best-EX and per-chart score queries skip such records; `best_clear_for_md5` keeps their lamps, which the player demotes before it writes them, and skips only an assisted record of a stale rule version. A SCRATCH AUTO run of rule 3 or later sets bests like any other.
- **Gotchas / edge cases**:
  - `load` is infallible by design (returns an empty book); `try_save` is the fallible form and `save` swallows the error for call sites that must not abort a run.
  - Records are append-only in file order, but `for_md5` returns them newest first (`played_at` descending). The result screen's "previous best" is computed *before* the new record is pushed.
- **Tests**: `src/tests.rs` (53 tests after e2c829f) covers record/book round-trips, index rebuild and push maintenance, the md5 case rules, best-EX / best-clear selection incl. the assist exclusion, the best record that kept a replay (`the_best_with_a_replay_is_the_oldest_run_of_the_best_score`), replay round-trip, and `write_atomic` (fresh file, overwrite, no partial file left behind, two threads of one process never sharing a temp file, the private mode). `tests/legacy_scores.rs` (4) loads `tests/fixtures/scores-legacy.ron` — a `scores.ron` written before the crate existed — and asserts the queries return exactly what they returned in the app. The `scoredb` modules carry their own tests (68 at ea698a9: `sync_tests.rs` for candidates, states and a refusal under the same builds, `tests.rs` for the rest, the pending import among them).

### rbms-library
- **Role**: The local song library: walking the configured folders, the per-chart summary the select screen browses, and the heavier per-chart detail computed for the focused row only. Headless — no app state, no rendering — so the same code backs the player's background scan and `rbms-cli scan`.
- **Public API**:
  - `SongEntry` — one chart as read from its header block alone: `path`, title/subtitle/artist/genre/maker, `level`, `difficulty`, `init_bpm`, `rank`, `total`, `mode`, `md5`, `stagefile`, `banner`, `preview` (`#PREVIEW`). An empty `#TITLE` falls back to the file name.
  - `ChartDetail` — the expensive per-chart summary (full timing integration): `notes`, `long_notes`, `duration_us`, `bpm_min`/`bpm_max`, and the density series (`density`, `peak_density`, `avg_density`, `end_density`).
  - `is_chart(path) -> bool` — extension test (`.bms`/`.bme`/`.bml`/`.pms`).
  - `scan_folder(root, &AtomicUsize, &AtomicBool) -> Vec<SongEntry>` / `scan_folders(&[String], …)` — recursive walk, results sorted by lowercased title; the counter feeds the loading bar and the flag cancels mid-walk. `scan_folders` is the union of every configured folder.
  - `compute_chart_detail(path, Mode) -> Option<ChartDetail>` — parse + `to_model` for one chart.
  - `Library` — the scanned set plus an md5 index: `from_songs`, `songs`, `len`, `is_empty`, `indices_for_md5`, `md5s`.
  - `scan::ScanRequest` (2026-10-23) — what a scan of the song database (`scan_into`) is asked: `roots`, `full`, a cancel flag, progress counters and `stamps_parser_version`. `ScanRequest::new(roots, full)` is a scan of every folder the library is read from and records the parser version when it completes. `ScanRequest::partial(roots)` is a scan of some of them (the folder a download was unpacked into): what changed under those roots is read and what is gone from them is dropped (`delete_missing` works under the roots only), and the parser version is left alone, so a full rescan another folder still needs is not recorded as done. `scan::DOWNLOAD_WORK_FOLDER` (`".rbms-partial"`) is the one folder name `enumerate` does not push onto its walk, so a scan during an unpack never reads a half-unpacked chart.
- **Key invariants & algorithms**:
  - **Scanning is cancellable.** Both scan functions take `&AtomicBool`, checked once per directory popped off the walk stack, and return what they have so far. This is what lets the loading screen abort a rescan of a large library instead of holding the window hostage.
  - **The cheap path never integrates timing.** `SongEntry` comes from the header block, so a folder of thousands of charts scans without building a `Model`; `compute_chart_detail` is called for the focused row only.
  - `Library::md5s()` yields md5s in library order, which is exactly the contract `DifficultyTable::match_levels` consumes — the indices it returns index back into `songs()`.
  - Duplicate md5s (the same chart in two folders) are kept: `indices_for_md5` returns every match.
- **Gotchas / edge cases**:
  - Unreadable files and unparseable charts are skipped silently — a broken chart in a folder must not stop the scan.
  - The progress counter counts *charts read*, so it stays still while the walk crosses a folder of audio files — an indeterminate bar is the honest presentation until a total is known.
- **Tests**: `src/tests.rs` (9) covers `is_chart` extensions, scanning a temporary tree (nested folders, non-chart files, cancellation mid-walk, the progress counter), `compute_chart_detail` on a synthetic chart, and the `Library` index (order, duplicate md5s, unknown md5 → empty slice).

  - **The settings screen is a table, not an index space.** Each row is a `SettingDescriptor` with its tab, label, kind, help text and a `visible: fn(&Config) -> bool` predicate; the screen calls `tab_rows` → `display_value` and reacts to `AdjustOutcome::Action(id)` for the rows that open a dialog (key config, font, skin). The old positional `SETTING_KEYCONFIG = 11` style constants and the `SETTING_TABS` index arrays are gone, so inserting a row can no longer silently misalign the screen.

An unknown *higher* version returns `ConfigError::Migrate` and the app starts on defaults **without saving**, so a newer machine's settings survive being opened by an older build.

- **Gotchas / edge cases**:
  - Load outcomes differ by failure mode: a **missing** file writes the defaults out (so the first run leaves a file to edit), a **migrated** file is copied to `*.ron.v{from}.bak` and handed back for the caller to rewrite, an **unparseable** file is moved to `*.ron.bak` and the defaults are used *without* being written, a file that **cannot be read** at all (permissions, a directory) is reported as `ConfigError::Read` and left alone, and a **newer-schema** file is left completely untouched behind `ConfigError::Migrate`.
  - The same version ceiling guards the account sync blob: `apps/rbms-player/src/ir_sync.rs` refuses a blob whose `schema_version` is past this build's rather than reading it as the current schema, which would strip every field a newer build added and then upload the stripped copy back over the account's settings.
  - `migrate` always `sanitise`s, so no caller has to re-check the ranges of a value that arrived from a file, a hand edit or a synced account.
  - `AudioOptions` carries a `reopen_pending` flag rather than reopening the stream itself — the app debounces and owns the device. The flag is `#[serde(skip)]` **and** excluded from `PartialEq` (hand-written), so comparing two `Config`s compares the documents they would be written as rather than a transient UI state that `sanitise` clears.

  - **A row whose number lives outside the document.** PAD DEBOUNCE (`SettingId::PadDebounce`, INPUT tab, 0~100 ms, step 1, `PAD_DEBOUNCE_*`, `DEFAULT_PAD_DEBOUNCE_MS` 16) is a `host_row`: the value is the key config file's `pad.debounce_ms`, which `rbms-config` never reads. `number_spec` gives it its range, `number_steps` reads `None`, `adjust` answers `Action`, and `display_value` says only what ships. `rbms-cli config` prints `(in keyconfig.ron)` for it rather than that number, since it reads the settings document alone. The player reads and writes it (`settings_ui.rs`: `setting_line`, `setting_number`, `set_row_number` → `AppShared::set_pad_debounce`, which writes `keyconfig.ron` at once; the screen stores a drag of its slider only when the drag ends, `applies_when_released`). `gamepad::DEFAULT_DEBOUNCE_MS` and `DEBOUNCE_MS_RANGE` are these constants.
- **Tests**: `src/tests.rs` (35) and `src/tests/{audio,library,persistence}.rs` (40 at ea698a9; `persistence.rs` checks the `0600` writes and the closing of an older build's open files) cover the schema defaults and `sanitise` clamps, the serde adapters for the gauge / note option, the descriptor table (every id present exactly once, no empty tab, `adjust` never leaves a declared range under ±1000 repetitions, `display_value` never empty, label snapshots equal the old screen's strings), and the audio helpers. `tests/migration.rs` (15) drives the fixture files in `tests/fixtures/`: `settings-v0-default` → `Config::default()`, `settings-v0-full` (all 24 legacy fields non-default) field by field, `settings-v0-partial`, `settings-v0-unknown-key`, `folders-v0` + `tables-v0` merged into `Config.library`, `settings-v99` (error, file untouched), and a `save` → `load` round-trip.

  - `property`: the 968 property ids and names (`generated/`, produced by `tools/gen-skin-property.rs` at the repository root), `SkinHost` (`boolean`, `integer`, `float`, `text`, `image_index`, `offset`, `timer_us`, `exec_event`, writers, audio, key state, …) and `MapHost` (a map-backed host for tests and the dump tool). `timer`: the timer ids (0..2999 built in, 10000.. custom); times are microseconds and OFF is `i64::MIN`. `dst`: destination keyframes, `TimerRef`, acc/loop, offset arithmetic. `resolve`: skin-root-only paths (`plain_path`), wildcard and random file selection (`Draw`, `RBMS_SKIN_SEED`), `MOVIE_NAME_ENDINGS`.
  - Errors are `SkinError` (thiserror): read, parse, too large, number out of range, path escape, type missing or unsupported, Lua expression/budget/load errors.
- **Key invariants**:
  - A Lua skin is two runs of the entry file in one interpreter: the header pass reads headers only (`main_state` is an empty table in the separate header-only interpreter used for listings); the body pass builds objects against the real game state. A module `require`d in the first pass is cached for the second.
  - The sandbox is layered: confined paths, no bytecode, no `os`/`io` escapes, no network, `__gc` never runs, and a budget (`skin.md` §4.3) that `pcall` cannot swallow once exhausted.
  - A function value that fails is reported once per function with a running count, answers its default (false/0/""), and is called again next frame.
  - Fail-soft per object: one unreadable image or bad expression drops that object with a warning; only the `SkinError` variants above abandon the skin, so the caller can fall back to a built-in screen.
- **Tests**: unit tests per module; `tests/` drives the loader, the Lua environment (`skin_lua_env`, `skin_lua_io`, `skin_luajava`, `skin_main_state`, `skin_lua_pattern`, `skin_from_lua`, `skin_luaskin`), fixtures under `tests/fixtures/` (a mini `.luaskin` pack among them), and `tests/default_pack.rs`, which holds the repository's default pack to the forbidden-API scan and checks each sprite sheet against its atlas.

### rbms-video
- **Role**: Decoding the movie files a skin draws from into RGBA frames, and nothing that draws. No dependency on other workspace crates.
- **Public API**:
  - `open(path) -> Result<Box<dyn VideoDecoder>, VideoError>`. `VideoDecoder`: `info() -> VideoInfo` (size, frame count, duration), `next_time_us`, `next_frame(Option<&mut Vec<u8>>)` (decode and optionally convert), `rewind`, `seek(time_us)`, `lost_samples`.
  - `VideoPlayer` (`spawn`, `with_queue`, `frame`, `advance(time_us)`, `advance_blocking`, `restart`, `failure`, `has_ended`): runs a decoder on a thread of its own and keeps `DEFAULT_QUEUE_FRAMES` (3) frames ahead, so the drawing side asks only for the frame due now.
  - `color` (YUV → RGBA), `bitstream` (MP4 samples → the stream the decoder reads), `container` (a box-by-box validator that runs before anything trusts a file).
  - `VideoError`: `Disabled`, `Io`, `Malformed`, `Unsupported`, `Decode`.
- **Key invariants**:
  - The one decoder reads H.264 out of MP4 and is compiled in by the `openh264` feature (default on): OpenH264 built from source and linked statically (`openh264` crate, BSD-2-Clause) plus `re_mp4` (MIT) for the sample tables. Without the feature `open` answers `Disabled` for every file and the surface is unchanged, so skins draw a movie's place empty.
  - `re_mp4`'s own `Mp4::read` can loop or panic on damaged files and is not used on untrusted bytes: `container` checks the boxes, keeps the H.264 track and rebuilds the file first.
  - Playback time is the caller's clock; a clock that stops stops the movie, and one that goes back seeks to the previous keyframe.
  - Supported streams: 8-bit 4:2:0 progressive H.264 (High profile, CABAC, B frames); not interlaced. Other containers or codecs are `Unsupported`.
- **Tests**: unit tests per module; in `rbms-player`, `assets/scripted_movie.rs` stands in for a real movie in the tests of everything that plays one.

### rbms-play
- **Role**: Pure logic crate that drives BMS playback over a song clock: it advances notes against the chart, emits keysound `PlayEvent`s, and feeds judgments into `rbms-judge` (including an autoplay mode used for chart verification). It owns no audio/render/IO — callers supply the `now_us` clock and a sink closure, and read back per-lane render state (beams, bombs).

- **Public API**:
  - `struct PlayEvent { wav: i32, at_us: i64 }` — a keysound (BGM or a hit note's wav) that should fire at `at_us`.
  - `struct Player` — the real-time play driver. The judge state is reached through `judge()` / `into_judge()`; it is no longer a public field.
  - `Player::new(model: Model, autoplay: bool)` — build a player; precomputes time-sorted BGM, note-head, and autoplay-action lists.
  - `Player::update(now_us, play: FnMut(PlayEvent))` — advance to `now_us`: flush due BGM/autoplay keysounds, feed autoplay/auto-lane judgments (through `JudgeEngine::auto_press` / `auto_release` at each action's own time, not through `press` / `release`, so the run never holds a key down), age out tap beams, then call `judge.update(now_us)` (the MISS/LN-finalisation sweep).
  - `Player::press(lane, now_us, play) -> Option<JudgeResult>` / `release(lane, now_us) -> Option<JudgeResult>` — interactive input; updates beam/bomb and emits the nearest head's keysound on press. The engine settles its clock up to `now_us` before it judges.
  - `Player::failed()` / `failed_at_us()` — read off the engine, which the player hands its GAUGE AUTO SHIFT, chosen gauge and floor to (`JudgeEngine::set_gauge_shift`) whenever one of them changes; the shift is no longer taken once per `update_judge`.
  - `Player::set_judge_rate(rate_percent)` — user JUDGE WIDTH multiplier; rescales both note and LN-end windows.
  - `Player::with_auto_lanes(model, autoplay, &[bool])` — a player that leaves the marked lanes to the chart (SCRATCH AUTO): their notes are taken off the chart it judges (after the lane layout is applied), kept only to be drawn (`PlaySession::field_timelines`) and heard (each head's keysound on the key bus at its own time), their mines are dropped, and input on them is ignored. `Player::new` is `with_auto_lanes(model, autoplay, &[])`.
  - `Player::set_gauge(GaugeKind)`, `judge() -> &JudgeEngine`, `into_judge() -> JudgeEngine`, `model() -> &Model`, `last_time_us() -> i64`.
  - `Player::update_schedule(sched_us, play)` / `update_judge(audible_us)` — the two clock axes Phase B split apart: keysounds are booked ahead on
    the scheduling axis, judging sweeps on the audible one. `update(now_us, play)` runs both against a single clock for callers that do not care.
  - `Player::beam_on() -> &[i64]`, `beam_off() -> &[i64]`, `bomb() -> &[(i64, u8)]` — per-lane render state for the skin.
  - `fn simulate_autoplay(model: &Model) -> JudgeEngine` — full autoplay pass; verification helper (should yield all-PGREAT, LNs once).
  - `struct PlaySession` — **one run of a chart**, the layer above `Player`: it owns the judge state, the replay being reproduced or recorded, the
    judge offset as inputs move it, the analysis clock, the timing-mark ring and the BGA timeline. `new(model, SessionOptions)`,
    `tick(SessionClock, &mut dyn SoundSink)`, `press(lane, raw_us, sink) -> Option<JudgeResult>`, `release(lane, raw_us)`, `seek(target_us)`,
    `is_finished(song_us)`, `all_notes_resolved()`, `summary() -> PlaySummary`, `judge()`, `model()`, `bga_frame()`, plus the analysis controls
    (`set_analysis_enabled`, `toggle_analysis_pause`, `adjust_analysis_rate`, `advance_analysis`, `sync_analysis_position`) and the judge
    offset (`set_judge_offset_us`, `judge_offset_ms`, `set_auto_calibration`, `adjusted_inputs`), and `set_playback_rate(percent)` for a practice slice played at another FREQUENCY (kept in the setup, so a `seek` rebuilds against it). A run played by hand makes room for its recording when it starts, four inputs per judged note (`RECORDED_INPUTS_PER_NOTE`), so the recording is not grown in the middle of play. `is_failed()` is the engine's: from the instant the gauge emptied under NONE the session takes no input and settles no time. The session carries the offset only to move it
    (AUTO ADJUST) and judges every input at the instant it arrived; where the notes are drawn for it is the player's business.
    **Nothing a run is judged by depends on the frames**: every input settles the run up to its own instant first (`settle_until`), and an input that arrives before what was already settled is judged and recorded at the settled instant (`input_instant`), so the recording reproduces it. The gauge history and the built-in result screen's gauge series are sampled at their own half-second and one-second instants on the song clock, and a failure closes the history at the instant the gauge emptied. A replay input is fed when its judged instant (the recorded time plus the offset an old replay states) is reached. `seek` rebuilds the run by playing the recording again silently up to the target, gauge history and tallies included. `crates/rbms-play/tests/replay_reproduction.rs` plays the same inputs at 1 ms, 120 Hz, 60 Hz, 30 Hz and uneven frames and reproduces each recording on each of them.
    The result screen's distributions, the FAST/SLOW split and the AUTO ADJUST step count each *judgment* of the player's own inputs once: a result that is not `counted` is skipped, and a plain long note held through its end, or one whose early release the margin confirmed, is tallied when the clock settles it (`tick`). A run that plays itself tallies nothing.
  - `PlaySession::play_out()` — plays the rest of the run out in one step and silently: every replay input still to come is judged at its own instant, then the clock is settled past the last note and the tail (`last_time_us() + PLAY_TAIL_US`, 2 s) by one `tick` into a `NullSink`. Since nothing a run is judged by depends on where frames fall, a replay played out this way judges every note as it did when it was recorded (`crates/rbms-play/tests/replay_reproduction.rs`, `playing_a_replay_out_in_one_step_judges_it_as_playing_it_frame_by_frame`: the summary, `total_judged` and `vanished` equal a 1 ms and a 60 Hz step), which is how the player judges a stored run again with no screen and no sound (`apps/rbms-player/src/ghost.rs`).
  - `fn auto_adjust_step_ms(Judge, delta_us) -> i32` — how far one judged input moves a judge offset that adjusts itself
    (`JudgeManager.java:697-703`): nothing for worse than GOOD or more than 150 ms out, else a thirtieth of the error, so nothing inside 15 ms.
    The step is taken off the offset, sign and all as in the reference (`judgetiming - (mfast +- 15000) / 30000`): the offset is how far ahead
    of the song the notes are drawn, so a player who presses early has it lowered. A session applies it after each input of a run played by
    hand, inside `AUTO_ADJUST_OFFSET_MIN_MS..=MAX_MS` (±200). A replay recorded while the offset still moved the judgement (waves 10A to 12)
    is reproduced at the offset each recorded input was judged at (`ReplayJudge.offset_steps`); a run recorded since records none.
  - `trait SoundSink { fn play(&mut self, SoundRequest); fn stop_all(&mut self); }` + `SoundRequest` (`wav`, bus, gain, pan, pitch, `SoundTime`) and
    `NullSink` — how a session emits sound without depending on `rbms-audio`. The app implements it over its `AudioEngine`; tests use `NullSink`,
    which is what makes a whole run reproducible headlessly.
  - `SessionOptions` — `autoplay`, `gauge`, `judge_offset_us`, `judge_rate_percent`, `auto_lanes`, `seed`, `analysis`, `auto_calibration`, `replay`, and what a course stage inherits: `initial_gauge` / `initial_combo` and (2026-10-23) `carried_gauges: Option<[f32; GaugeIndex::COUNT]>`, every one of the nine gauges' values the stage before ended on (`GrooveGauge.java:150-155`; `None` for a single chart and for a course's first stage). `PlaySession::gauge_values()` reads those nine values at the end of a stage, exact rather than the last gauge-history sample, and `Player::carry_gauges` starts each slot there (a gauge that ran out stays out); a `seek` rebuilds with them.
  - `SessionClock` — the pair of clock axes a tick is given (`SessionClock::at(song_us)` collapses them for callers with one clock).
  - `PlaySummary` — everything the result screen and an IR submission need as plain values: `counts[6]`, `ex_score`, `max_ex_score`, `max_combo`,
    `total_notes`, `total_judged`, `fast`/`slow`, `early[6]`/`late[6]`, `avg_judge_us`, `empty_poor`, `gauge_value`, `clear_lamp`, `min_bp`, `failed`, `finished_gauge`, `gauge_shifted`. `max_combo` is the chart's own (a course stage carries no streak in); `min_bp_with_unreached()` is the recorded BP (`BMSPlayer.java:909`), charging the notes a run the gauge ended never reached; `left_unfinished()` is the summary of a run left with Esc before its end: every note not reached is a late POOR let pass, the lamp FAILED, the rest as reached (the reference adds the unreached notes to the BP alone; here the counts take them too, so the judgements add up to the chart's notes). `PlaySession::standing_combo`/`standing_max_combo` are the course's streak, `course_lamp(notes_before, counts_before)` the course's lamp.
    Computing it is pure: writing the record, saving the replay and submitting to the IR stay in the app.
  - `TimingMark` — one judged input's timing error, newest last, for the analysis overlay (`recent_marks(count)`).
  - `PlayRecord` (`record.rs`) — what a skin's result screen asks beyond the summary, each to the reference's definition: the gauge log and bounds of all nine gauges, `finished_gauge`, `failed_at_ms`, `play_time_ms`, the timing distribution, per-second judgements, and `avg_duration_us` / `total_duration_us` (`ScoreData.avgjudge` / `totalDuration`: every note's distance from its input, a note missed or never reached counting `UNJUDGED_DURATION_US`, one second), which is the `avgjudge` a record of rule generation 4 stores and sends; not the engine's signed `avg_judge_us`.
  - A run left before its end (2026-10-23): `PlaySession::left_record() -> PlayRecord` is the record the result screen is handed for a run the player left with notes still to come: `summary` is `PlaySummary::left_unfinished()` (every note not reached a late POOR, the run FAILED) and the gauge history falls to zero from where it stopped to the end a failed run is padded to (`GaugeLogRecorder::closed_left`, `BMSPlayer.java:722-727`; a run an empty gauge already ended is closed as `closed()` closes it). `failed_at_ms` stays `None`, since no gauge ended it. `record()` is still the run as it stood, which is what the history row and the submission are made from.

- **Key invariants & algorithms**:
  - `AUTO_BEAM_US = 80_000` (80 ms): in autoplay/auto-lane, a tapped (non-LN) note lights its lane beam for 80 ms then auto-releases, mirroring the reference implementation's `auto_minduration`. LN-held beams stay lit (gated by `ln_active[lane]`) until the LN release.
  - Window selection (`JudgeEngine::from_model_for_mode` in `Player::with_auto_lanes`): all four tables (note, scratch, LN end, LN scratch end) come from the chart's mode at its `#RANK` / `#DEFEXRANK` judgerank. `set_judge_rate` recomputes the effective judgerank as `base * rate.max(1) / 100` (min 1) and applies it to BOTH note windows and the separate LN-end windows (`ln_end_for_mode`). Recently changed: the LN-end window now follows `#RANK` instead of a fixed 100% constant.
  - Autoplay actions (`collect_actions`) are built per-lane: a `Press` for every Normal and LN head, a `Release` for every LN end; an LN head with no matching `LongEnd` is dropped (no press, no sound, no judge). All event lists are sorted by time so keysounds emit in non-decreasing time order.
  - Bombs fire only for judge index ≤ 3 (PG/GR/GD/BD) — never empty POOR (index 4), MISS, or `update()`'s sweep, which never touches the bomb array. `bomb[lane] = (hit_us, judge_index)`.
  - `press` emits `nearest_head_wav`: the lane-scoped note head (Normal or LN start) minimising `|t - now_us|`; lanes with no head emit nothing. Beam-on writes are bounds-guarded so out-of-range lanes (e.g. `press(99, …)`) just no-op/return None.
  - `simulate_autoplay`/`Player` clone the `Model`; `update` is idempotent past full judgment (the sweep won't re-judge).

- **Gotchas / edge cases**:
  - `with_auto_lanes` takes nothing unless the mask length exactly matches `model.mode.key` and a marked lane holds a note; a wrong-length mask leaves every lane interactive (pinned by tests). `PlaySession::has_auto_played_notes` says whether anything was taken, which is what makes a run an assist.
  - Input on an auto lane is fully ignored: `press`/`release` return `None` and do not light that lane's beam.
  - Autoplay (`Player::new(.., true)`) is not a hand on the keys: it never raises `held[lane]` in the engine, so a mine behind an autoplayed note costs nothing and a hell-charge note keeps paying out gauge only because the engine is told it plays itself (`set_autoplay`). A scratch-lane CN/HCN under autoplay is two PGREATs, not a PGREAT and a POOR.
  - `release()` only stamps `beam_off` if `beam_on` was lit; an unpaired release leaves `beam_off` at `i64::MIN`. An empty press (far from any note) still lights the beam but no bomb.
  - The MS candidate-gate is fixed and does NOT widen with JUDGE WIDTH: the far-early empty-POOR edge (`ms.1 = +500ms`) stays put, so a press 600 ms early returns `None` even at 200%. Conversely widening reaches BAD/PGREAT edges that are otherwise unreachable.
  - A plain LN that is held and never released is finalised by `update()` as soon as the clock passes its end, with the head's judgement (the reference's `lnstartJudge`; `held_ln_never_released_finalises_via_update_sweep`). A CN/HCN whose end goes by unheld is swept as a POOR at its end's BAD-late bound.
  - This crate has NO `main.rs`/binary, audio clock, theme thread-local, or library/search/sort — those live elsewhere; here the clock and audio are entirely the caller's responsibility.

- **Tests**: A large `#[cfg(test)] mod tests` at the bottom of `crates/rbms-play/src/lib.rs`, `crates/rbms-play/tests/note_count.rs` (the decoder's note count equals the judge engine's and autoplay is all PGREAT on charts with overlapping or unpaired long notes, on generated charts too), and `crates/rbms-play/tests/scratch_auto.rs` (the same figures as a chart without the turntable, the turntable keys, keysounds, replay and seek, DP, 9 keys) (helpers `model()` via `to_model(parse(bms), Mode::BEAT_7K)`, `autoplay_collect`). Coverage: autoplay perfect-score/EX=2n/full-combo/no-miss invariants over dense charts, mines excluded, LN counted once, dangling-LongStart safety; keysound count/time-ordering; `auto_lanes` length guard and input-drop behaviour; interactive beam/bomb transitions; `nearest_head_wav` lane-scoping and LN-head lookup; `set_judge_rate` widening/clamping (rate 0 → min, fixed-MS-window non-widening); `update()` sweep MISS/LN finalisation, idempotency, monotonic autoplay combo; and rank-scaled LN-end windows. Runnable example: `examples/autoplay_score.rs` (`simulate_autoplay` on a real chart file).

### rbms-course
- **Role**: Pure course domain crate. It reads reference-compatible course documents, retains only valid and non-conflicting constraints, derives stable course hashes, and advances a `CourseRun` without depending on the player, judge, renderer, or network crates.
- **Public API**:
  - `load_dir(path)` / `load_file(path)` / `parse(text)` / `save(dir, course)` — loads, parses and writes JSON course files; invalid entries are normalised or omitted by `Course::validate()`.
  - `Course`, `CourseChart`, `CourseConstraint`, `TrophyRule` — course metadata, ordered chart identity, the 14 recognised constraints, and trophy criteria. `Course::validate()` normalises a document before it becomes playable; `Course::hash()` identifies a course by its name and ordered chart hashes.
  - `CourseRun`, `StageResult`, `CourseTotals`, `CourseStep` — one continuous run. `advance()` folds a finished stage, preserves the resulting gauge and combo carry, and returns `Next`, `Cleared`, or `Failed`. `CourseRun.carry_gauges: Option<[f32; GAUGE_SLOTS]>` (2026-10-23, `GAUGE_SLOTS` = 9, the reference's nine gauge slots) is every gauge slot's value the stage just played ended on, which the next stage starts each of its gauges on; the integration layer sets it after `advance()` (the crate knows no judge types and the player holds `GAUGE_SLOTS` equal to its own slot count at compile time), and `carry_gauge` stays the one value the course opened with or the last stage ended on.
  - `bundled` (module; 2026-10-23) — `genoside_2018() -> &'static BundledCourses`, the GENOSIDE 2018 grade courses the build carries, parsed once from `web/data/courses/genoside-2018/courses.json` (`include_str!`; every course has been through `Course::validate`). `BundledCourses { schema, source: BundledSource, groups }`, `BundledGroup { id, name, keys, courses }` (`genoside-2018-sp`, 22 courses of 7 keys, then `genoside-2018-dp`, 22 of 14, each in the order first grade to last), `BundledCourse { course_hash, course }` (the id the file states beside each course, which a test holds equal to `Course::hash()`), `BundledCourses::courses()`. `BundledSource` names where every part of the file came from (the maker's course archive with its size and SHA-256, the two difficulty-table headers the constraints and trophies were taken from, the title source), so a course can be traced and taken out of a build. The file is written by `rbms-cli course-snapshot` and read by the website.
  - `table` (module; 2026-10-23) — `courses_from_table_header(&serde_json::Value) -> TableCourses { courses, skipped }` reads a difficulty table header's `course` field (`TableDataAccessor.java:192-213`): a list of groups of courses (flattened in order), a flat list or one course object; a course names its charts by a `charts` list or by `md5` (and optionally `sha256`) lists, hashes are lower-cased, `release` is true, and an entry that is not a course or fails `Course::validate` is left out and counted. `same_charts(a, b)` is whether two courses play the same charts in the same order by md5 whatever they are called; `bundled_twin(&Course) -> Option<&'static Course>` is the bundled course that does. The course id (`Course::hash`) includes the name and, per chart, the sha256 when there is one, else the md5, so a table's `GENOSIDE 2018 初段` would be ranked apart from `GENOSIDE 2018 段位認定 初段`; the player and the website take the bundled one.
- **Invariants**: only the first constraint in each of the five exclusive groups survives; an invalid chart identity or empty course is rejected; failed stages still contribute to the final totals but stop subsequent loading; trophies are selected from the highest qualifying rule. The app translates its play result into `StageResult` and owns UI/IR persistence.
- **Tests**: unit tests cover loading, normalisation, stable hashing, constraint precedence, carry-over, failure termination, totals and trophy boundaries. `bundled/tests.rs` holds the data file to its stated ids (44 courses, no duplicate id, an id equal to the computed one, every chart with an md5 and the constraints and trophies the source gives), `table/tests.rs` the three header shapes, the lower-casing, the skipped entries and `bundled_twin`.

### rbms-download
- **Role**: Getting a chart archive a difficulty table links to and unpacking it without trusting it (2026-10-23, the Stella and missing-chart work). No dependency on another workspace crate: `reqwest` (blocking), `encoding_rs`, `thiserror` and `zip` (`9.0.0`, `default-features = false` with `deflate-flate2-zlib-rs`, so the only new crates are `zip` and `typed-path`; the user approved `zip` for unpacking, 2026-10-23 decision 15). The player's `download.rs` drives it on a worker thread; `rbms-cli mirror-pack` takes its unpacking limits.
- **Public API**:
  - `classify_link(&str) -> LinkKind` (`DirectZip`, `Browser`, `Unusable`) — judged from the address alone. A web address (http or https with a host) is a `DirectZip` when it is on `stellabms.xyz` under `/upload/` or its path (the query left out) ends in `.zip` in any case; every other web address (a page, a cloud folder, `.rar` / `.7z`, a lone chart file, `page.html?file=a.zip`) is `Browser`; anything else is `Unusable`. `browsable_url(&str) -> Option<String>` is the address that may be handed to the system's browser: http or https with a host, no white space or control character, at most `MAX_BROWSABLE_URL_CHARS` (2048), normalised, so it always begins with `http`.
  - `download_to(url, file, &DownloadLimits, &Progress, &AtomicBool)` / `download_with(.., get)` — fetch a zip into `file` (the second takes the request as a function, which is how the tests run without a network). Limits: `DOWNLOAD_MAX_BYTES` 512 MiB (an announced `Content-Length` over it is refused before reading, and the bytes that arrive are counted too), `DOWNLOAD_SILENCE` 30 s without an answer, `DOWNLOAD_TOTAL` 15 min altogether (looked at between 64 KiB pieces, where the cancel flag is looked at too), at most 10 redirects, a redirect off http and https is refused, user agent `rbms-download`. An answer that does not begin `PK\x03\x04` (or `PK\x05\x06`) is `NotAZip`, a web page standing in for a file among them. The body goes to the file, not to memory, and a failed download leaves no file. `Progress` (`received`, `expected`, `phase` as atomics) is what a screen reads while a worker runs; `phase` is `Progress::IDLE`, `DOWNLOADING` or `EXTRACTING`.
  - `extract_zip(archive, into, &ExtractLimits, &AtomicBool) -> Result<ExtractReport { written, skipped, charts }, DownloadError>` — unpack into a folder that does not exist yet or is empty. Limits: `EXTRACT_MAX_ENTRIES` 10,000, `EXTRACT_MAX_ENTRY_BYTES` 1 GiB, `EXTRACT_MAX_TOTAL_BYTES` 2 GiB, counted from the bytes that come out and not the sizes the archive states, and the archive's list of entries is itself read within a budget (`IndexTooLarge`). An entry name is read as UTF-8 when the archive flags it or it is valid UTF-8, else as Shift_JIS, else lossily; a name is refused (the entry skipped and counted) when any piece of it, split at `/` and `\`, is empty, `.` or `..`, holds a control character or one of ``<>:"/\|?*``, ends in a space or a dot, or is a Windows device name (`CON`, `PRN`, `AUX`, `NUL`, `COM1`-`COM9`, `LPT1`-`LPT9`, extension ignored); links are skipped; a name that is already taken (also a file where a folder should be) is skipped and never overwritten. Only what a chart pack is made of is written (`is_kept_extension`): charts `bms bme bml pms bmson`, sounds `wav ogg mp3 flac`, pictures `bmp png jpg jpeg gif`, movies `mpg mpeg avi mp4 wmv m4v webm mkv` and `txt`. An archive with no chart in it fails as `NoChart`, and every failure removes `into`.
  - `safe_folder_name(title, md5) -> String` — the title with `<>:"/\|?*` and control characters replaced by `_`, white space and dots trimmed from its ends, cut to 64 characters (and 200 bytes), then ` [first 8 characters of the md5]`; a title that leaves nothing, or names a Windows device, gives the md5 part alone. `settle(staging, parent, name) -> Result<PathBuf, DownloadError>` moves `staging` to a new folder `parent/name`, or `name (2)`, `name (3)` ... when that is taken, and never overwrites anything.
  - `DownloadError` (thiserror): `NotWebAddress`, `HttpStatus`, `TooLarge`, `TimedOut`, `Read`, `Request`, `NotAZip`, `Cancelled`, `Io`, `Archive`, `IndexTooLarge`, `TooManyEntries`, `EntryTooLarge`, `UnpackedTooLarge`, `NoChart`, `StagingNotEmpty`, `UnsafeName`, `NameTaken`; the `Display` text is what the player shows after "download failed".
- **Tests**: `tests/{link,fetch,extract,name}.rs` — the link classes against the Stella upload form and the other shapes, a download past its cap or announcing too much, going silent (the time left is injected), an HTML answer, a cancelled one and a redirect off the web, and for unpacking `../`, absolute and drive paths, Shift_JIS names, links, other kinds of file, an archive that unpacks past its caps (made in the test with `zip::ZipWriter`), too many entries, device names, an archive with no chart, a taken name (also on Windows, where a refused create reports a folder in the way as access denied), and folder names. No test reaches the network.

- **Key invariants & algorithms**:
  - **`App` is `{ shared: AppShared, stage: Stage, suspended: Vec<Suspended>, launch_chart: bool, startup_error: Option<String>, window: Option<AppWindow> }`** (a `Suspended` is a parked `Stage` with the skin scene it was in). Splitting the state that outlives a screen change (`AppShared`) from the state a screen owns (`Stage`) is what makes `self.stage.update(&mut FrameCtx { shared: &mut self.shared, .. })` pass the borrow checker — and it is why a screen can be a plain `match` arm instead of a field of one large struct.
  - **Screens are a trait, dispatch is a `match`.** Each state struct implements `StageHandler` (`update` / `draw` / `handle_key` / `handle_mouse` / `handle_mouse_drag` / `handle_scroll` / `handle_ime` / `handle_pad` / `on_enter` / `on_exit` / `debug_lines` / `holds_keys`); `Stage` dispatches by matching its own variants, so a new screen cannot be forgotten in one of the paths. `Select`, `SkinMenu`, `PlayMenu`, `Decide`, `Play`, `CourseResult` and `Practice` are boxed — a session with its decoded BGA, and the browser with its cached scene, would otherwise set the size of every variant and make each change a large memcpy; a test pins the size of `Stage` (`STAGE_SIZE_LIMIT`).
  - **One transition rule, one place.** A screen returns `Transition::{Stay, Open, To, Back, Quit}`; `App::apply` runs the leaving screen's `on_exit`, swaps, and runs the arriving screen's `on_enter`. `Open` suspends the current screen onto `suspended` and `Back` resumes it, which is how the settings screens return to the browser exactly as it was. Assignments of the form `self.stage = Stage::X` scattered through the app (22 of them) no longer exist — `grep -rn '\.stage = Stage::' apps/rbms-player/src/` is 0.
  - **The frame loop is a dispatch.** `frame()` measures fps/RAM, polls the network, IR jobs and the audio reopen debounce, calls `stage.update`, applies the transition, then draws `stage.draw` plus the two app-wide overlays (connection dot, debug panel) and presents. It runs when the presenter thread (`gpu/present.rs`) wakes the event loop with `FrameReady`: the image the frame is drawn into has come. The loop runs with `ControlFlow::Wait` and never waits for the display itself, so a key is taken in, and judged, at the instant it comes in (`docs/acknowledge/2026-10-15-adr-keyboard-input-timing.md`). `window_event` translates the winit keyboard, mouse-button, cursor-move (drag), wheel, focus and redraw events into `handle_key` / `handle_mouse` / `frame` and does nothing else — the per-stage key matrix lives in the stages.
  - **Logical space**: a skin screen is drawn at the physical viewport left after the letterbox decision (`display.letterbox`, always for BORDERLESS), so its pixels are the window's. The built-in screens and the system overlays stay laid out in 1280×720 (`CW`/`CH`) and are scaled onto it; cursor coordinates are mapped back. The surface format is a non-sRGB one so bytes pass through unchanged. Text on those screens is not enlarged with them any more: `Canvas::device_scale` reports the enlargement and `Canvas::fill_rect_device` takes rectangles on the target's own pixels, so the text engine rasterises glyphs at the size they cover (rbms-render, Text is rasterised on the target's own pixels). Default `MODE = BEAT_7K`.

- **Gotchas / edge cases**:
  - A corrupt config or key-config file is moved aside to `*.ron.bak` before defaults are used, so a later save cannot clobber a recoverable file. The rules for which failure writes a file are `rbms-config`'s, not the app's.
  - `lane_keys()` guarantees every lane `0..mode.key` is bound: empty, missing or bad tokens backfill from the default. Control keys resolve **before** lanes in play, so a shared key shadows the lane; the key-config editor flags collisions and refuses a colliding rebind.
  - Replay launch forces `autoplay = false` for the whole session (the recorded stream drives judging). An md5 mismatch between replay and chart only warns. Autoplay, replay and practice runs do not persist a `ScoreRecord`, do not auto-save a replay, and are not submitted. Every other run does, assisted or not (the replay when AUTO REPLAY is on; the submission when signed in): `docs/play-options.md` §10.
  - Click hit-testing walks `hot` topmost-first (last drawn wins); a click that misses everything dismisses an open modal. `hot` is rebuilt every frame.
  - Result deltas (`prev_ex`, `prev_best_ex`) are read from history *before* this run's record is pushed.
  - `#![forbid(unsafe_code)]` holds even though `gpu/` derives `bytemuck::Pod`/`Zeroable` — the derive's generated `unsafe impl` does not trip the lint, so the app needs no `deny` escape hatch.

### apps/rbms-cli
- **Role**: Headless companion to the player; it never depends on the player, so no window or audio stack enters a CLI build. Depends on `rbms-model`, `rbms-parser`, `rbms-chart`, `rbms-config`, `rbms-library`, `rbms-store`, `rbms-skin`, `rbms-table` (the last for `chart-pattern --table`; it brings `reqwest` into the CLI build, though the CLI never calls it), and since 2026-10-23 `rbms-course` and `rbms-download` (`course-snapshot` and `mirror-pack`), `zip`, `encoding_rs`, `md-5` and `sha2`.
- **Commands**: `rbms-cli <chart>` (metadata, hashes, counts); `scan <dir>` (`rbms-library`); `config <settings.ron>` (migration result, the copy it kept, every settings row); `scores <scores.ron> [--md5 <md5>]` (`rbms-store`); `skin-dump <skin pack folder|document> [--scenario <json>] [--overlay <folder>] [--frames <N>] [--seed <n>] [--json] [--probe-budget] [--strict] [--allow-failure <document>]...`; `chart-pattern <library folder> --out <folder> [--table <data.json>] [--mode beat-7k]`; `course-snapshot --zip <2018_course.zip> --normal-header <file> --insane-header <file> --titles <md5-title.json> --retrieved-on <YYYY-MM-DD> --out <courses.json> [--check]`; `mirror-pack <library folder> --out <folder> (--table <data.json>)... [--all] [--dry-run]`.
- **skin-dump** (`src/skin_dump/`): loads every `.luaskin` / `.json` / `.json5` in a pack against a scenario (`scenarios/*.json`: a `MapHost` per screen type), reports header, object and function-value counts, files, diagnostics (warnings, errors swallowed by the skin's own `pcall`, function failures, printed lines) and, with `--frames`, the cost of calling every function value once per frame; `--strict` (`gate.rs`) turns the findings into an exit code; the pack folder is listed before and after to prove the skin never wrote into it. Output reading guide: `skin.md` §5.1.
- **chart-pattern** (`src/chart_pattern/`): walks a library folder (path order, symbolic links not followed, every `rbms_library::is_chart` file), reads each chart once through `rbms_parser::parse` (`bmson::parse` for a bmson) → `detect_mode` → `to_model`, opening no keysound and no picture, and writes the charts of `--mode` (BEAT_7K unless named; `beat-5k`, `beat-10k`, `beat-14k`, `popn-9k`, `keyboard-24k`) as `<out>/<md5>.json`. Files are read by a pool of up to 8 workers, 64 charts at a time, and stored in path order; two files with one md5 are one chart and the first in path order is the one written. A file that cannot be read (an unreadable folder, a bmson that is not valid) is listed with its reason and left out; the run still exits 0, and exits 1 only when it could not be done (library not a folder, table unreadable, a file not writable). Progress (`read N/M charts`) goes to stderr, the report to stdout.
  - **Document** (`document.rs`, one compact line, keys in this order): `format` `"rbms-chart-pattern"`, `version` 1, `parser_version` (`rbms_library::songdb::PARSER_VERSION`), `md5`, `sha256` (of the file's bytes, the values the player and the library scan store), `mode`, `declared_ln` (`"ln"`/`"cn"`/`"hcn"` from the chart's long notes, `null` when it has none or states no flavour: the first long note carrying a stated flavour decides, so a chart that sets `#LNMODE` but has no long note reads `null`), `has_undefined_ln` (`rbms_chart::contains_undefined_long_note`), `uses_control_flow` (`rbms_library::scan::uses_control_flow` on the file's bytes, made public for this; always false for a bmson; the parser resolves `#RANDOM`/`#SWITCH` with seed 0), `init_bpm`, `total` (as the header or the bmson states it, `0` when a BMS chart has no `#TOTAL`), `rank`, `play_level` (the header read as a whole number, `null` otherwise), `playable_notes` (`count_playable_notes` on the unresolved model, so an undefined long note's end is not counted), `notes` (parallel arrays `time_us`, `lane`, `kind`, `section`; sorted by time and then lane; `lane` is the model lane, 0 to 6 the keys and 7 the scratch in BEAT_7K; `kind` 0 note, 1 long-note head, 2 long-note end, 3 mine; hidden notes and background sounds are not read), `tempo` (`{ t_us, bpm, stop_us, scroll }` at each timeline whose BPM or scroll speed differs from the one before it, and at every stop; empty for a chart that changes none, whose tempo is then `init_bpm` and scroll speed 1).
  - **Rerun**: a pattern is stored through a temporary file and a rename, and only when the file is missing or its bytes differ, so a second run over the same library writes nothing (`written 0, unchanged N`). Files of an earlier run that no chart stands behind any more are left in place.
  - **Table coverage** (`coverage.rs`): `--table` reads a table body (`data.json`) with `rbms_table::DifficultyTable::parse_body`, lowercases and de-duplicates its md5s, and prints and stores `<out>/_coverage.json` (pretty JSON: `format` `"rbms-chart-pattern-coverage"`, `version`, `mode`, `parser_version`, `table_md5s`, `table_entries_without_md5` (entries with a sha256 only, which an md5 match cannot reach), `matched`, `missing` (md5s no chart read in this run has, sorted), `other_mode` (md5s whose charts are all of another mode, sorted), `failed_files`). `missing` may hide the md5 of a file that could not be read, which `failed_files` counts.
  - **Output stays out of the repository**: the layouts are the charts' authors' work. The tests write hand-made charts to a temporary folder (process id and a counter in its name, removed by a drop guard) and set modification times explicitly to prove that an unchanged file is not touched, so none of them waits on a clock.
