# 기본 스킨 구현 순서 누락

## 지적

사용자는 제공 파일이나 사진에서 필요한 기능이 보이면 `docs/`에 정확한 할 일·사양·상세를 먼저 기록하고, 추가 기능을 구현한 뒤 기본 스킨을 만들어야 한다고 지시했다. 이전 결과는 배경 이미지 중심 문서를 먼저 배포했고, 개별 객체에 필요한 기능은 후속 과제로 남겼다. 사용자는 이 순서를 지켰는지 다시 물었다.

## 원인과 수정

기존 화면 합성 기능으로 보이는 일부 화면을 곧바로 구현 범위로 정하고, 곡 목록·플레이 노트/판정/게이지·옵션 행 등에서 문서 모델만 존재하고 실제 렌더 객체가 없는 상태를 완전한 파일 커스터마이징과 구별하지 못했다. 이번 보정에서는 화면 결함을 먼저 기록한 `docs/plan/2026-09-17-skin-visual-correction.md`를 작성하고, 남은 개별 객체의 상태·입력·완료 조건을 `docs/plan/2026-09-17-skin-object-spec.md`에 기능 구현 전에 기록했다. `docs/PROCESS.md`의 V7·V8은 기능과 기본 파일 작업이 실제로 끝날 때만 체크한다.

## 적용 시점

스킨 화면이나 객체를 새로 구현할 때마다 코드 변경 전에 현재 모델의 지원 여부와 실제 렌더/상태 연결을 확인하고, 미지원 객체의 기능 사양과 실패 기준을 문서에 기록한다.

보편 규칙 승격 후보: 아님. 이번 교정은 이 프로젝트의 화면 스킨 작업 순서에 관한 구체적 요구다.
