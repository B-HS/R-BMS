# "다른 사이트 흔적을 지워라" 를 기능을 가진 주소까지 넓히지 않는다

최종 갱신 2026-10-15 · 대응 커밋 ea698a9

## 무엇을 지적받았나

2026-10-15. 발광 표 페이지에서 사용자가 출처·삭제 요청 문구를 지우라 했고("제발 다른사이트의 흔적좀 지워놔"), 곡 데이터의 외부 주소도 지우는 안(B)을 골랐다. 메인은 4fda17c 에서 곡마다 `url`·`url_diff`·`name_diff`(곡을 내려받는 주소)까지 모두 비우고 곡 상세의 "받는 곳" 링크도 지웠다. 사용자 원문: "어라 잠시만 외부주소 말한게 곡 다운로드 받는 그곳말한거야 ? 그건 지우면안되는데".

## 왜 틀렸나

"외부 주소" 를 주소의 모양으로만 보고 필드의 기능을 보지 않았다. 사용자가 지우라 한 것은 출처를 알리는 표기(문구, 원본 표 운영자의 메모 `comment`, `original_url`, artist 에 섞인 주소)이고, 곡을 받는 링크는 이 표를 쓰는 목적이다. 삭제는 사용자에게 보이는 데이터 변경인데 지울 필드의 목록을 보여 주고 확인받지 않았다.

## 어떻게 고쳤나

dd5518e: 다운로드 링크(`url`·`url_diff`·`name_diff`, 곡 상세의 "받는 곳")를 되돌리고 `comment`(792건)·artist 주소(9건)·`original_url`·화면의 출처 표기만 지운 채로 둔다. 스냅샷 정규화(`web/scripts/snapshot-table.ts`)가 이 규칙을 적용하고 `--check` 가 통과한다. 결정 기록은 [표 페이지 ADR](../acknowledge/2026-10-14-adr-table-page-no-source-notice.md) 의 정정 절이다.

## 언제 적용하나

사용자가 "흔적·문구·표기를 지워라" 처럼 이름으로 범위를 말한 삭제를 데이터까지 넓힐 때. 지울 필드를 이름과 건수로 나열해 보여 주고, 사용자가 쓰는 기능(링크, 다운로드)을 가진 필드는 지우는 쪽에 넣지 않은 채 묻는다.
