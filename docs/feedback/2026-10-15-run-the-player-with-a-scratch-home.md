# 플레이어를 실행할 때는 실제 HOME 을 쓰지 않는다

최종 갱신 2026-10-15 · 대응 커밋 ea698a9

## 무엇이 잘못됐나

2026-10-15 12:15~12:17. S19 감사 에이전트가 개발 빌드의 `rbms-player` 를 실제 `HOME` 으로 `--help` 를 주고 실행했다. 당시 빌드는 `--help` 를 앱 시작 전에 처리하지 않아 앱이 일반 실행처럼 시작했고, 로그인된 사용자의 설정과 기록 DB 를 열었다. 그 결과 기록 동기화가 판 49개를 운영 서버에 보냈다(모두 accepted, 리플레이 6개 업로드, 43개 대기). 같은 실행이 `settings.ron` 을 다시 썼고 곡 DB 를 다시 훑었으며 `scoredb` 의 `ir_sync` 와 `user-folders` 를 갱신했다. 사용자 결정(원문 "A 나중에 테스트할떄 참조가능할수도있으니 뭐"): 올라간 기록은 그대로 둔다([결정 기록](../acknowledge/2026-10-15-adr-accidental-sync-records-kept.md)).

## 왜 틀렸나

- 에이전트 지시에 "실제 HOME·실제 서버로 실행하지 말 것"이 없었다. 앱은 켜지는 것만으로 파일과 네트워크를 쓴다.
- 실행 파일에 부작용 없는 `--help`·`--version` 이 없어 "도움말만 보는" 실행도 앱 시작이었다.

## 어떻게 고쳤나

- 앱: `--help`·`-h`·`--version` 과 거절된 명령줄을 설정·DB·네트워크를 만지기 전에 끝낸다(`apps/rbms-player/src/command_line.rs`, 1676c57).
- 에이전트 지시: `rbms-player` 는 반드시 `HOME=$(mktemp -d)` 와 `--server http://127.0.0.1:9` 로 실행하고, 사용자의 실제 HOME 을 쓰지 않는다. 릴리스 산출물 점검은 `--version` 만 쓴다([ci-release.md 2.2절](../ci-release.md)).
- 사용자 확인 하나가 남았다: 설정 파일이 다시 쓰였으므로 v0.1.4 를 처음 실행할 때 설정이 의도한 값인지 본다([실제 창 QA](../quality-assurance/2026-10-11-default-skin-manual-check.md) 3.19절 R3).

## 언제 적용하나

플레이어·`rbms-cli` 처럼 사용자 설정 폴더(`$HOME/.config/rbms/`)나 기록 DB 를 여는 실행 파일을 에이전트가 돌릴 때 항상. 다운로드한 릴리스 산출물, 개발 빌드, 테스트용 실행 모두 해당한다.
