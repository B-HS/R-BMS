# 푸시 뒤 CI 결과를 확인하지 않음 (2026-10-11)

최종 갱신 2026-10-15 · 대응 커밋 ea698a9

## 무엇이 잘못됐나

Lua 스킨 호환 작업(웨이브 1B~7B, 2026-10-09~11)에서 웨이브마다 로컬 게이트(fmt, clippy, `cargo test --workspace`, `git diff --check`)를 통과시키고 커밋·푸시했지만, GitHub Actions 의 결과는 한 번도 확인하지 않았다. 그 사이 ubuntu·macos·windows 의 test 작업이 웨이브 1B 푸시(run 37954732199)부터 전부 실패하고 있었다. fmt + clippy 작업만 통과했다. 사용자 지적이 아니라 웨이브 7B 푸시 뒤 메인이 `gh run list` 를 처음 실행해 발견했다.

## 왜 틀렸나

- 사양의 게이트를 "로컬 명령 4종"으로만 정의했고 CI 를 게이트에 넣지 않았다. 프로젝트 README 는 CI 가 세 OS 에서 테스트한다고 적고 있다.
- 로컬 기기(macOS arm64, 대용량 메모리)에서는 드러나지 않는 실패였다.
  - 조작된 폰트 값이 정한 64 GiB 할당: macOS 는 큰 영(0) 할당을 지연 매핑해 통과시키고, CI 의 macOS 는 SIGKILL, Linux 는 할당 실패로 abort.
  - Windows 의 쓰기 오버레이 경로 처리.
  - 느린 러너에서 60초를 넘기는 테스트들(작업 전체 57분).
- `cargo test` 는 실패한 테스트 바이너리에서 멈추므로 뒤의 실패가 가려졌다.

## 어떻게 고치나

- 푸시 직후 `gh run list --branch dev --limit 5` 로 직전 실행 결과를 확인한다. 실패하면 `gh run view <id> --log-failed` 로 원인을 찾아 다음 웨이브 전에 고친다.
- 웨이브 완료 보고에 CI 상태(통과·실패·진행 중)를 로컬 게이트와 별개로 적는다.
- CI 의 테스트 단계에 `--no-fail-fast` 를 써서 한 번에 실패 전부가 보이게 한다.
- 입력 값이 할당 크기를 정하는 코드에는 상한을 두고, 그 상한을 단언하는 테스트를 둔다. 로컬 통과를 근거로 삼지 않는다.

## 언제 적용하나

원격에 CI 가 있는 저장소에 푸시할 때마다. 특히 플랫폼에 따라 달라지는 코드(파일 경로, 메모리 할당, 스레드·시계, GPU·오디오 장치)를 건드린 푸시.
